本檔是模型記者兩份規則檔（`daily.md`／`pages.md`）的歷史敘事，不是待執行規則。考古鏈：`[加入: 日期]` → 本檔 → `wiki/log.md` 同日 Query 條目。

（2026-09-13 由 `wiki-ingest-models.md` 條文旁的敘事搬入；條文一字未改。）

**2026-07-26**（model-comparison 選型品質審核六條）：深度 review 判定該頁決策層為全頁品質最低處——三個模型的「最適合」全部命中 agentic 而無分界、「不適合」16 格中僅 2 格可據以決策、決策層零來源歸因。同批的 E 條實例：Opus 4.8 的「Fast Mode 省時場景」在 Opus 5 也支援 fast mode 後已不成立，卻讓讀者有理由留在已被取代的模型。

**2026-08-04**（G 條儲存格短語化）：讀者回報本頁不可讀——查證過程、官方原文比對、多來源歧異全被塞進儲存格，最寬一列 996 字元、單格 700+ 字元，網站上多欄表格直接爆版。

**2026-08-05**（H 條欄數紀律）：讀者回報快速選型表 7 欄在網站上每格被壓到不可讀，因此定案對照表 ≤ 5 欄、快速選型表 ≤ 4 欄。

**2026-08-29**（I 條實付成本）：Claude 4.7 起換用新 tokenizer，同一段文字約多產生 30% token（官方遷移指南給的範圍 1×–1.35×），於是牌價沒動、實付漲了，而快速選型表的 $/Mtok 欄看不出這件事。庫內早有記錄卻無機制說明：`official-community-gap` 的「成本感知模型路由」列寫著該需求「2026-06-27，Opus 4.7 tokenizer 改版成本大漲後爆發」。

**2026-09-26**（各現行模型頁共用 `## 跟它怎麼說話`）：使用者拿跨專案 REVIEW-PRINCIPLES 對照官方 prompt 指南時發現，官方的 prompting 建議是按模型分的（Claude Code 內建 claude-api skill 的 model-migration 指南，每個模型一節「Behavioral shifts (prompt-tunable)」），且相鄰兩代常給相反的藥——Opus 5 要刪「自我驗證」「用子代理驗證」的句子並限制子代理，Fable 5.1 反過來要保留驗證句、放手非同步派工；Opus 4.6 起 CRITICAL／MUST 會過度觸發；Sonnet 5 字面解讀、review harness 帶門檻會吞掉真 bug。wiki 模型頁當時只記規格、基準、定價與 API 破壞性變更，沒有任何一處回答「換到這個模型，我的 prompt 哪幾句要改」。使用者裁決：由模型記者在更新模型頁時用幾句話描述模型的 prompt 特性。落點設為每個現行模型頁一節，≤5 句、一句一旋鈕、官方出處帶查證日、相反傾向互指；記者無 web 工具，日報沒帶官方內容時留待查證行由主編於 `/wiki-lint` 5l 補查。
