# .claude/reporter-rules/community/ 沿革（教訓存檔）

本檔是社群記者三份規則檔（`daily.md`／`pages.md`／`weekly.md`）的歷史敘事，不是待執行規則。考古鏈：`[加入: 日期]` → 本檔 → `wiki/log.md` 同日 Query 條目。

（2026-09-13 由 `wiki-ingest-community.md`／`wiki-ingest-community-lint.md` 條文旁的敘事搬入；條文一字未改，只是換家。）

**2026-07-10**（dev.to 以內容判斷、不看讚數）：實測顯示最有價值的第一手實作文（如「對抗式 Claude 互審 loop」「local reverse proxy 看 CC 送什麼」）讚數常只有 2–3，反而 SEO 農場文有 5–6 讚。互動門檻對照表的數字因此不套用在 dev.to。

**2026-08-05～08-15**（主線 tag 改日更只標 tag、縫合改週更）：日更小縫實驗證明，每天只看一個節點的記者結構上只做得到「往段尾加一句」，兩週就把 `community-large-codebase-workflow` 這頁綜合敘事長回 log。2026-08-15 使用者裁決：每日只標 `**主線：**` tag，整線重寫改週更（每線 ≤30 行固定骨架）。

**2026-09-02**（tools 頁兩層併為單一決策表）：原「痛點洞察＋值得關注」兩層，痛點格塞 9 個工具名等於沒有推薦。改版依據見 `wiki/log.md` 2026-09-02 相關條目。

**2026-09-03**（唯一一則否定證據被合法擋在社群通道）：一則 Reddit 貼文拿 Managed Agents 當對照組（宣稱同模型同準度、成本低最多 75%），是四個月來唯一一則對該頁有決策價值的證據，卻落在日報「社群」分類、由社群記者手上——功能記者的規則檔從未要求任何人把「別人怎麼講我的功能」的訊號送過來。於是兩側同時立法：社群側「官方功能的負向對照要回流」、功能側「否定證據也要有路回來」。

**2026-09-07**（code-quality-decline 頁面健檢）：Token 消耗異常訊號群原文把十則（含四則無互動數）的訊號定調為「結構性未解問題」——自承無互動數的貼文推不出強結論，因此該表的證據硬度欄與「不得用自承無互動數的貼文推出強結論」一條同批立法。

**2026-09-23**（tools 與 skill-interest-watch 按問題切，撤回 09-03 再裁決）：09-03 讓開發實務 tab 只留總覽頁、tools 頁退出 tab，總覽每日機械抄錄整張「我卡在這裡」決策表。三波冷讀者實測都分不出兩頁差在哪（同一張表出現兩次），而副本最多落後一天，實測撞過 tools 已換首選、總覽仍印舊 owner。使用者裁決：按問題切、不按 tab 切——tools 只答「我卡住了該裝哪個」、直接進 index「💻 開發實務入口」與 tab（tab 放的是讀者要「怎麼做」的頁，與維護者分工無關）；skill-interest-watch 改名「社群工具規模榜」，只答「這一類現在誰大、誰在漲」，不再抄決策表，每類留一行「本庫判斷 →」連 tools 症狀列（`check_tools_page.check_spokes` 照舊對帳）。條文見 `.claude/reporter-rules/community/weekly.md`「skill-interest-watch：機器快照頁」；實作見 `wiki/log.md` 同日條目。
