# .claude/reporter-rules/devpractice/ 沿革（教訓存檔）

本檔是 devpractice 記者兩份規則檔（`daily.md`／`weekly.md`）的歷史敘事，不是待執行規則。考古鏈：`[加入: 日期]` → 本檔 → `wiki/log.md` 同日 Query 條目。

（2026-09-13 由 `wiki-ingest-devpractice.md`／`wiki-ingest-devpractice-lint.md` 條文旁的敘事搬入；條文一字未改。）

**2026-08-15**（每日不寫頁）：日更彙整的實驗顯示，每天只看一批新增的記者只做得到往段尾加一句，兩週就把彙整頁長回 log——因此 devpractice 的彙整全歸週更，每日只沉澱候選帳本。

**2026-09-02**（吃 diff 不吃 tag，使用者裁決）：靠其他記者標 tag 是跨記者耦合——主線 tag 規則自己就寫著「漏填等於該節點不存在」，等於把「什麼算 coding」的判斷分散給兩個不管這頁的人。diff 不會漏、不會忘、不依賴紀律，且撿的是記者已判定值得入庫的內容，天然過了一層品質濾網。

**2026-10-04**（手冊整頁交給開發實務，使用者裁決）：`topics/coding-workflow-guide` 原本功能記者寫主體、開發實務只寫「本週 coding 亮點」一節，192 筆候選只能在亮點節掛連結、動不了正文。同日問八位記者各自的讀者，開發實務的讀者問的是「這週有什麼讓我現有做法要改」，正是手冊在答的事；功能記者的讀者問的是「這週升不升版」。使用者裁決整頁移交。搬遷時逐條過缺點、能解的都解掉：(1) 無新指令旗標的官方使用指南只有手冊一個家，改由分類層直接標「開發實務」並產派工包，不靠功能記者轉知；(2) 每日只准把這一種條目寫進對應階段，候選仍等週更——08-15「每日不寫頁」防的是彙整節長成流水帳，不是正文；(3) 比對腳本排除手冊自己，免得今天寫的明天被自己再撿；(4) 週彙整原本只讀近七天候選，跳一週就漏，改用行數游標（`devpractice_diff.py pending`／`consume`）；(5) 亮點節從十條縮到三條、只放本週真的改了正文的地方，「社群面待補」從固定輪替改成候選多的那段優先；(6) 回報併入收報腳本；(7) `check_devpractice_state.py` 看守狀態檔有跟著 ingest commit 進 git（09-28 漏帶過一次）。`topics/anthropic-agent-stack` 同輪評估後不搬：該頁規則只收官方原句、不留判斷空間，搬了只多一段轉手。
