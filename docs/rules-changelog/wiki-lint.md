本檔是**歷史敘事，不是待執行規則**——條文已在上方，執行時不必讀本檔。存放於此的原因：條文本身已能獨立執行，敘事只在有人想問「為什麼有這條」時才需要。考古鏈為 `[加入: 日期]` → 本檔 → `wiki/log.md` 同日 Query 條目。

**2026-08-09**（渲染層驗收）：資料層檢查全綠、網站上 18 條 wikilink 死掉，因為壞的是 renderer 不是資料。

**2026-08-20 A**（5c 結案回掃）：`entities/pricing` 於 08-08 拿到 Opus 5 定價的官方逐字確認，但先前一次 lint 曾以 pricing 當時的保守措辭為準，把 `topics/model-comparison` 五處「官方確認」下修為「推算值」。上修時沒回掃，`model-comparison` 與 `overview`（當前局勢表）掛著「非官方逐字確認」12 天，直到使用者為了別的事要求補價格表才被發現——而 overview 那句是**現況型宣稱**，讀者看到的就是錯的。探針欄本來就是為了讓機器找得到這筆懸置而存在，回掃只是把同一組字串再用一次，不需要新機制。

**2026-08-20 B**（死鏈分三桶）：首次全量掃描 795 條，舊分類判出 58 條「死鏈」——實際只有 5 條是真的 404。其餘 15 條 401 全來自 Reuters／Barron's／WSJ（付費牆，內容還在），38 條逾時裡包含 `www.anthropic.com` 自己逾時 3 次。**若照舊規格派工，會把 53 個活著的來源標成失效**——正是雲端 egress 守衛當初要防的頁面污染，只是從另一扇門進來。

**2026-08-20 C**（死鏈改讀檔）：這步是純 HTTP、不需要 LLM，卻因為雲端 egress 封鎖被標成「只能本機執行」，於是自 2026-07 起一次都沒真正跑過（08-01 留待辦 → 08-08「非本月首次，跳過」→ 08-15 再跳過）。改由 GitHub Actions 執行正是 2026-07-10 分裂架構的原句：不需 LLM 的網路工作歸 Actions。順帶修掉「僅每月第一次 lint 執行」這個觸發器——它會被雲端那次用掉，之後整月都跳過。

**2026-08-28 A**（lint 回報格式缺「轉知處置」欄）：`.claude/rules/wiki-reporter-shared.md` 的回報契約要求記者每次都回報轉知處置，而 lint 派工訊息確實會附上轉知待接手清單（見步驟 2）——但 lint 專用回報格式原本沒有這一欄，記者的處置無處可寫、主編也無從核對，帳本結不了案。兩份規則對同一行為給出不同格式，本身就是 6a 該抓的矛盾型態。

**2026-08-28 B**（收報核對加行為層）：形狀檢查幾乎不可能觸發退回——近 6 週 lint 皆 6/6 一次過、月度蒸餾自述「退回 0 次」。**連續滿分與蒸餾無料是同一枚硬幣**：改進迴路的訊號源被自己的檢查強度餓死。歷史上記者品質退化（全覽表漏列、最後新聞更新填錯）全部是使用者事後撞見的，沒有一次是收報核對抓到的。抽 1 項的成本是一次 `git diff`，而它是這個迴路唯一的真實訊號來源。

**2026-08-28 C**（懸置語法 WARN 無人讀）：這些 WARN 專為「條件反轉未清理」而設計（腳本第 8 號檢查），但流程原本沒有任何步驟讀它——訊號產出了、消費端沒寫，偵測器形同虛設。

**2026-08-28 D**（6a／6d 不掃自己）：lint 專用回報格式曾與 `wiki-reporter-shared.md` 的回報契約長期分裂（前者缺「轉知處置」欄），正是 6a 該抓的矛盾型態——但 6a 原本不掃自己，所以抓不到。6d 亦然：`wiki-ingest.md` 沒有後綴，接不到 `wiki-ingest-*.md` 這個 glob；本檔則單純沒被列入，但本檔有 **35 條** `[加入:]` 條款——全庫最多——等於「規則最密集的檔案，它的規則從不被審查是否過期」。**檢查者把自己排除在檢查範圍外，是這類缺陷的共同形狀。**

**2026-08-28 E**（待裁示標擱置週數）：這些事項只寫進 `wiki/log.md`，而**使用者不讀該檔**——出口是 `/weekly` 步驟 0 的呈報。擱置週數是那份呈報的排序依據；沒有它，六週前提過的候選與本週新提的長得一模一樣，於是每週重抄、每週被忽略（實例：某建頁候選連續第 6 週被提出）。
