## 0. 使命句與一句話設計

> **外面出現了什麼，對用 Claude 的我有什麼衝擊、多大。**

**一句話設計：** 一張按「衝擊度」排序的對手雷達表回答「多大」，一段 3 行 callout 回答「這禮拜」，其餘一切都是那張表的證據層——**證據層可以厚，重點層必須是一張表**。

三條不變式（違反其一即回退為百科）：
1. **「多大」是排序問題**——只有全域可比的單一表答得了，28 個各自為政的子節答不了。
2. **衝擊度量「若屬實，讀者要不要改變什麼」，證據硬度另有一欄**——兩軸絕不合併（🔴-A1）。
3. **每個成長區都要有上限與退場**——沒有數字紀律的節，一定會長回 28 節。

## 2. 對手雷達表

### 欄位定義與判準句（可直接貼進記者規則）

| 欄 | 定義 | 判準句 |
|---|---|---|
| **對手** | 具名產品或廠商 | 一個對手一列，不分產品線；同廠商跨層（如 Meta Muse Code／Muse Glimmer）合為一列，兩者都寫在動態格 |
| **最新動態（日期）** | 一句話事實＋**所以呢** | 寫成「X 發生了 → 對用 Claude 的人 Y」；只寫事實不寫 Y 的列，退回時序 |
| **衝擊面** | 四選一 | 定價／能力／生態／政策 |
| **衝擊度** | 見下表 | **量「若屬實，讀者要不要改變什麼」，不量證據硬度** |
| **這個消息有多硬** | 來源數＋缺什麼 | 白話寫；**仍需懸置標記的事實照舊在懸置細節區放完整標記，短標記 ⟨Q-nn⟩ 放本格末** |

**衝擊度三級（規則檔逐字用這段；句中不得出現「數字」「查證」「來源」等證據詞）：**

> - 🔴 **會改變決策**：讀者可能因此換工具、改預算、或延後升版——競品在讀者**已經在用的那一層**出現可比的價格或能力落差。
> - 🟡 **要留意但先不動**：影響的是讀者的**上游**（他用的工具的供應商、他所在市場的價格帶），他本人現在不必做任何事。
> - ⚪ **知道就好**：不影響任何 Claude 使用者當下的選擇（新進入者、廠商自宣、尚無對比對象）。
>
> **判準是「屬實的話」。證據不足不降衝擊度，只降硬度欄**；兩欄同時偏低者本來就不該進表（見准入）。

**排序：** 衝擊度降序（🔴→🟡→⚪），同級以最新動態日期新者在上。**不按廠商字母、不按首次追蹤日。**

**准入：** 具名產品或廠商，且與 Claude 在**工具層或模型層**直接競爭。純分析文、新聞稿自宣、投資／人事／管制／股價敘事一律不進表（見第 7 節第 0 條）。

**退場：** ⚪ 且 90 天無新動態 → 移出表，降為表下「久未更新」一行；🔴🟡 不因時間退場，但 90 天無新動態須**降一級**。

**上限：** 12 列。滿了先汰除最舊的 ⚪；⚪ 汰盡仍滿 → 回報主編，不自行砍 🟡。

## 7. 維護者同步：`.claude/rules/wiki-ingest-commercial.md` 該節完整替換文字

> 以下整段**取代**現行 L105–109（`## competitor-landscape 更新規則` 至該節結束），可直接貼上。節名逐字即機械契約（見第 8 節）。

```markdown
## competitor-landscape 更新規則 `[加入: 2026-07-05，改版: 2026-09-05]`

本頁是**選型雷達**，回答「外面出現了什麼、對用 Claude 的我有什麼衝擊、多大」——不是競品百科。
改版依據：2026-09-05 頁面健檢（`docs/page-audits/competitor-landscape-2026-09-05*.md`）。

### 0. 本頁不收什麼（先看這條，再看觸發條件）

以下五類即使標題出現 Anthropic 也**不進本頁**，改在回報標明轉知：

| 型態 | 落點 |
|---|---|
| Anthropic 自己的動作（融資、合作、IPO、估值、資本支出） | [[topics/anthropic-business]] |
| 人事流動（誰去了誰家） | [[topics/ai-talent-flow]] |
| 管制與其實效（出口管制、地理封鎖、繞過、灰市） | [[topics/anthropic-government-policy]]（轉知安全政策記者） |
| 具名企業採用／退出事件 | [[topics/enterprise-tool-tracker]]（事件層），本頁只留一行結論＋wikilink |
| 股價方向與市場判讀 | [[topics/market-signals]]（轉知投資分析記者）；**本頁不得出現股價語言** |

判斷式：**「Anthropic 自己做了什麼」不進本頁；「別人衝著 Anthropic 做了什麼」才進。**

### 1. 觸發條件（三類，各有落點）

- **(a) 競品定價變動**（訂閱月費、API 費率、換算後成本倍數）→ 覆寫 `## 競品定價對照` 該競品那一列。
- **(b) 競品能力或可用性變動**（發布、開源、下架、斷供）→ 覆寫 `## 對手雷達` 該對手那一列的「最新動態」與「衝擊度」。
- **(c) 其餘**（分析文、傳聞、廠商自宣、非競品）→ `## 時序` 一行，**不開子節**。

數字須回 `news/*.md` 原文查證；查無具體公開數字時依 `.claude/rules/wiki-ingest-format.md`「懸置標記語法」標記，不可推算或杜撰。

### 2. `## 對手雷達`（覆寫式，本頁的核心交付）

五欄固定：`對手｜最新動態（日期）｜衝擊面｜衝擊度｜這個消息有多硬`。

- **最新動態**寫成「X 發生了 → 對用 Claude 的人 Y」；只寫事實答不出 Y 的，退回 `## 時序`。
- **衝擊面**四選一：定價／能力／生態／政策。
- **衝擊度＝「若這則屬實，讀者要不要改變什麼」**，與證據硬度**分開判**：
  - 🔴 **會改變決策**：讀者可能因此換工具、改預算、或延後升版——競品在讀者已經在用的那一層出現可比的價格或能力落差。
  - 🟡 **要留意但先不動**：影響的是讀者的上游（他用的工具的供應商、他所在市場的價格帶），他本人現在不必做任何事。
  - ⚪ **知道就好**：不影響任何 Claude 使用者當下的選擇（新進入者、廠商自宣、尚無對比對象）。
  - **判準是「屬實的話」——證據不足不降衝擊度，只降硬度欄。** 兩欄同時偏低者本來就不該進表。
- **這個消息有多硬**：寫來源數與缺什麼的白話（如「跨 2 媒體，月費數字缺」）。**它不能取代懸置標記**——仍需標記的事實照舊在表下「懸置細節」區放完整標記，短標記 ⟨Q-nn⟩ 放本欄末。
- **排序**：衝擊度降序，同級以最新動態日期新者在上。不按廠商字母、不按首次追蹤日。
- **准入**：具名產品或廠商，且與 Claude 在工具層或模型層直接競爭。新聞稿自宣、分析文、人事、管制、投資敘事不進表（見第 0 條）。
- **退場**：⚪ 且 90 天無新動態 → 移出表，降為表下「久未更新」一行；🔴🟡 不因時間退場，但 90 天無新動態須降一級。
- **上限 12 列**：滿了先汰除最舊的 ⚪；⚪ 汰盡仍滿 → 回報主編，不自行汰除 🟡。
- **同廠商跨層合為一列**（如 Meta 的 Muse Code 與 Muse Glimmer），兩者都寫進動態格。

### 3. `## 競品定價對照`（覆寫式）

- 四欄不變：`工具/模型｜定價｜vs Claude 定位｜來源日期`。
- **一個競品永遠只有一列**——有新價就覆寫並更新來源日期，**不新增第二列**。
- **合併列時，儲存格只留**：定價數字（或「未見掛牌價」）＋一句定位＋最新來源日期；被合併掉的脈絡（雙軌策略推論、對比對象不可混用、實測條件）**一律下沉表下「競品定價細節」區，每條 ≤200 字元**。
- 表滿 **12 列**或某列來源日期 **>90 天** → 移出表，降為表下「久未更新」一行。
- **定性宣稱**（「大幅降低成本」無數字）不佔列，寫進 `## 對手雷達` 的「這個消息有多硬」欄。
- 儲存格 ≤120 字元（全站通用，`.claude/rules/wiki-ingest-format.md`「表格放結論，細節下沉」）。

### 4. `## 硬答案`（累積封頂 6 條）

- **准入**：有**可查證的頭對頭數字或可查證定價**，且答的是讀者會單獨問出口的問題；每條必帶查證日。
- **退場**：上限 6 條，滿了汰除**查證日最舊者**（不是「最不重要者」——重要性沒有判準，日期有）。查證日距今 >90 天者在條目末加「（YYYY-MM-DD 查證，此後未回訪）」；>180 天直接汰除。
- **不寫跨家跑分數字**（見第 7 條）。

### 5. `## 雷達細節`（按需，只為 🔴 開）

- 只為衝擊度 🔴 的對手開子節，**上限 8 節**。新對手預設不開子節，只進雷達表一列。
- 每節固定兩層、**≤6 行**：
  - **現在的答案**（≤3 條可執行結論）
  - **還沒解決**（≤2 句）
- **軌跡不寫在這裡**——「Microsoft 三次動作的連貫」屬 `## 時序`（一行制，一則一行，讀者自然看得到連著的四行）。細節節只准寫「現在」，這樣它結構上就長不回舊版 28 節（舊版的病灶正是每節都在複述自己的歷史）。
- 對手降為 🟡⚪ 時，該節結論併入雷達表那一格後**移除子節**。

### 6. `## 時序`（累積，一行制）

- 非定價事件在 `## 時序` prepend **一行**：`- **對手名**：一句話事實（來源）`。
- **不得展開意涵、不得寫「詳見…子區塊」**——時序是索引不是正文，互指「詳見」會讓兩邊都缺席。
- **保留最近 3 個完整月**（本月＋前 2 月）；更舊者依 `.claude/rules/wiki-ingest-format.md`「時段蒸餾與封存（全站通用）」逐月封存至 [[topics/competitor-landscape-archive]]，每次 lint **至多 2 個時段**。保留窗與封存門檻是同一條線的兩側，不會出現無家可歸的月份。

### 7. `## 查證快照（2026-08-13，不回訪）`（凍結區，只減不增）

Claude Code vs Codex 的頭對頭比較表與四組基準分數凍結於此，**不新增、不回訪**。新的跨家數字一律不寫進本頁，改在雷達表硬度欄寫「最新排名見 [[topics/model-task-leaderboard]] 本週快照」。理由：本頁標頭蒐集邊界句已對讀者承諾「帶跑分數字的第三方對照評測收不到、缺口處改指向外部活榜單」。

### 8. `## 摘要` 與頂部 callout

- 頂部 `> **本週衝擊**` **覆寫**（不 prepend）：上限 3 行，**只收 🔴🟡**，每行結尾必須是「所以呢」，🟡 必須寫得出影響讀者的哪個決定。
  ```

## 11. 仍需使用者裁決（3 點）

### 1. 手術切法：一刀到位 vs 兩刀（規則一次到位）

- **(a) 兩刀**（第 9 節）：本週規則全文＋雷達表＋前置手術＋06 封存；下週定價表合併、雷達細節重寫、時序一行制。**規則不切半**，記者手上永遠一套規則。
- **(b) 一刀到位**：本週全做完（約 6.2 小時，單一 commit 巨大）。
- **建議 (a)**。理由：第二刀的三件事（定價表合併、細節節重寫、時序改寫）都是**收斂到已生效規則**的動作，晚一週不會產生矛盾；而一次改 500+ 行的 commit，出錯時難以定位是哪一步弄壞了 `run_tests`。

### 2. ⟨P-01～03⟩ 是否順手轉正為 ⟨Q-03～05⟩

- **(a) 轉正**：改編號並把 metadata 由 `標｜複｜查` 改為 `標｜查｜複`，三筆從此被 `PENDING_RE`／`SHORT_RE` 看見，納入每日探針掃描與逾期佇列。副作用：本頁 `pending_count` 由 6 升至 9（誠實上修，且三筆複查日都是 09-13＝未來，**不會製造逾期警報**）；全庫「舊字樣存量」由 30 降至 27（棘輪基線只擋新增，下降無妨）。
- **(b) 不轉正**：維持現狀，三筆繼續對機器隱形，成對紀律純靠人守。
- **建議 (a)**。理由：本案的核心主張是「能被抓到壞掉的方案優於看起來乾淨的方案」，而這三筆正好是頁面上唯一機器看不見的懸置。成本是三行文字。

### 3. `## 查證快照（2026-08-13，不回訪）` 的存續期限

- **(a) 訂 180 天自動汰除**（2027-02-09 前後由 lint 移除整節，結論已由活榜單承接）。
- **(b) 永久保留為證據層**（跟 archive 一樣只增不減）。
- **建議 (a)**。理由：一個明說「不回訪」的區塊若沒有到期日，三年後仍會掛在頁上，而讀者不會每次都注意到標題裡的日期；180 天與 `## 硬答案` 的 >180 天汰除規則同一把尺，記者只要記一個數字。
