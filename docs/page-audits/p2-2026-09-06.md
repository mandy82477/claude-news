## 1. 使命句候選（各兩句，定稿由主 session 判）

**feature-radar**

- **A（推薦）**：**「這禮拜官方動了什麼、值不值得你現在跟，以及跟上去會壞什麼。」**
  理由：決策層三節（`⭐ 本週推薦` L11–19、`⚠️ 升版風險` L23–55、`⏰ 倒數中` L59–66）正好是這三問，且三節都已有覆寫機制與明文規則。它承諾**衝擊與時限**，不承諾逐版裁決——符合「不虛報優先於行動導向」。

  缺點：把 91 列全覽表排除在使命外，而全覽表是本頁唯一的橫向索引。

**不建議：**「Claude 官方功能全紀錄」。那是現況（78% 版面是月度條目），但這個使命會讓 685 行編年史當主角，把 56 行決策層擠成附錄。

**entities/claude-code**

- **A（推薦）**：**「Claude Code 現在有什麼毛病、哪些修了、哪些你得繞過去。」**
  理由：`## 已知問題` 241 條／286 行是全頁最大且**唯一自帶狀態層**的資產（🔴／✅／⛔／❓／🔎 五值，九組組頭統計經掃描全部自洽）。版本表與歷史記錄是它的證據層，不是主體。

  缺點：把 121 列版本表與 subagent 對照表排除在使命外，而後者正是使用者興趣線索的落點。

## 11. 設計起點

**feature-radar Q2（版面達得到嗎）：不及格，一處。** 使命是「該不該現在動」，但決策層只佔 6%，且 `⚠️ 升版風險` 把結論（不必怕，直接升）藏在三個舊 🔴 之下——**版面說的話與資料說的話相反**。這不是文筆問題，是排序問題。

**entities/claude-code Q2：不及格，兩處。** (a) 241 條已知問題有狀態層卻**沒有結論層**，讀者拿得到「這是已知的」，拿不到「這些裡面哪幾個現在會咬到我」；(b) 出口只有一條（L87），Q1 與 Q4 的讀者從本頁走不出去。

**一句給設計者的起點：**

> 兩頁各有一節已經是對的形狀——radar 的 `升級前該做的事`（L48–53：**我的情況 → 我要做什麼**）與 claude-code 的 `Subagent 型別差異對照`（L537–586：**先分軸，再逐軸給覆寫式小表，每表帶查證日**）。把這兩個形狀當本輪的通用單位，讓「升版風險」與「已知問題」各自長成它；**兩頁的編年層（radar 685 行月節、claude-code 286＋127＋151 行）先蒸餾、先補退場線，補完之前不要動拆頁，也不要在無退場機制的表上再加欄。**
