## 提案 A 問題清單

### 🔴-A1｜衝擊度判準與「這個消息有多硬」是同一根軸，且 A 的示範自己違反自己的判準

**證據**：提案 L54 定義「🔴＝有可查證的定價或能力數字直接可比 Claude 現行方案；🟡＝方向明確但數字未載」；同頁 L60 的示範第一列把 Meta Muse Code 標 **🔴**，而該列的動態欄自己寫著「**月費未載**」、硬度欄寫「**數字缺**」。照 A 自己的判準這列只能是 🟡。

這不是筆誤，是設計問題：判準量的是**證據硬度**，但表已經有一整欄在量證據硬度（「這個消息有多硬」）。兩欄同軸的後果是——一個會讓讀者立刻換工具的重大威脅，只要沒公布數字就永遠上不了 🔴；一次無關痛癢的調價只要有數字就是 🔴。使命句問的是「衝擊**多大**」，不是「消息多硬」。明天的記者拿這條判準判，會判出一張按「誰有公布數字」排序的表。

**改法（可直接貼進記者規則）：**

> **衝擊度＝「若這則屬實，讀者要不要改變什麼」，與證據硬度分開判（硬度寫在『這個消息有多硬』欄）：**
> - 🔴 **會改變決策**：讀者可能因此換工具、改預算、或延後升版（如競品在讀者已在用的層級上出現可比的價格或能力落差）
> - 🟡 **要留意但先不動**：影響的是讀者的**上游**（他用的工具的供應商、他所在市場的價格帶），本人現在不必做任何事
> - ⚪ **知道就好**：不影響任何 Claude 使用者當下的選擇（新進入者、自宣、尚無對比對象）
>
> **判準是「屬實的話」——證據不足不降衝擊度，只降硬度欄。** 兩欄同時偏低者，本來就不該進表（見准入）。

照這條重判 A 的三列示範：Muse Code 🔴（價格戰打到讀者這一層，屬實就要重新比價）／Cursor 斷供 🟡（A 自己在示範裡寫「對用 Claude Code 的人不是」——那正是 🟡 的定義）／HydraFusion 🟡。

### 🔴-A2｜「index 鉤子同步義務」叫商業記者去改 `wiki/index.md`，直接違反記者邊界

**證據**：提案 L125 新增第 4 條「規則加一句：雷達表首列換人時，同步改寫該摘要格」。而 `.claude/rules/wiki-reporter-shared.md`「邊界限制」明文：**「不可碰 `wiki/feature-radar.md`、`wiki/index.md`、`wiki/log.md`（由主編統一處理）」**。

而且 index 第 95 列的摘要格現在長這樣（實際檔案）：

```
| [[topics/competitor-landscape]] | 💼 商業 | ongoing | Google 祕密開發競品 + OpenCode 157K 分流 + DeepSeek clone 低成本替代生態　↳ 子故事：[[topics/competitor-landscape-archive]] |
```

後半段 `↳ 子故事：` 是 `scripts/gen_wiki_frontmatter.py` 投影的機器內容，`scripts/check_hierarchy.py` 第 6 項在驗。叫記者「改寫該摘要格」＝叫他手動編輯一個半機器格，手滑掉投影就是 run_tests 紅。

**改法：**

> 4. **index 鉤子失效轉知**：`wiki/index.md` 該列摘要格的鉤子句現為 04–05 月舊事實。雷達表首列（衝擊度最高者）換人時，在回報「同步自查」欄寫 `⚠️ 需主編同步 index 鉤子：[新的一句鉤子]`，**不可自行編輯 `wiki/index.md`**——該格後半段的 `↳ 子故事：` 是機器投影，手改會被 `check_hierarchy.py` 抓到。主編改的只有 `　↳` 之前那半段。

### 🔴-A3｜蒸餾封存用超了契約門檻：07／08 月都不到 3 個月，且一次開三個時段

**證據**：`.claude/rules/wiki-ingest-format.md`「時段蒸餾與封存（全站通用）」三處硬條件——
1. 「候選門檻：該月距今 **≥ 3 個月**（月份算術：本月序 − 該月序 ≥ 3）」→ 今天 09-05，只有 **2026-06 及更早**達標（9−6=3 ✅；9−7=2 ❌；9−8=1 ❌）
2. 「**每頁至多 2 個最舊時段**（漸進，不一次大搬家）」
3. 對象判準：「這個區塊的條目是按時間 prepend 的嗎？」——**Codex 頭對頭表不是**，它是一張累積表

提案 A 三處各踩一項：L86 把頭對頭 7 列表「搬 archive `## 2026-08`」（非時序區塊＋1 個月）、L89「07 月上旬起走蒸餾封存」（2 個月）、L134 一次新增 `## 2026-06`／`## 2026-07`／`## 2026-08` 三個分節（超過 2 個時段上限）。

後果不只是違規：archive 頁狀態是 `resolved（封存頁）`、callout 寫著「本頁為原始條目封存」。把上個月還在延燒的東西丟進去，等於**對讀者謊稱它已經結案**；⟨Q-02⟩（標 08-22，未結案的 ❓）跟著進去，`scan_pending_verifications` 之後命中，派工單上會是一個封存頁——記者照 shared 規則只能加 `訊`，這筆懸置實質被凍住。

**改法：**

> **本輪只封存 2026-06 一個時段**（唯一達 ≥3 個月門檻者），archive 新增 `## 2026-06` 一節，主頁該月蒸為 ≤15 行時段總結＋末行 `原始條目見 [[topics/competitor-landscape-archive#2026-06]]`。
> **07、08 月留在主頁**，改一行制（見時序窗口，裁決點 4）；下個月 lint 再封 07，再下個月封 08——這就是契約要的漸進。
> **Codex 頭對頭表不進 archive**（它不是時序區塊）。它的去處見 🔴-A6／裁決點 1。

### 🔴-A4｜宣稱的 lint 看守是假的：`table_census.py` 不驗字元數、也不驗列數上限

**證據**：提案 L127「用它驗 ≤120 字元與列數上限，不寫新腳本」。實際讀 `scripts/table_census.py`——它輸出的是 `| 頁 | 節 | 欄 | 列 | 成長 | 機制 |`，`census()` 只算 `len(header)`／`len(rows)`／日期欄有無／prepend-append 判定，**全檔沒有任何字元數邏輯，也沒有任何上限判定**（`_mechanism()` 甚至只是拿**節名字串**去 `.claude/rules/*.md` 搜有沒有「淘汰|移除|覆寫|…」這類詞，是啟發式，檔頭自己寫著「『有』代表有人寫過規則，不代表規則被執行」）。

一個提案的核心防線寫著一個不存在的功能，比沒有防線更危險——下一輪 lint 會看到「已有機械看守」就跳過。

**改法（把兩件事拆開寫進 lint 回報條）：**

> **雷達表健檢（商業記者 lint 回報欄）：**
> - 列數與成長型態：`python scripts/table_census.py topics/competitor-landscape`（它只回報欄數／列數／成長型／規則檔有無提到該節名——**不驗字元數，也不會擋任何事**，讀數字自己判）
> - 儲存格 ≤120 字元自查（沿用 `.claude/rules/wiki-ingest-models.md` G 條那行，換頁名）：
>   ```
>   python -c "import re;[print(n,len(c)) for n,l in enumerate(open('wiki/topics/competitor-landscape.md',encoding='utf-8'),1) if l.startswith('|') for c in re.sub(r'\]\([^)]*\)',']',l).split('|') if len(c)>120]"
>   ```
>   有輸出且非純引用來源格 → 違規，先短語化再收工
> - 回報欄：`雷達表健檢：N 列（🔴a／🟡b／⚪c）／逾 90 天未動 M 列（已處置）／超長儲存格 K 格（已下沉）`

順帶一個機械副作用要知道：`table_census._mechanism()` 是**拿節名去規則檔搜**的。所以 `## 對手雷達`／`## 競品定價對照` 這兩個節名一旦改，普查立刻報「無機制」——**節名在這裡是機械契約字串**。提案 L141「本頁零錨點入邊，節名可自由重組」只對 wikilink 成立，對 table_census 不成立。動刀時務必讓新規則檔逐字寫出新節名（A 的三句改寫剛好有寫到，但要當成契約守，不是順手寫）。

### 🟡-A5｜「同競品合併為一列」會把已經超標的定價表格子撐得更大

`## 競品定價對照` 現況已違反全站通用的「儲存格 ≤ 120 字元」：L66（Muse Code）、L72（pi-coding-agent）、L79（GPT-5.6）等格都在 150–250 字元區間。A 要把 DeepSeek 三列併一、Muse 兩列併一——**合併的定義就是把兩三格的內容塞進一格**，不配套下沉就是把違規放大。

**改法**：合併規則加一句——

> 合併列時，**保留在儲存格裡的只有：定價數字（或「未見掛牌價」）＋一句定位＋最新來源日期**；被合併掉的脈絡（雙軌策略推論、對比對象不可混用、實測條件）一律下沉「競品定價細節」區，每條 ≤200 字元。合併後跑上方的字元數自查，有輸出才算沒做完。

### 🟡-A6｜`## 讀者速答` 保留跨家快照分數，與**本頁自己的蒐集邊界句**打架（比 MC L193 更硬的證據）

簡報把這件事框成「本頁 vs model-comparison L193 的硬衝突」。實際更嚴重的是**本頁標頭那一行**（L29，且被 `.claude/review-registry.json` must_contain 看守）已經自己承諾：

> **帶跑分數字的第三方對照評測收不到**……因此本頁的競品能力比較以官方數字與社群並排實測為主，**缺口處改指向外部活榜單**（見 [[topics/model-comparison]] 的外部評測榜單節），**不自行推算**。

A 的讀者速答（提案 L108）在正文放 SWE-bench 88.6–88.7%／69.2% vs 58.6%／82.7% vs 69.4%——標頭說「這類內容收不到、改指活榜單」，正文擺著一整排跑分。冷讀者不會去讀 MC L193，但他會同時看到這兩段。詳細意見與第四種收法見下方裁決點 1。

### 🟡-A7｜`## 讀者速答` 自己是一個沒有淘汰機制的成長區（正是本次要治的病）

骨架表寫「累積封頂（上限 6 條）」，但**新增四條規則裡沒有任何一條寫讀者速答的准入／退場**。上限寫在提案文件裡、不寫進規則檔＝下個月它有 9 條。而且「上限 6」不回答滿了汰誰。

**改法（補為新增第 5 條）：**

> 5. **`## 讀者速答` 准入／退場**：准入＝有**可查證的頭對頭數字或可查證定價**，且答的是讀者會單獨問出口的問題；每條必帶查證日。上限 6 條，滿了汰除**查證日最舊者**（不是最不重要者——重要性沒有判準，日期有）。查證日距今 >90 天的條目，在條目末加「（YYYY-MM-DD 查證，此後未回訪）」；>180 天直接汰除。

### 🟡-A8｜`## 雷達細節` 只為 🔴 開節 ⇒ 考題 b4 對多數對手答不出來

A 的骨架表把 b4（「某則合作對競爭格局意味什麼」）掛在 `## 雷達細節`，但准入是「只為 🔴 開節、上限 8」。🟡⚪ 的對手在全頁只剩雷達表一格（≤120 字元）。b4 現況本來就是 ⚠️，改完對 🟡⚪ 仍是 ⚠️。

**改法**：不必為此開節——把雷達表「最新動態」格的寫法規定成**帶意涵的一句**（「X 發生了，所以對用 Claude 的人 Y」），並在骨架表把 b4 的落點誠實改成「🔴 對手→雷達細節；🟡⚪→雷達表一句＋時序」。答不到就寫答不到，別讓骨架表宣稱涵蓋。

### 🟡-A9｜「觀察重點為覆寫式結論層」與骨架表對不起來

新增第 3 條規定 `## 觀察重點` 是覆寫式結論層，但 A 的**頁面骨架表裡根本沒有這一節**（L84 說 3 條真結論併入摘要與雷達表）。記者拿到規則會去找一個不存在的節，然後自己建回來——28 節的復活入口。

**改法**：二選一並寫死。建議刪節，第 3 條改為：「跨對手的結論寫進 `## 摘要`（3 句上限），**不另開 `## 觀察重點`**；單則新聞一律進時序。」

### 🟡-A10｜MC「外部評測榜單」加一列，是動別的記者的頁，且欄位形狀不合

提案 L101 要在 model-comparison 的外部評測榜單表「加一列『Claude Code vs Codex 誰強』→ 指 leaderboard」。兩個問題：(a) 那頁是**模型記者**的，商業記者不能寫，要走 `scripts/pending_handoffs.py open --from 商業 --to 模型`；(b) 那張表的第一欄是「**你想做的任務**」（寫 code、畫圖、選 API…），「誰強」不是任務，硬塞進去會破壞該表的問句形狀。

**改法**：改為在 MC 的「外部評測榜單」節**散文末尾**加一句（仍走轉知），或乾脆不加——a3 走錯頁的讀者由本頁「相關頁面」節反向接住即可。

### 🟢-A11｜時序一行制的 tag 會在網站卡片上留下裸中括號

`scripts/build_web.py` 的 `latest_headline()` Pattern 2 讀 `## 時序` 第一個 `- ` 行當列表卡片摘要。它的 `^\*\*\[[^\]]*\]\*\*\s*` 只剝**獨立成粗體**的 `**[tag]**`；A 的一行制格式 `- **[對手名] 一句話事實（來源）**` 是整行一個粗體，剝完會留下字面的 `[對手名]`。現行格式 `- **[新增追蹤，明確截止日] Reddit：…**` 也一樣（所以這是既有現象、非新錯），但既然要改格式，順手改成 `- **對手名**：一句話事實（來源）` 就乾淨了。

### 🟢-A12｜「本週衝擊」第二行自證不該在表上

示範第二行結語是「對用 Cursor 的人是變數，**對用 Claude Code 的人不是**」——這是誠實的好句子，但它同時說明這則對本頁讀者沒有衝擊。放進「本週衝擊」的前三行，等於用最貴的版位講一件不影響讀者的事。建議 callout 准入寫死：**只收 🔴🟡**，且 🟡 必須寫得出「對讀者的哪個決定有影響」。

### 🟢-A13｜`## 讀者速答` 這個名字在本頁已經被用掉兩次

L58（定價表 callout「讀者速答『競品各多少錢』」）與 L173（頭對頭表下的 `**讀者速答**：`）。升成 h2 之後同頁三個「讀者速答」，`table_census` 的節名比對與日後 grep 都會混。建議 h2 改叫 `## 硬答案`／`## 已查證的頭對頭`，並把舊的兩處粗體標籤改掉。

## 提案 B 問題清單

### 🔴-B1｜母頁契約與 B 自己的日更規則正面對撞

B 的維護者同步第 6 條明文採用母頁契約：「每日 ingest 母頁**只准動三樣**——頂部 callout、分支目錄表、既有懸置標記加 `訊`；`## 對手雷達` 的結論層整線重寫留給 `/wiki-lint`」。

但 B 同時全盤沿用 A 的三句改寫，其中第一句是：「(b) 競品能力或可用性變動 → **覆寫 `## 對手雷達` 該對手那一列**」——那是每日 ingest 的動作，落在母頁的非三樣區。明天的記者同時拿到「每天覆寫雷達表」與「母頁每日唯讀」，兩句都在同一份規則檔裡。

這不是措辭問題：**雷達表如果只能週更，本頁就答不了 a1／b3（本週有什麼新東西）**，而那正是使命句。

**改法（三選一，需在提案內定案，不能兩句並存）：**

> (i) 母頁契約的「每日唯讀」只適用於**有子故事頁分擔事件流**的結論層節；`## 對手雷達` 明文列為**每日可覆寫的例外**（理由寫在規則裡：它是本頁對使命句的直接交付，週更會讓 a1 失效）。

### 🔴-B3｜`check_hierarchy` 第 5 項會在「只有子頁有新聞」的日子擋掉 web build

## 對「需使用者裁決的 6 點」的評審意見

### 1. MC L193 硬衝突怎麼收——**不同意設計 agent 傾向的 (b)，建議第四種收法 (d)**

設計 agent 傾向 (b)：本頁保留結論行、MC L193 加一句例外。反對理由有二：

- **更硬的證據不是 MC L193，是本頁自己的標頭**。L29 蒐集邊界句（`.claude/review-registry.json` must_contain 看守）已經對讀者承諾「帶跑分數字的第三方對照評測收不到……缺口處改指向外部活榜單……不自行推算」。留數字＝標頭與正文互相打臉，而且冷讀者兩段都會看到。改標頭那句則是改對讀者的承諾，比改 MC 更嚴重。
- (b) 要動 MC 的立法。**能不立法就不要立法**——一個為了單頁版面而在別頁開的例外，三個月後沒有人記得它為什麼在。

**(d) 第四種收法：數字不搬家、也不留在重點層——留在它已經在的證據層。**

> 頭對頭那 7 列與 08-13 查證的四組分數，**原樣留在本頁**，但整節降級並在表上方標「**2026-08-13 查證快照，不回訪**」；`## 硬答案`（原讀者速答）那條只寫**哪個基準測什麼能力、該看哪個活榜單**，不寫分數，末尾一句「當時的實測數字見下方『08-13 查證快照』」。
>
> 結果：MC 不用改一個字（L193 管的是 MC 自己）；本頁蒐集邊界句不用改（沒有新增跑分、沒有自行推算、確實指向了活榜單）；數字有家、且那個家自己標明是過期快照；`## 硬答案` 保持「只放不會過期的東西」。**不需要立法，所以其實不需要裁決**——若使用者採 (d)，這一點可以直接從裁決清單移除。

（若使用者仍偏好搬走，(c) 搬 leaderboard 確實會破壞那頁的週快照覆寫契約，設計 agent 的判斷正確。）

### 2. 衝擊度判準要不要凍結成 registry 機械契約——**不同意凍結**

`.claude/rules/claude-md-edit.md`「機械契約字串住固定區」的准入條件寫得很清楚：**「這個字串有沒有任何 script 在 grep？用指令答，不憑印象」**。衝擊度判準散文沒有任何消費端（我跑過 grep：`scripts/`、`web_reader/assets/`、`src/tests/` 對 `衝擊度` 零命中）。凍進 registry 只會多一處要同步、零看守力——正是該檔警告的反面。

**真正該凍的是欄位形狀，不是判準散文**，而且要先有消費端。建議：

> 本輪**不登記 registry**。改為在規則檔裡把判準寫成讀者處境語言（見 🔴-A1 改法），並由 lint 每週複查全表分級（人工，寫進商業記者 lint 回報欄）。**若日後真要機械化**，該登記的是雷達表表頭五欄的逐字形狀，且必須同時寫出消費它的 script（例如讓 `table_census` 對本頁多驗一條欄位順序）——沒有消費端就不進 registry。

### 3. 脈絡砍到 5 行還是 8 行——**兩個選項都答錯了題，建議改問法**

行數不是旋鈕。要問的是：**那條軌跡現在還在影響選型嗎？** Microsoft 三次動作的連貫軌跡（06-21 退訂 → 07-07 自研模型 → 07-15 銷售話術 → 08-10 基建投資）之所以有價值，是因為它**還在往同一個方向走**；Zhipu 從編碼到資安的演進同理。而一旦某條軌跡的結論定了（如「Microsoft 已全面轉向自研＋Copilot」），軌跡就變成歷史，該在時序而不在細節節。

**建議收法（比 5 行/8 行都更能防復發）：**

> `## 雷達細節` 每個 🔴 對手固定兩層、**≤6 行**：
> - **現在的答案**（≤3 條，可執行結論——照 `community-large-codebase-workflow` 已驗證的契約形狀）
> - **還沒解決**（≤2 句）
>
> **軌跡本身不寫在這裡**——它是時序的事（一行制，一則一行，讀者自然看得到 Microsoft 四行連著）。細節節只准寫「現在」，這樣它結構上就長不回 28 節（28 節的病灶正是「每節都在複述自己的歷史」）。

### 4. 時序保留窗 60 天還是 90 天——**兩個都不對，這題與蒸餾門檻互斥**

今天 09-05。蒸餾契約要求 ≥3 個月才可封存 → 只有 06 月可封。60 天窗（回推到 07-07）會把 07 月從主頁清掉，**但 07 月封不進 archive**——那批內容會無家可歸（不是搬走，是刪掉）。90 天窗（回推到 06-07）剛好也吃到封不了的 07 月。設計 agent 兩個選項都會撞牆。

**建議：把保留窗綁在蒸餾門檻上，用同一把尺。**

> `## 時序` 保留**最近 3 個完整月**（本月＋前 2 月；今天＝09、08、07），更舊者依 `.claude/rules/wiki-ingest-format.md`「時段蒸餾與封存」逐月封存，**每次 lint 至多 2 個時段**。
>
> 好處：保留窗與封存門檻永遠是同一條線的兩側，不會出現無家可歸的時段；且每個月自動滾動一格，記者不用記天數。本輪即：09/08/07 留在主頁（改一行制），06 蒸餾入 archive。

### 5. 是否一併處理內部用語外洩——**同意順手做，但範圍限本頁正文**

理由：這些字有一半（`專頁定向` 出現在觀察重點兩條、`source_count=2` 出現在定價表與 OpenCode 節）本來就在這次要動刀的段落裡，**不順手改反而要動兩次**。全站清單維持另立待辦不變。

改寫對照（不是刪除，是換讀者語言）：`專頁定向` → 刪除該括號（該資訊已由標頭蒐集邊界句用讀者語言講過）；`source_count=2` → 「兩個獨立來源」；`暫不覆寫上方…僅並列記錄` → 「與 05-18 的 157,000 名並列，兩個數字口徑不同」；`詳見下方細節` 保留（那是讀者導航，不是內部術語）。

### 6. C 當第一刀、A 當第二刀——**不建議**

C 的三件事**不是** A 的真子集（設計 agent 這句判斷是錯的）：
- 時序：C 是「07 月蒸餾＋08 月一行制不搬」，A 是「近 60 天一行制、更舊封存」——兩套不同的窗
- 規則：C 是「不改現行三句、只加三句」，A 是「三句全部改寫」——A 的第一句改寫直接推翻 C 加的第 3 句（C 說「累積 ≥3 則才開子節」，A 說「一律不開子節，只進雷達表」）

先做 C 等於**先立一版下週要推翻的規則**，記者在兩週內收到兩份互相矛盾的規則檔——`.claude/rules/wiki-ingest.md` 的「🚫 派工 prompt 不得臨場加寫操作指示」講的正是這種矛盾的代價（記者同時拿到兩份指令，只在他剛好夠警覺時才會被發現）。

**若使用者本週時間有限，該切的是 A 的範圍而不是換成 C：**

> 第一刀（本週，同一 commit）：前置手術＋刪指標表＋`> 本週衝擊`＋`## 對手雷達`（28 節先只壓成表，細節節暫時整批留在表下方不動）＋**規則三句改寫＋新增五條一次到位**＋06 月封存。
> 第二刀（下週 lint）：定價表合併與細節區瘦身、`## 雷達細節` 依 🔴 篩選與 ≤6 行改寫、07 月封存。
>
