## 2. radar：版本階梯表（Q1 的核心交付）

**判準句：一列一個版本門檻，只收「破壞性變更」與「預設值改變」兩型；純新增功能不進表（它不會在你不知情時改變行為）。**入表的第二道是「誰會遇到」——**「你要做的事」欄寫得出對號條件就入表，寫不出限定的收進表下 catch-all 句**（與 claude-code 結論表判準 ② 同一根軸）。**上限 12 列，依版本降序。退場：列的版本距今逾 3 個月即移出，降入 catch-all 句並點名，原記錄留在 [[entities/claude-code#版本更新]]。新增列的依據只有官方 changelog——本庫報導覆蓋率不算數。**

逐字見 `scratchpad/p2-draft.md` 第 14–36 行，**十二列**（261／260／257／243／239／234／233／232／222／215／212／207），依 verified 第六節的完整 changelog 重寫。**兩處判準修正讓這十二列成為可推導的結果，不是手挑**：

- **第二道判準的軸從「場景寬窄」改成「寫不寫得出誰會遇到」。** 我上一版用寬窄判、把 v2.1.239 剔除；評審把它寫回去並在格子裡寫明「不在資料常駐工作區的人不受影響」——**那個限定句一寫出來，這一列就對讀者有用了**。寬窄是我的主觀感覺，「寫不寫得出對號條件」是可查的，而且與 claude-code 結論表判準 ② 同軸，兩張表從此同一把尺。
- **退場線 6 個月改 3 個月，上限維持 12、不改 13。** 原本「破壞性變更一律必列」＋6 個月窗，數學上撐不住——任何一季出現三個以上破壞性變更就爆表。改 3 個月後 v2.1.160（2026-06-02，逾 3 個月）**依規則自己離場**，不必為它破例，也不必手動判「它夠不夠重要」；它在 catch-all 句裡被點名，讀者仍找得到。

表上一句改為「本表的依據是官方 changelog 逐版核對（核對到 v2.1.261，2026-09-06），不是本庫的報導覆蓋率；2.1.213／230／242／249／250 是官方未發行的跳號，不是缺漏」（🟡-5）。

**「以上皆非 → 可直接升級」的矛盾是漏字，不是判斷錯（依補充查證 V8 改寫）**：#53940 的 issue 標題就是「Cowork Edit/Write tools silently truncate」、標籤 `area:cowork`＋`platform:windows`，所以舊表「重度使用 Cowork」那列本來就是對的——冷讀者判它「與 Cowork 無關」，是因為頁面 L35／L43 兩處都漏寫「Cowork」。**處置改成補限定詞而非搬結論**：三行風險細節各補平台／產品限定（#22543 桌面版 Cowork、#4953 Linux、#53940 Windows＋Cowork），三個 🔴 今天 gh 查證仍全部 OPEN，狀態不動。「以上皆非 → 可直接升級」保留，改寫成階梯表下的收尾句（上面逐字已含），讀者對得上號才敢用它。原「升級前該做的事」四列（L48–53）併入本表「你要做的事」欄，不另存一表。

## 3. claude-code：`## 現在會咬到你的`（Q4 的核心交付）

**判準句（三條全過才入表）：① 狀態為 🔴 或 ⛔，且是缺陷不是功能請求——GitHub 標 `enhancement` 者不入表，還沒做的東西不會咬你；② 「誰會遇到」欄必須寫出產品或平台限定（Cowork／Desktop／Linux／Windows／企業 SSO），寫不出限定就是所有人；③ 寫得出「你能做什麼」，繞法或「無繞法」都算，兩者皆答不出的條目留在下方分組。上限 8 列。排序：不可自行復原者（資料遺失、工作遺失、帳單、安全）在最上，其餘依「誰會遇到」的範圍由寬到窄。退場：翻 ✅ 或官方給出替代即移出；連續 90 天無新回報且非資料完整性類者移出，並在原條目末加「（已移出結論表，YYYY-MM-DD）」。**

狀態沿用本頁既有五值 🔴 未修復／✅ 已修復／⛔ 官方拒修／❓ 待查證／🔎 查無官方（九組組頭統計已與之自洽，健檢卡 N5），不引進 pricing 的 ⚖️ 與 ⏸。逐字表見 `scratchpad/p2-draft.md` 第 47–61 行，**七列**依序為 #53940、#4953、#22543、#24057、#5706、#52871、#61015——**每一列都通過我自己寫的三條**（皆 🔴 缺陷、皆寫出產品或平台限定、皆有繞法或明寫「無繞法」），排序前兩列為不可復原（檔案截斷、進程被殺），其餘由「用桌面版 Cowork 的人」逐步收窄到「用排程 routine 的人」。**#13354（額度上限自動續行）雖為 🔴，但屬功能請求非故障，依判準 ① 留在功能請求分組不入表**（V8 標籤 `enhancement`；`claude-code.md:139` 的敘述是「使用者**希望**…」），留言數 72 → 80。上限維持 8 列不動——七列是今天的實況，不是把上限改成七。

**出口**（治 Q1／Q4 從本頁走不出去）：表下一行 `**接下來看什麼**：這幾條翻 ✅ 的那一天會寫在本頁分組裡，升版判斷見 [[feature-radar]]「從你現在的版本升上去，會遇到什麼」；官方建議的做法見 [[topics/coding-workflow-guide]]。`
