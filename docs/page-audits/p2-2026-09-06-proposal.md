> **兩頁都留、都不拆。radar 的「升版風險」改成一張「從你這一版升上去會遇到什麼」的版本階梯表，claude-code 的 241 條已知問題上面加一張「現在會咬到你的」結論表；同時把熱度／試用價值收成只住全覽表一處，讓跨層打架在結構上不可能發生。**

**被考慮過但不推薦的方向（各一行）：**
- 拆 claude-code「已知問題」不選，因為子故事三題第 ② 題（自己的結論）現在就不成立——結論層正是本案要補的東西，補完才有得判。

**可行性前提（一行）：本案不需要任何新進料，也拿不到新進料。** 版本階梯表的每一列都取自兩頁既有文字或 `p2-2026-09-06-verified.md` 已查證的官方 changelog；`src/news_aggregator/sources/topic_watch.json` 的 `_global_max` 是 **8**，三個 active topic（3＋3＋2）已用滿，`_rejected` 已有一筆先例，功能線申請不到額度。兩頁節奏是每日更新（功能記者寫 claude-code、主編彙整 radar，見 `.claude/rules/wiki-ingest-features.md` 負責頁面表），本案不改節奏；**唯一新增的動作是「主編查官方 changelog 才准新增階梯列」**，該出口在 `/wiki-lint` 已存在（主編層有 web 工具）。

## 3. claude-code：`## 現在會咬到你的`（Q4 的核心交付）

**判準句（三條全過才入表）：① 狀態為 🔴 或 ⛔，且是缺陷不是功能請求——GitHub 標 `enhancement` 者不入表，還沒做的東西不會咬你；② 「誰會遇到」欄必須寫出產品或平台限定（Cowork／Desktop／Linux／Windows／企業 SSO），寫不出限定就是所有人；③ 寫得出「你能做什麼」，繞法或「無繞法」都算，兩者皆答不出的條目留在下方分組。上限 8 列。排序：不可自行復原者（資料遺失、工作遺失、帳單、安全）在最上，其餘依「誰會遇到」的範圍由寬到窄。退場：翻 ✅ 或官方給出替代即移出；連續 90 天無新回報且非資料完整性類者移出，並在原條目末加「（已移出結論表，YYYY-MM-DD）」。**

狀態沿用本頁既有五值 🔴 未修復／✅ 已修復／⛔ 官方拒修／❓ 待查證／🔎 查無官方（九組組頭統計已與之自洽，健檢卡 N5），不引進 pricing 的 ⚖️ 與 ⏸。逐字表見 `scratchpad/p2-draft.md` 第 36–50 行，**七列**依序為 #53940、#4953、#22543、#24057、#5706、#52871、#61015——**每一列都通過我自己寫的三條**（皆 🔴 缺陷、皆寫出產品或平台限定、皆有繞法或明寫「無繞法」），排序前兩列為不可復原（檔案截斷、進程被殺），其餘由「用桌面版 Cowork 的人」逐步收窄到「用排程 routine 的人」。**#13354（額度上限自動續行）依判準 ① 退出表**——V8 查得它的標籤是 `enhancement`，是還沒做不是壞掉；它留在下方分組並更新留言數 72 → 80。
