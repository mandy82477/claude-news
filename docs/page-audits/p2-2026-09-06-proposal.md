## 2. radar：版本階梯表（Q1 的核心交付）

**判準句：一列一個版本門檻，只收「破壞性變更」與「預設值改變」兩型；純新增功能不進表（它不會在你不知情時改變行為）。破壞性變更一律必列；預設值改變只列本站讀者身分（跑多代理的工程師）會碰到的，窄場景者收進表下一句指官方 changelog。上限 12 列，依版本降序。退場：列的版本距今逾 6 個月即移除，原記錄留在 [[entities/claude-code#版本更新]]。新增列的依據只有官方 changelog——本庫報導覆蓋率不算數。**

逐字見 `scratchpad/p2-draft.md` 第 14–37 行（**十列**，依 verified 第六節的完整 changelog 重寫，不再靠報導覆蓋率）：⚠️ 四條必列 212／215／232／257，多代理讀者五條 232／233／234／243／260，另補 222（移除 ultraplan、Remote Control 不能再由 repo 設定開啟）與 160（`workflow` 更名）兩條破壞性變更；**v2.1.239 與原 222「安全修復」列刪除**——前者只影響資料常駐工作區（🟡-5），後者是修好不是壞掉，收不進「破壞性變更或預設值改變」，兩者併入表下「只影響窄場景」那一句。**「v2.1.242–244 與 v2.1.252–257 未見報導」整句刪除**：verified 第六節確認那些跳號是官方沒發，不是本站漏報，留著會讓讀者以為表有洞。

**「以上皆非 → 可直接升級」的矛盾是漏字，不是判斷錯（依補充查證 V8 改寫）**：#53940 的 issue 標題就是「Cowork Edit/Write tools silently truncate」、標籤 `area:cowork`＋`platform:windows`，所以舊表「重度使用 Cowork」那列本來就是對的——冷讀者判它「與 Cowork 無關」，是因為頁面 L35／L43 兩處都漏寫「Cowork」。**處置改成補限定詞而非搬結論**：三行風險細節各補平台／產品限定（#22543 桌面版 Cowork、#4953 Linux、#53940 Windows＋Cowork），三個 🔴 今天 gh 查證仍全部 OPEN，狀態不動。「以上皆非 → 可直接升級」保留，改寫成階梯表下的收尾句（上面逐字已含），讀者對得上號才敢用它。原「升級前該做的事」四列（L48–53）併入本表「你要做的事」欄，不另存一表。

## 3. claude-code：`## 現在會咬到你的`（Q4 的核心交付）

**判準句（三條全過才入表）：① 狀態為 🔴 或 ⛔，且是缺陷不是功能請求——GitHub 標 `enhancement` 者不入表，還沒做的東西不會咬你；② 「誰會遇到」欄必須寫出產品或平台限定（Cowork／Desktop／Linux／Windows／企業 SSO），寫不出限定就是所有人；③ 寫得出「你能做什麼」，繞法或「無繞法」都算，兩者皆答不出的條目留在下方分組。上限 8 列。排序：不可自行復原者（資料遺失、工作遺失、帳單、安全）在最上，其餘依「誰會遇到」的範圍由寬到窄。退場：翻 ✅ 或官方給出替代即移出；連續 90 天無新回報且非資料完整性類者移出，並在原條目末加「（已移出結論表，YYYY-MM-DD）」。**

狀態沿用本頁既有五值 🔴 未修復／✅ 已修復／⛔ 官方拒修／❓ 待查證／🔎 查無官方（九組組頭統計已與之自洽，健檢卡 N5），不引進 pricing 的 ⚖️ 與 ⏸。逐字表見 `scratchpad/p2-draft.md` 第 43–57 行，**七列**依序為 #53940、#4953、#22543、#24057、#5706、#52871、#61015——**每一列都通過我自己寫的三條**（皆 🔴 缺陷、皆寫出產品或平台限定、皆有繞法或明寫「無繞法」），排序前兩列為不可復原（檔案截斷、進程被殺），其餘由「用桌面版 Cowork 的人」逐步收窄到「用排程 routine 的人」。**#13354（額度上限自動續行）雖為 🔴，但屬功能請求非故障，依判準 ① 留在功能請求分組不入表**（V8 標籤 `enhancement`；`claude-code.md:139` 的敘述是「使用者**希望**…」），留言數 72 → 80。上限維持 8 列不動——七列是今天的實況，不是把上限改成七。

**出口**（治 Q1／Q4 從本頁走不出去）：表下一行 `**接下來看什麼**：這幾條翻 ✅ 的那一天會寫在本頁分組裡，升版判斷見 [[feature-radar]]「從你現在的版本升上去，會遇到什麼」；官方建議的做法見 [[topics/coding-workflow-guide]]。`
