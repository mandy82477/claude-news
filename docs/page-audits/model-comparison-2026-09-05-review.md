## 案 A 問題清單

### 🔴-A1｜新表擋在 Q4 前面：唯一通過的一題被降級

A 把 `## 我在比的是哪兩個東西` 放在 LB **第 2 節**（`## 本週快照` 之前）。冷讀者四題裡 Q4（畫圖哪家最強）是 LB 唯一的 ✅，路徑 `index L92 → LB L54`，2 跳。改後讀者一進頁先撞上一張 4 列有 2 列核心欄是 ❓ 的表——而 A 自己在「代價」段寫著這張表「**會長期掛 ❓**」。

用一題永遠答不了的問題，去擠掉一題本來答得好的問題，是淨損。

**改法（可直接貼進 5b）：**

> `## 我在比的是哪兩個東西` 置於 **`## 本週註記` 之後**（第 6 節），不得置於 `## 本週快照` 之前——本週快照是本頁對讀者的主要交付，工具層換算是補充層。`## 摘要` 末句加一行導航：「你要比的是工具（Codex CLI、OpenCode）不是模型？先看下方『我在比的是哪兩個東西』。」

### 🔴-A2｜示範列違反自己寫的判準，且兩根軸量成一根（上一波同型病復發）

判準句寫死「**『它跑什麼模型』查不到就標懸置，不得推測**」。示範第 1 列（Claude Code）第 3 欄寫「Terminal-Bench 3.0、SWE-bench」、第 4 欄寫「工具＋模型合測（換 harness 分數就變）」——兩格都是推測：LB 快照表 L58 那一列的受測體逐字是「**Claude Opus 5（42.7%）**」，是**模型**不是 Claude Code；「合測」這句庫內零來源。第 2 列（Codex CLI）誠實標了 ❓，第 1 列卻沒有——同一欄兩種標準。

更根本的是軸不一致：**列的單位是「工具」，第 3、4 欄量的卻是「榜」的性質**。同一個工具在不同榜上答案不同（TB 3.0 與 2.1 排名相反，見 LB L73），一格塞不下；而第 4 欄對第 1、2 列給的是同一個值——它其實在描述 Terminal-Bench，不是描述那兩個工具。

**改法（判準與欄位一起改）：**

> 三欄固定：`工具（harness）｜它跑什麼模型｜已知以工具身分受測的榜`。
> - 「它跑什麼模型」＝**官方文件載明的預設模型**，查不到標懸置（`.claude/rules/wiki-ingest-format.md`「懸置標記語法」），不得由榜上出現的模型名反推。
> - 「已知以工具身分受測的榜」只填**該榜條目名逐字就是工具名**者；榜上寫的是模型名（如 Terminal-Bench 3.0 寫「Claude Opus 5」）→ 填 `—（榜上以模型計）`，不得填該榜名。
> - **刪除「榜量的是工具還是模型」欄**：它是榜的屬性，寫在 `## 評比方式索引` 對應榜的「盲點」欄，一榜一次，不逐列複製。

示範第 1 列照此重寫：`Claude Code | Sonnet 5 預設，可切 Opus 5／Fable 5.1（見 [[topics/model-comparison]]） | —（榜上以模型計）`。第 4 列 Pi coding agent 三欄有兩欄是 `—`，依「讀者真的會拿來替換 Claude Code」准入不成立，退出表、降為表下一行。

### 🟡-A3｜5b 是 Haiku 抓取任務，A 卻要它產出「官方文件載明的預設模型」

5b 第 1 點現行 prompt 是「逐一查該頁涵蓋榜單清單中的所有榜」。A 要加「順帶回報各 harness 官方文件所載的預設模型」——那不是查榜，是查各廠商文件，是另一種工作。塞進同一個 Haiku prompt，最可能的結果是它從榜上抄一個模型名回來（正是 🔴-A2 禁止的事）。

**改法：** 分成兩點寫，並在 prompt 內寫死否定條件：「**只採該工具官方文件／官方 README 的逐字記載**；榜單頁上的模型名不算，查不到就回報『查不到』，不得推斷。」

### 🟡-A4｜新表在 `table_census.py` 眼中會是「無機制」（健檢卡第 5 問的訊號）

`table_census._mechanism()`（L39–50）拿**節名（先剝掉全形括號內容）**去 `.claude/rules/*.md` ＋ `.claude/commands/*.md` **逐行**搜，需**同一行**出現 `淘汰|移除|保留|封存|覆寫|蒸餾|汰除|到期|清理` 任一詞。A 的 5b 改寫寫的是「另維護 `## 我在比的是哪兩個東西` 表（4 欄，判準見本步驟）」——同行無機制詞 → 普查永遠報「無機制」。

**改法（5b 該行逐字）：**

> 另維護 `## 我在比的是哪兩個東西` 表（三欄；上限 8 列，**汰除**連續 90 天無新資訊者；每週**覆寫**，不累積）。

### 🟡-A5｜「連續 4 週全 ❓ 就撤表」缺一個誰來數的機制

A 的煞車寫「5b 第 2 點加一句『工具層表連續 4 週全 ❓ → 回報使用者評估撤表』」。誰記得上一週是不是全 ❓？頁面上沒有這個狀態。

**改法：** 表下固定一行 `%% 維運備忘：全 ❓ 週數 N（YYYY-MM-DD 起算）；連續 4 週回報使用者評估撤表 %%`，5b 每週遞增或歸零。狀態寫在頁上、寫在 `%% %%` 裡（`.claude/rules/wiki-reporter-shared.md`「維運備忘的家」），才不依賴記憶。

### 🔴-B1｜`（…，不回訪）` 是禁詞，這個節名會讓 `run_tests.py` 變紅

`scripts/check_reader_language.py` 的 22 個禁詞裡有 **`不回訪`**，理由逐字寫著「維護承諾（我們不會再查），不是內容」，替代寫法逐字寫著「本節為 YYYY-MM-DD 的一次性查證結果，最新請見 [[…]]」。

實跑現況：`python scripts/check_reader_language.py` → `OK: 讀者語言閘 — 無新增命中`，存量基線 7 筆／3 頁**全在 archive 頁**，MC／LB **零基線**。B 的 `## 家內同口徑對照（2026-07-09，不回訪）` 是新增命中 → exit 1 → `run_tests.py` 紅 → `gate_web_build` 擋站。

**改法（照 CL 已經驗證過的形狀，逐字可貼）：** CL 的凍結區標題實際是 `## 查證快照（2026-08-13）`（L170），維護承諾在 L172 的 `%%` 裡：

```markdown
## 家內同口徑對照（2026-07-09 一次性查證）

%% 維運備忘：本節不新增、不回訪。到期日 2027-01-05（建立日 +180 天），屆時整節移除 %%
> 本節是 2026-07-09 那一天的同口徑數字，**之後沒有再更新**；現行陣容的選型見上方快速選型表。
```

E 條補句同步改為：「節名加『（YYYY-MM-DD 一次性查證）』，到期日與不再更新的承諾寫進 `%% … %%` 維運備忘——**『不回訪』是讀者語言閘的禁詞，不得寫進正文**。」

## 對三個裁決點的意見

### 1. 跨家答案的家放哪？——**不同意建議的 (b)，建議第三種收法 (c)**

反對 (b) 的理由是路由證據，不是偏好：**CL 不可改，而它三處都指向 LB**（L77／L172／L201）。把答案放進 MC，等於在站上製造一個「所有既有箭頭都指 LB、但答案在 MC」的結構——冷讀者走的正是那條箭頭。要修好它，只能改 CL（本波禁止）或依賴一條還沒落地的 index 路由。

同時 (a) 也不必要：A 的新表是它與 C 的唯一差異，而那張表 (i) 擋掉 Q4、(ii) 自陳會長期掛 ❓、(iii) 給 5b 加一份它不擅長的工作。

> **(c)：答案哪裡都不搬——三頁各自把「現在的答案」寫成一句話，落點維持既有箭頭。**
> - LB 摘要宣告「跨家與跨工具的排名到此為止」＋**自己先給一句答案**（「沒有單一答案，最近一次頭對頭 2026-08-13」）；`## 本週註記` 加常設「工具層對照」註記（含懸置標記）。
> - MC 摘要末句改成 🟡-C3 的逐字（結論句＋兩個出口），不建表。
> - CL 一個字不改，三處箭頭全部仍然正確。
>
> 結果：Q1 從「3 跳拿到一半」變成「3 跳拿到一句完整且標明日期的結論」，零新表、零跨維護者依賴、零 5b 改動、零 registry 新契約。**這就是案 C 加上 🟡-C3。**

### 2. Benchmark 對照表怎麼處置？——**同意 (b) 凍結，但必須用 🔴-B1 的命名**

支持凍結的理由提案講對了（庫內唯一的家內同口徑橫向表）。但要配三件事：(i) 節名不得含「不回訪」；(ii) L98 的跨家格照 🟡-B5 處理；(iii) `## 家內同口徑對照` 要能被 `table_census` 認出有機制——E 條那行須逐字含節名與「到期」二字。

此點與第 1 點確實可獨立裁決 ✅。

### 3. 要不要現在補字元上限的機械閘？——**同意 (a)，本波一併做，但驗紅不可省**

理由成立且提案的存量數字我重算**完全吻合**（194／1141），`check_reader_language.py` 的 baseline 模式我讀過原始碼確認（`split_hits()` L284–289、`main()` L327 只對 `new` 回 exit 1，legacy 印 WARN 摘要）——這是可複製的真模式，不是宣稱。

唯一補充：`REVIEW-PRINCIPLES` 第 2 條的驗紅要**兩次**——(a) 塞一條 250 字元條列確認 exit≠0；(b) 把該條加進 baseline 後確認 exit＝0。只驗前者證明得了「會紅」，證明不了「baseline 真的放行」，而後者才是這支腳本敢上線的前提。
