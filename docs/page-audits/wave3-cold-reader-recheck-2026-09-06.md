## Q1　09-14 週配額改版，我 Max 5x 是變多還是變少？衝擊多大？有哪些選項？

**⚠️ 半拿到（2 跳）。** 前兩問完全拿到，第三問缺一半。

變少：pricing L36「**09-14 起你的週配額變成現在的 83%**：+50% 加成 09-13 23:59 PT 到期……接手的是永久 +25%……換算後相對現在少約 17%」。衝擊量化得很好，L46 給了我唯一能自己對號的方法：「09-14 之後做同樣份量的工作，`Settings > Usage` 的用量百分比會比現在多跑約 **20%**（1 ÷ 0.83）」。這句是全站對我最有用的一句。

選項只給到一半。L137「評估調整用量節奏或方案層級」是空話；緊接著 L46 就寫「**升到 Max 20x 能多拿多少，官方未載明，本庫不推估**」——那我要怎麼評估方案層級？誠實但把我留在原地。真正可執行的兩條反而散在別處且沒被收攏成「選項」：開 usage credits 續命（L66，但同段警告它會讓上限失效）、把常規工作路由到 Sonnet 5（要走到 model-comparison L125 才看得到）。

## Q2　API 跑 Fable 5.1 一小時／一個月多少？跟訂閱差幾倍？

**✅ 拿到（2 跳）。** pricing L88–98「一小時／一個月大概多少」是全站設計最好的一節：口徑寫在表上（L90「一小時 agent 工作 ＝ 50k 輸入 ＋ 15k 輸出 token ＋ 一個 session-hour，取自官方 Managed Agents 算例」），第四欄直接標「這個數字哪來的」，官方算例與推算分得清清楚楚。Fable 5.1 約 $1.33／小時、約 $117／月。我拿計算機驗了三列，$10/$50 牌價代入 50k/15k 加 $0.08 session-hour，三列全部對得上。

「差幾倍」它拒絕直接回答，理由給得站得住：L98「Max 5x 的 $100 買的是週配額……**兩種貨幣不可直接相除**」。要倍數就得跳到 enterprise-cost-management，那邊有 40–44 倍（見特別提問 5 的保留）。

## Q4　公司要控成本，官方有什麼、別人怎麼做、先看哪個？

**⚠️ 半拿到（2 跳）。** enterprise-cost-management L57–60 的缺口表列出官方 Spend Controls 對應：組織層上限＋75%／90% 警示、部門層報表、每人限額，唯一未解是混合計費管理。別人怎麼做也很足：Spotify Portal 路由降 90%、Uber 四個月燒光年預算、Thomson Reuters 縮減依賴。

### 4. 內部用語外洩（原句＋行號）

1. pricing L205「本表上限 6 列。」——讀者不需要知道表的容量。
2. pricing L205「**這五值不看留言數，只看官方有沒有給出答案**——**示範列**中 #79337……」——「示範列」讓我以為那筆事故是假資料，其實是真的。
3. pricing L218「下方「事故與爭議」事件流每個 `####` 小標已補一個狀態符號。」——`####` 是 markdown 語法，網站上我看不到它。
4. pricing L134「一條一規則，附來源日期；失效規則移除，計費事故與爭議見下方……」——前半是寫給編輯的體例。
5. pricing L90「**口徑固定**：一小時 agent 工作 ＝……」——「口徑」是會計／內部詞，寫「本表假設」我立刻懂。
6. pricing L46／L98「**本庫不推估**」「本頁不重複列」——「本庫」是誰？我以為在讀一個網站不是一個資料庫。
7. enterprise L64「**判讀原則：** 一缺口一列，狀態四選一（✅／🧪 部分回應／❌／⏸ 需求已消失）；標 🧪 逾 90 天無新細節者，備注須寫「官方已 N 天無進一步說明」」——整段是給維護者的作業規範，出現在正文。
8. enterprise L42「現況（2026-09-06 **重算**）」——重算是後台動作。
9. enterprise L81「**🧰 現在就能下的解**」——🧰 沒有圖例，我不知道它跟旁邊的內容有何不同。
10. model-comparison L99「### token 成本：兩個方向相反的實測結果（**並陳，不選邊**）」與 L119「Opus 4.6（**非可選項，換代前基準線**）」——編輯政策與表格角色說明，混在標題與儲存格裡。

### 5. 「這是在騙我 / 這數字哪來的」

**最嚴重一筆：enterprise-cost-management L46。** 摘要指標表寫「已量化的訂閱與 API 價差 ｜ **三個獨立方法論指向 40–44 倍**」。往下看三個來源：modelplane.ai 44 倍（HN 19 分）、Quesma 40 倍（HN 31 分）、cookbook-meter——但 cookbook-meter 根本沒有給倍數，它給的是絕對金額 $5,868，而且該頁自己在 L116 寫「**HN score 僅 2，留言中的兩個具體數字屬個別使用者自述，未經第三方驗證，不可視為母體代表性樣本**」。一個不產出倍數、作者自述、HN 2 分的來源，被摘要表升格成「第三個獨立方法論」，還進了一個沒有任何保留字的指標格。**表上的宣稱比它自己的證據段強。** 這是我在這五頁裡唯一覺得被推銷的地方。

**次一筆：enterprise L62 的位置。** 「非 Enterprise 組織的四項缺口實質全部仍為 ❌」寫在表下，而表裡是兩個 ✅。快掃的人只會看到 ✅。這不是造假，是排版讓事實輸給印象。

**標「推算」「官方算例」的數字，反而全部經得起查。** pricing L90–98 三列我逐筆驗算（50k×牌價＋15k×牌價＋$0.08），與月度、$100 換算的小時數全部自洽；假設寫在表上方，來源欄逐列標明哪列是官方逐字、哪列是推算。model-comparison L114–121 的六列以 130K/6.5K 代入牌價也全部對得上，且 L136 明寫「上表為 +30% 概值下的換算，非實測……遷移前應以 `count_tokens` 對自己真實的 prompt 量一次」。這兩處是我看過最誠實的推算揭露，沒有可挑之處。

**⚠️ 疑似注入：** 無。（pricing L134、enterprise L64 雖是祈使句，但明顯是誤留的編輯體例，不是針對我的指令。）

### 6. 我最想改的三件事

1. **enterprise-cost-management 的摘要指標表要降級**：「三個獨立方法論指向 40–44 倍」改成「兩個定價分析指向 40–44 倍，第三個工具化換算方向一致但為單人自述」；同時把 L62 的「非 Enterprise 全部仍為 ❌」提到表的上方，否則三個 ✅ 會誤導所有非 Enterprise 讀者。
2. **兩張成本表加互斥的抬頭句**：pricing L88 節標題下第一行就寫「本表答『我跑一小時多少錢』；換模型跑同一件工作差多少見 model-comparison」，model-comparison L95 對稱處理。現在分界句在表下，讀者先撞到數字才撞到分界。
3. **Q1 的「選項」要收成一格**：pricing「現況」段末補一個三行清單——開 usage credits（附上限失效警告）／把常規工作路由到 Sonnet 5（連 model-comparison）／升 Max 20x（官方未載明增量，說明無法評估）。現在這三條散在三個地方，而「評估調整用量節奏或方案層級」這句等於沒說。
