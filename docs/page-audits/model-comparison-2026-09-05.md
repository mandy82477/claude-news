## 4. 鄰居分工（三對）＋「誰比較強」環的斷點

| 對 | 一句分工原則 | 現況違反處 |
|---|---|---|
| MC ↔ leaderboard | **家內「我該用哪個」＝MC；跨家「誰最強」＝leaderboard，一題一家、不互留副本** | MC L110–125 留著跨家實測（L116 Fable 5 vs GPT-5.6 Sol、L125 三家並排），與 MC 自己 L193「本頁不記快照分數」矛盾；leaderboard L42 只寫「家內見 MC」，沒寫「跨家到我為止」 |
| MC ↔ competitor-landscape | **模型的能力與代價＝MC；廠商的動作與衝擊＝CL** | 大致乾淨（CL 定稿已凍結跑分）。殘留：CL 蒐集邊界句 L28 把讀者導向「MC 的外部評測榜單節」——那是**轉介節不是答案頁**，且為頁級連結，讀者落在 MC 頂端要自己捲 190 行 |
| leaderboard ↔ CL | **榜單排名＝leaderboard；宣稱可不可信與衝擊＝CL** | **硬衝突**：CL L149–150（查證快照，凍結不回訪）與 L85 雷達列均寫「最新排名見 leaderboard」，但那是 **Claude Code vs Codex 的工具／harness 層**比較，leaderboard 18 列**沒有任何工具層列** |

**環的斷點判定：斷點在 model-task-leaderboard，不在另外兩頁。**

- MC L193 與 CL L149 都**正確地**把跨家轉出去了，兩頁都指向同一個終點——所以環其實不是環，是**兩條指向同一個接不住的終點的箭頭**。
- leaderboard 接不住的原因有三，缺一不可：(a) 只有模型層、無工具層（a1 問的 Codex 是工具）；(b) 表的軸是「你想做的任務」，答不了「A vs B」的問法；(c) index 開發實務入口表 L24–33 **零路由**指向它，入邊 5 筆（4 筆 CL、1 筆 MC L169）全在他頁內文深處——**只有已經被踢過一次的人才進得去**。
- 因此唯一落點原則寫成：**跨家（含跨廠商工具）誰強＝leaderboard；Claude 家內選型與實付＝MC；別人衝著我做了什麼、多大衝擊＝CL。** 三頁各留一句出口，不留副本。
