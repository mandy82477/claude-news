> 第 5 段：「明價」說過頭、Code Review 限 Team／Enterprise 補上、Q3 一句講完；「Length has a cost」「round seven」現行官方查無→拿掉引號；`/simplify` 改名史查無→拿掉；「官方沒標的坑」官方已明寫（verified 表 L421、L427、L434–440）

````markdown
**官方有四個 review 入口，誰能用、怎麼付錢各不相同；另有兩個邊寫邊掃的安全外掛。**

`/code-review` 是 Claude Code 內建指令，不是外掛；`/review` 是它的別名（v2.1.223 前 `/review` 是另一個指令）。

| 入口 | 什麼時候跑 | 誰能用、怎麼付錢 |
|---|---|---|
| `/code-review` | 本機背景 subagent，手動 | 任何方案；算一般用量 |

| `/security-review` | 本機，手動 | 一般用量 |

**一次多少錢，一句話**：本機兩個入口算你平常的用量；ultrareview 用完 3 次免費後每次約 $5–25；GitHub 上的 Code Review 沒有單價——先設月上限，挑幾個 repo 用 Once 或 Manual 試跑，看後台平均單次成本再乘每月 PR 數（新 repo 預設每次 push 都審，最貴）。對照用的整體參考值：Claude Code 每位開發者每個活躍日約 $13、每月 $150–250。估法四步與封頂細節見 [[topics/enterprise-cost-management#LLM code review 一次多少錢：官方給的是估法，不是單價]]。

**官方給的成本收斂旋鈕**：觸發模式選 Manual 或 Once；`REVIEW.md` 設 skip rules 與重審收斂；降 effort（`low`／`medium` 只報最有信心的，是少誤報而非少覆蓋）；Code Review 專屬月上限；per-repo 均價監看；security-guidance 分層關閉。本機 `/code-review` 自 v2.1.288 起可加 `--max-findings <n>`（或 `all`、`default`）限制回報條數，見 [[entities/claude-code]]。
````
