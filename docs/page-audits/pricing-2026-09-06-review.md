### 🔴-2 「打平點」那句與同一頁的方案表互相矛盾

## 🟡 應修（8）

1. **「一小時／一個月」表仍會被 `table_census` 判成「機制：無」**。§5 第 4 點的新列寫「同步重算」，而 `table_census.py` L26 的 `MECH_RE` 只認 `淘汰|移除|保留|封存|覆寫|蒸餾|汰除|到期|清理`。**修法**：該列動作欄改為「**整表覆寫重算** `## 一小時／一個月大概多少` 三列；口徑固定為官方 Managed Agents 算例的 token 量，推算列須標「推算」」。順手把 L79 改名那列寫成「**覆寫** `## 我的方案現在有什麼` 對應列」（該表現況機制欄同樣是「無」）。

2. **換算法「乘 0.83」的可執行性沒被驗證**。V2 只說官方「在 `Settings > Usage` 顯示你自己的數字」，沒說那是絕對配額還是已用百分比；若是百分比，「乘 0.83」對讀者是無意義的操作。**修法**（§2.1 換算法末句替換）：「**你會看到的變化**：09-14 之後做同樣份量的工作，`Settings > Usage` 的用量百分比會比現在多跑約 **20%**（1 ÷ 0.83）——官方不公布配額絕對量，這是唯一能自己對號的方式。**升到 Max 20x 能多拿多少，官方未載明，本庫不推估**。」

3. **$0.08 是 Managed Agents（beta）的費用，不是「跑 API 一小時」的費用**。不講清楚，讀者會以為呼叫 API 被按小時收錢。**修法**：口徑 blockquote 末加一句「`$0.08／session-hour` 只在透過 **Managed Agents**（beta，須 beta header）執行時發生；直接呼叫 API 沒有按小時計費，該列扣掉 $0.08 即可。」

4. **index 只給了列文字，沒說貼哪張表，而那張表的宣告句會排斥它**。首屏可見的是 `## 💻 開發實務入口`（L27–38，兩欄），其前言明寫「只放**開發實務強相關**的頁面（怎麼做、裝什麼、選什麼）」。**修法**：(a) 前言改為「只放**開發實務強相關**的頁面（怎麼做、裝什麼、選什麼、**要花多少**）」；(b) 在「我卡住了」那列之後插入提案 §5-8 的兩欄列。另外 **index L50 的 pricing 摘要鉤子仍是 07-13 印度盧比舊事**，本波未列入——一併改為：`訂閱方案、牌價與乘數、計費規則現況；09-14 起週配額換軌、還在發生的計費事故`。

5. **四個新禁詞漏了冷讀者真正引用的那一個**。冷讀者第 4 節第 3 條點名的是「**已掃日報至**」，總帳校準欄也明寫這一類；提案的四詞（未收錄／收錄標準／候選症狀／低度信號）不含它。實測全庫（排除 `log.md`）**43 行**，一次加進去等於一次大規模基線重建。**修法**：本波照裁決加四詞即可，但在 `docs/page-audits/ledger.md` 第 3 波列補一行待辦：「讀者語言閘缺詞『已掃日報至』（43 行存量），留待下次全庫基線重建時併入」——不寫下來，下波會再漏一次。
