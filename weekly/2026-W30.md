# 本週深挖 · 2026-W30（07-20 ～ 07-26）

> **本週一句話**：開源競品把成本壓到三分之一，Anthropic 用「半價旗艦」回應——而你手上真正該調的旋鈕，可能根本不是換模型。

---

## 一、頭條敘事：半價旗艦是回應，不是慶祝

這一週要從價格看起。週一 The New Stack 實測給出一個難以忽視的數字：Moonshot 的 Kimi K3 與 Anthropic 旗艦 Fable 5 效果相當，成本只要三分之一，代價是慢四倍；同日阿里巴巴 Qwen3.8 被多家媒體報導為「僅次於 Fable 5」。對一個靠能力差距收 $10/$50 的旗艦來說，這是差異化被侵蝕的訊號。

週六 Anthropic 回應：Opus 5 發布，官方稱編碼與知識工作評測逼近 Fable 5，定價 $5/$25 恰為一半，並直接成為 Max 新預設、Pro 最強選項。兩件事並排看，「半價旗艦」與其說是升級，不如說是主動把價格帶往下壓一階——當對手用三分之一成本逼近，守住能力差距不如先守住性價比曲線。

資本面同時在補彈藥：AMD 宣布投資最高 50 億美元並簽晶片協議、Meta 傳出評估最高 100 億美元運算合作、Alphabet 持股市值躍升至約 1,240 億美元，懸置已久的 15 億美元著作權和解案也由聯邦法官核准落地。算力、資金、法律風險三個變數在同一週各收斂一格。

最耐人尋味的是政治面：白宮指控 Moonshot 從 Anthropic「蒸餾」竊取技術，同批報導裡矽谷業界卻聯合反對 Anthropic 的對中限制立場。同一件事實——差距正在縮小——商業上叫「開源用三分之一成本追上來」，政治上叫「技術被竊取」，只是誰付帳單還沒共識。

## 二、技術討論與深挖

### 本週版本：可以升，但先確認兩件事

本週釋出 v2.1.216 → v2.1.220，其中只有 **v2.1.218** 有實質功能異動（`/code-review` 改為背景 subagent 執行，審查不再佔用對話內容）；v2.1.220 為純 bug fix，官方未列具體項目。

**升版前先確認兩個無過渡期的 breaking change 是否影響你**：`/fork` 自 v2.1.212 起不再於同一 session 內啟動子 agent（依賴舊行為的 skill／hook 須改用 `/subtask`）；`/verify` 與 `/code-review` 自 v2.1.215 起不再自動觸發，須手動呼叫——**如果你的流程把「Claude 會自己審」當成隱性保護，升級後那層保護就沒了**。另外重度使用 Cowork 者近期避免處理大型檔案：Edit/Write 因緩衝區上限會靜默截斷檔案（#53940），任何檔案大小皆可重現，目前無官方修復時程。

### 討論綜述

- **成本槓桿成為競爭主軸**：Kimi K3 以三分之一成本、四倍延遲換到相當效果（The New Stack 實測）。對照組是「便宜但慢」，這在互動式編碼場景可能不成立，但在批次任務成立。
- **Anthropic Status 事件密集**：本週日報累計出現 31 個服務事件連結，涵蓋 Opus 4.1／4.5、Fable 5、Haiku 4.5、多模型錯誤率上升與服務中斷，多數在數十分鐘內修復。單看任一天像雜訊，連起來看是一條值得盯的穩定性曲線。
- **帳務類回報成為 issue 主體**：一則反映 Max 方案工作階段限制自 3 月起異常快速耗盡的回報累積逾 800 則留言，為近期單一 issue 最大宗；同期另有 Fable 5 在 Max 方案被誤判需購買 credits 的 bug（官方證實為誤判，建議重啟）。
- **Boris Cherny 的評價軸線換了**：他公開表示比起評測分數，更看重 Opus 5 是「目前最難被提示注入攻破」的模型——這是他首次跳出能力／效率框架談安全性。
- **社群工具持續湧現**：單週 Show HN 出現十餘款以 Claude Code 為基礎的工具（語音控制、記憶稽核、瀏覽器自動化、桌面替代方案），另有純 HTML 簡報工具 Bento 拿到 877 分。

### 深挖：effort 參數——換模型之前，你該先動的那個旋鈕

官方在《Choosing a model》裡寫了一句很容易被跳過的話：**調整 effort 通常比換模型更有效**。本週陣容剛換代，正好是理解這句話的時機。

**基礎快講**：`effort` 是請求層級參數，五級 `low / medium / high / xhigh / max`，API 與 Claude Code 預設 `high`（設 `high` 等同不設）。它和 `thinking` 不同——`thinking` 控制「要不要思考」，`effort` 控制「整個回應花多少 token」，且作用於**所有 token**：文字、思考、以及**工具呼叫本身**。

**機制層**：正因為管到工具呼叫，低 effort 不只是「話變少」，而是**合併操作成更少的工具呼叫、跳過前言直接動手、完成後只給簡短確認**；高 effort 則會先講計畫、多跑幾輪工具、給詳細摘要。對 agentic 工作流來說，這調的是 agent 的探索深度，不是輸出長度。官方也明講 effort 是行為訊號而非硬性 token 預算——低 effort 遇到夠難的問題還是會思考，只是想得少。

**三個會咬人的地方**：

1. **改 effort 會打掉 prompt cache。** effort 會改變 rendered prompt，長 session 中途換 effort，先前快取前綴全部失效。正確做法是跨工作負載變動，而不是在依賴快取的對話中途變動——一開始選定就別動。
2. **`xhigh` / `max` 下 Opus 5 不能關 thinking**（送 `thinking: {"type": "disabled"}` 直接回 400），且要把 `max_tokens` 開大，官方建議從 64k 起調，否則模型沒空間跨 subagent 展開。
3. **不要沿用舊模型的 effort 設定。** Opus 5 官方指引是「從預設 `high` 起手」，Opus 4.7／4.8 卻是「編碼與 agentic 從 `xhigh` 起手」——**兩代起手點不同**，照抄會系統性偏高或偏低，官方要求換模型後重跑一次 effort sweep。

**怎麼用**：Opus 5 日常編碼維持預設 `high`，最吃重的長時 agentic 才上 `xhigh`；成本敏感的批量與 subagent 大膽往 `low`／`medium` 走——官方對 Fable 5 甚至說低 effort 常勝過前代模型的 `xhigh`。**先在 effort 這條軸找到工作點，再考慮是不是真要換模型。**
