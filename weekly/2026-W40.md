## 一、頭條敘事：用 Homebrew 或 apt 裝 Claude Code 的人，版本可能比你以為的舊

原生安裝會自動更新到最新版，但照官方文件用 Homebrew、apt、dnf、apk 裝的預設跟的是晚一週的穩定版，而且不會自己更新。打一次 `claude --version`，和本週版本段的 2.1.289 比一比。另一件便宜的事：用 Pro 或 Max 訂閱的人檢查 shell 裡有沒有殘留 `ANTHROPIC_API_KEY`。本期兩篇專文，開發實務講 Claude Code 換成 Sonnet 5.5 後長任務為什麼會停在半路，財經講一份外流文件裡哪些數字是新的，各約兩分鐘。

### 深挖：本期兩篇記者專文

開發實務講 Sonnet 5.5 在哪些 effort 設定下會停在半路、或沒驗就說做完；財經講一份外流文件裡哪些數字是新的。

#### 開發實務｜Claude Code 的 Sonnet 換成 5.5，長任務可能做到一半就停下來問你

**這週換了什麼？** 09-28 起 `sonnet` 指向 Sonnet 5.5，Claude Code v2.1.284 也把 API 端的預設 Sonnet 換成它。容易漏看的是 effort：API 上預設是 high，但在 Claude Code 裡 Sonnet 5.5 預設是 medium。[Claude Code 模型設定文件](https://code.claude.com/docs/en/model-config)（10-04 取得）

**我會不會中？** 官方提示指南列了三種情況。effort 在 low 或 medium 跑長的 agent 任務，它比較容易做到一半停下來確認計畫或發問，無人值守就卡住。effort 在 low 時，它有時沒跑測試或 build 就回報改好了。自己寫 agent 外殼的人，若把使用者中途補的話塞進 `tool_result`，它會當成冒充使用者的注入，忽略或要你確認。[Sonnet 5.5 提示指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-sonnet-5-5)（10-04 取得）

**你以為有效、其實沒有的？** 第一是叫它「少想一點」：medium 以上它幾乎每則回覆都先想一下，用提示要它少想並不可靠，要直接降 effort。第二是沿用 Sonnet 5 的 effort 設定：級距重新校準過，同名等級想的量不一樣。反方向也有坑：開到 max，它做完會自己多跑幾輪審查、另派審查子代理；官方加一段「做完就停」後，成本少約三分之一、品質不變。

**現在能做什麼？** 要它無人值守跑完的，啟動時加 `--effort high`，或設 `CLAUDE_CODE_EFFORT_LEVEL=high`；也可以照指南加「做到全部完成為止」那段，但 session 會跑更久、更花錢。非用 low 不可的，加指南那段「改到可執行的程式就跑真實檢查」，官方測得幾乎不再跳過、成本只略增。直接呼叫 API 的，遷移指南列的變更多半直接回 400 錯誤，唯一不報錯的是工具呼叫之間的文字改放進 thinking 區塊，只顯示文字的介面會整段變安靜（推論：這和媒體說的「一種沒有錯誤訊息」吻合）。[遷移指南](https://platform.claude.com/docs/en/models/sonnet-5-5/migration-guide)（10-04 取得）

#### 財經｜招股書外流的新數字，與 Broadcom 那兩筆其實是同一筆

**這週哪些是新數字？** 招股書內文外流，Reuters 09-28 獨家，TechCrunch 同日轉述：2025 年營收約 46 億美元（年營收，較前年成長 12 倍）、營業虧損逾 80 億美元（營業虧損）、未來幾年的雲端與算力支出承諾 5,180 億美元（承諾額，多數不論用不用都要付）。這批數字才是這週真正新的。最該記住的是比例：未來要付的算力錢，是去年營收的一百多倍。[TechCrunch 報導](https://techcrunch.com/2026/09/28/anthropics-prospectus-details-losses-growth-and-yes-a-warning-that-its-ai-could-end-humanity/)（10-04 取得）

**營收近半來自 Amazon、Google，意思是什麼？** calcalistech 09-30 引 Reuters 分析：2025 年有 47% 的營收是透過這兩家的雲端市集賣出，2023 年只有 11%。這是賣貨的通路，不是買家，不能讀成「兩家是大客戶」。[calcalistech 報導](https://www.calcalistech.com/ctechnews/article/r8sh14ux4)（10-04 取得）

**看起來像進度的其實是什麼？** Broadcom 的 420 億與 600 億。兩天內先後見報，看起來像金額變大，其實是同一筆交易的兩端。420 億美元（貸款額度上限）是招股書揭露的：Broadcom 同意借給 Anthropic 的上限，債可轉成 Anthropic 股份。600 億美元（籌資總額）是 Bloomberg 10-02 報的 Broadcom 銀行團向市場籌的債務，其中 420 億是 A 級優先擔保段。借出端和籌資端各有一個數字，所以兩個數字不衝突。剩下的 180 億美元（次順位段）據二手報導由 Blackstone 領頭，一手報導未見。[Yahoo Finance 轉載 Bloomberg](https://finance.yahoo.com/technology/ai/articles/broadcom-starts-amassing-60-bln-050839573.html)（10-04 取得）

**還沒定論的：** 公開版 S-1 還沒出，以上都是轉述。另有二手整理稱淨虧損 420 億美元（淨虧損），與營業虧損差太多又沒人說明原因，本文不採用。

**下週看什麼：** 公開版 S-1 有沒有遞交，以及裡面的營收、虧損與這週外流版對不對得上。

**下次怎麼認：** 看到數字變大，先問兩個數字是不是同一筆交易的不同層；看到「透過某某賣出」，先問某某是通路還是買家。
