# CLAUDE NEWS 週報 · 2026-W38

## 一、頭條敘事：你的外掛會自己更新，而修補三個月前就悄悄裝好了

09-18 資安團隊 AIR 公開一個代號 Plugin4Shell 的漏洞，同時打中 Claude Code、Codex、GitHub Copilot 與 Gemini CLI 四款編碼 agent（[Help Net Security](https://www.helpnetsecurity.com/2026/09/18/plugin4shell-ai-coding-agents-vulnerability/)）。本刊把這條線稱為**外掛零點擊**。它不需要你點任何東西：外掛在背景自動更新，攻擊者只要控制外掛的 repo，就能讓一次例行更新執行他的程式碼，而外掛拿到的權限和你本人一樣大——你的原始碼、雲端憑證、SSH key、內部 repo 都在射程內。

Anthropic 修掉它的版本是 v2.1.179，發布於 2026-06-16，比公開揭露早了三個月。那版的發行說明寫的是串流中斷、spinner 卡住、滑鼠滾輪（[GitHub release](https://github.com/anthropics/claude-code/releases/tag/v2.1.179)）——沒有一個字提到安全性。這是協同揭露的標準做法，但對使用者的實際效果是：你這三個月一直安全，而你不知道自己曾經不安全過。

這件事之所以是本週頭條，在於它剛好戳中官方本週推進的方向。Cowork 於 09-17 併入單一 Claude 介面，同時推出 Claude Docs 與 Claude Slides 兩項 beta（[官方](https://claude.com/blog/cowork-is-now-claude)）；同日更新的官方文件載明，以 claude.ai 帳號登入的終端機 session 會載入該帳號啟用的 skills 與 plugins，雲端 session 讀帳號設定、本機 session 讀 `~/.claude/skills/`（[官方文件](https://code.claude.com/docs/en/desktop.md)）。隔天 Claude Code Projects 改版開 Beta，讓多個雲端 agent session 跨裝置持續跑長任務（[The Verge](https://news.google.com/rss/articles/CBMikwFBVV95cUxNZUxTNjFoWnlrU0x5ektWaF93WEJ4U0RxbTBRMV9MVVlmQ19pS3ZnYnBsV1lLVkN4YXI4UmlrcktOMmRmRkV1cTFSUk56SkJWaWgwT2dEZ1FTeHdhUlUyVndiWWxvZ0VQZTVueE1PVWtya2ZiZ2dnUlRUUHVVbmotaUNqMExwQ1JCdWZQQWpoanRsQWc?oc=5)）。本刊把這條線稱為雲端接手。

兩條線是同一個假設的兩面。雲端接手把「你不必在場」變成產品方向——工作在別的機器上繼續、設定跟著帳號走、外掛自動更新。外掛零點擊示範了這個假設失手時會發生什麼：自動化本身就是攻擊面，因為零點擊的「零」指的正是你沒有機會攔下來。四家廠商裡只有兩家修好了，Copilot 至今沒有修補、Gemini CLI 被 Google 直接停止維護。

你該做的事：今天跑一次 `claude --version`，只要不低於 2.1.179 就已經修好，不必做別的（本週的 v2.1.276 順帶修了另一個迴歸，用 proxy 或 gateway 的人本來就該升）。真正要做的是另一件——打開你裝過的外掛清單，確認每一個的來源 repo 你都還信得過。這個漏洞修的是 agent 驗不驗證 commit，不是外掛作者會不會變壞。

### 深挖：一個 40 個字元的分支名字，怎麼讓「釘住 commit」失效

**為什麼是這週**：外掛零點擊本週見報，而它示範的不是 AI 的問題，是一條你每天在 CI 裡也會踩到的 git 行為。

**基礎快講**

**SHA 釘選**（SHA pinning）是供應鏈防護的標準做法：不寫「拿這個 repo 的最新版」，改寫「拿這個 repo 的這一個 commit」。SHA 是內容雜湊，內容變了雜湊就變，所以釘住 SHA 理論上等於釘住一份確切的程式碼；外掛市集就是這樣記錄版本的。

要和它區分的是**驗證**。釘選是「我要求拿到 X」，驗證是「我確認拿到的真的是 X」——聽起來像同一件事，實際是兩個步驟。Plugin4Shell 的全部內容就是：四款 agent 都做了第一步，都沒做第二步（[AIR Security](https://www.air.security/blog-posts/plugin4shell)，2026-09-18 取得）。

**機制層**

為什麼「checkout 了」不等於「拿到了」？因為 40 個十六進位字元既可以是 commit 物件的 ID，也可以是合法的分支名稱，而兩者同名時，**git 優先解析成分支**。

agent 安裝外掛時跑的是這兩行：

```
git clone <外掛 repo> ./
git checkout aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
```

攻擊者控制那個 repo，於是建一個**名字就是那 40 字元 SHA** 的分支並設為預設。checkout 執行時，git 簽出的是分支上的內容，不是那個 commit。外掛裝好了，釘選看起來完好無損，跑起來的卻是攻擊者的程式碼。（Gemini CLI 的變體改劫持 `FETCH_HEAD` 這個名字，原理相同。）

正確的修法只有一句話——簽出之後跑 `git rev-parse HEAD`，拿實際落地的 commit 和釘選的 SHA 比對，對不上就中止。Anthropic 在 v2.1.179 補上，OpenAI 在 Codex 0.146.0 補上；GitHub 以「託管 repo 有命名限制、攻擊面較小」為由不修 Copilot。

**四個陷阱**

1. **「零點擊」的零，來自自動更新，不是來自漏洞本身。** Claude Code 與 Codex 預設在背景更新已安裝的外掛。沒有這個預設，這漏洞要你手動重裝一次才會中；有了它，你什麼都不用做。
2. **釘住 SHA 不等於信任 repo。** 攻擊前提是攻擊者控制了外掛的 repo——帳號被盜、維護權轉手，或作者本來就有惡意。SHA 釘選防的是「內容在你不知情時被換掉」，防不了「repo 的主人換了人」。修好版本之後該做的是清點來源，不是再多釘一層。
3. **修補已出貨不代表你被通知過。** v2.1.179 的發行說明列的是串流、spinner、滾輪，隻字未提安全性。協同揭露期間這樣寫是業界常規，但如果你用「這版修了什麼」決定要不要升級，你會系統性低估升級的價值。
4. **外掛的權限就是你的權限。** 研究報告點名的射程包括本機原始碼、雲端憑證、SSH key、內部 repo 與正式環境密鑰——外掛不跑在沙箱裡，它以你的身分執行。

**怎麼用**

決策規則兩條：**升級只看版本號，不看發行說明**——跑 `claude --version`，低於 2.1.179 就升。**外掛看來源不看數量**——把裝過的外掛逐一對回它的 repo，維護者是不是你認得的人、repo 還活著嗎；答不出來的就移除。Copilot 與 Gemini CLI 沒有修補版可升，只剩後者這條路。
