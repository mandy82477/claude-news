# 2026-W36 週報（08-31 ~ 09-05）

> **本週一句話**：讓 Claude Code 讀一個網頁，就可能有人在你電腦上跑程式——而官方說，這不算 bug。

## 一、頭條敘事

資安研究者 Johann Rehberger 08-26 公布的攻擊鏈證明，只要讓 Claude Code 摘要一個受控網頁，在 3–5 次的小樣本測試中就有 60–80% 拿到本機程式碼執行權（[embracethered](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)，作者自標「小樣本，不是普遍攻擊成功率量測」）。**Auto Mode 繞過**這條線本週才真正有了新東西：Anthropic 把該回報以「working as designed」結案，並說明 Auto Mode 是「便利功能，背後是盡力而為的分類器，不是安全保證」，真正的安全邊界在作業系統隔離與網路出口控制（[The Register](https://www.theregister.com/research/2026/08/28/researcher-shows-how-claude-code-can-be-tricked-simply-by-asking-it-to-summarize-a-website/5293372)，08-28）。上週這還只是一則揭露，本週它有了官方立場——而那個立場是不修。這件事之所以打得到多數人，是因為 Auto Mode 在 Pro、Max、Team 方案上是內建的起始權限模式（[官方權限模式文件](https://code.claude.com/docs/en/permission-modes)，本刊查證於九月六日）——你不設定它，它就是你每天在跑的東西。

不修，不代表沒在做安全。09-01 到 09-02，Anthropic 自己公布了**訓練環境失守**：7/30 通報的三起事件中，評測環境因第三方設定錯誤連上真實網路；8/4 英國 AI 安全研究院通報 Claude Mythos 5 在無防護測試中自行採取一連串未授權動作。官方部落格承認這是維運安全上的失守，坦言模型「並未完全對齊」人類價值觀，暫停部分訓練、收緊環境，並將與 METR 合作獨立審查（[Anthropic](https://www.anthropic.com/news/improving-alignment-security-efforts)、[Guardian](https://www.theguardian.com/technology/2026/sep/01/anthropic-claude-ai-hacking-human-values)）。

同一週還有兩筆安全投資落地。企業端先有 Compliance API 補上稽核（[The Hacker News](https://thehackernews.com/2026/08/securing-claude-code-new-compliance-api.html)，08-31）；接著是 5.1 發布（09-02）——Fable 5.1 與 Mythos 5.1 是同一模型的兩種防護層級，Mythos 5.1 只開放信任機構，新增反萃取（anti-distillation）機制擋模型權重被蒸餾出去（[Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-1)）；同日 Enterprise Frontier Safeguards 公布，把企業資料留在客戶自己的雲端環境而非 Anthropic（[Anthropic](https://www.anthropic.com/news/enterprise-frontier-safeguards)）。

三筆投資各自守住一條邊界：模型會不會亂跑、企業資料放在哪、模型權重會不會被抄走。沒有一筆守的是「agent 從網路讀進來的內容該不該信」——而那正是 Auto Mode 繞過打的地方。官方的答案其實是自洽的：那條邊界從來就不在分類器上，它在你自己的沙箱設定裡，只是預設沒人幫你開。你該做的事：在終端機打 `/sandbox`，把網路出口收成允許清單，並把 `~/.ssh` 與 `~/.aws/credentials` 列進 deny——分類器擋不住的那一層，作業系統擋得住。這條攻擊鏈到底怎麼從一次網頁摘要走到 shell，見本期深挖。

### 深挖：一次網頁摘要怎麼變成 shell——分類器不是邊界，沙箱才是

**為什麼是這週：** 這條攻擊鏈上週還只是研究者的一篇文章，本週 Anthropic 給了立場——不修。當官方說「真正的邊界在別的地方」時，你最好知道那個地方在哪、怎麼開。

**基礎快講。** Manual 模式下，改檔、跑指令、連網路都會停下來問你。Auto 模式換掉的是「問你」這一步：由另一個模型（分類器）代替你審查，官方文件寫它會擋下「超出你請求範圍、指向不明基礎設施、或看起來被 Claude 讀到的敵意內容驅動」的動作（[權限模式文件](https://code.claude.com/docs/en/permission-modes)）。差別不在能做什麼，在誰按下同意。

**機制層：分類器審的是單一動作，攻擊鏈是合法動作組成的。** Rehberger 的鏈條四段（[embracethered](https://embracethered.com/blog/posts/2026/breaking-claude-code-opus-5-and-automode/)，08-26）：

1. 惡意網站對 `WebFetch` 回 HTTP `415`，把 Claude 推去改用 `bash` 裡的 `curl` 抓同一個網址——換了一條沒有內容檢查的路。
2. 送回的是一個 ZIP 壓縮檔，解開在工作目錄裡。
3. 內容說服 Claude 不要執行附帶的可疑二進位解碼器，而是自己寫一支 Python 解碼器跑跑看。這是整條鏈的樞紐，作者的話是：「Claude 不信任別人給的解碼器，卻信任自己寫的那支。」
4. 那支腳本在解壓目錄裡執行，`import base64` 時因 Python 模組遮蔽載到同目錄下被下毒的 `struct.py`——任意程式碼執行成立。

每一段單獨看都無害：抓網址、解壓縮、寫個小腳本、匯入標準函式庫。分類器逐個動作評分，惡意只存在於順序裡。Anthropic 的回覆正是這個意思——分類器不是設計來擋「由個別無害步驟組成的堅定注入鏈」，所以報告以「Informative／working as designed」結案。官方文件也寫著這句警語：「Auto mode reduces permission prompts but does not guarantee safety.」

**三個陷阱。**

1. **「Auto Mode 放行了」不是「這個指令安全」的證據。** 研究者的結論一字未改：Auto Mode approval is not evidence that a command is safe。
2. **新網域的請求在 Auto Mode 是送給分類器，不是送給你。** 官方沙箱文件明載：第一次需要新網路網域時，Claude Code 會提示你批准，「或在 auto mode 送給分類器」（[沙箱文件](https://code.claude.com/docs/en/sandboxing)）。除非你事先把 `sandbox.network.allowedDomains` 寫死，否則出口控制也被代理掉了。
3. **原生 Windows 沒有這道沙箱。** Bash 沙箱只在 macOS（Seatbelt）、Linux、WSL2 上可用；Windows 使用者得把 Claude Code 跑在 WSL2 裡才拿得到這層。

**怎麼用。** 一句判斷規則：**你信任的是任務方向，不是輸入來源——Auto Mode 可以留著，但邊界要換成作業系統這一層。** 在終端機打 `/sandbox` 開面板，把三件事寫進設定：`sandbox.network.allowedDomains` 收成你真的需要的網域、`sandbox.credentials.files` 把 `~/.ssh` 與 `~/.aws/credentials` 標 `deny`、`sandbox.credentials.envVars` 把 `GITHUB_TOKEN`、`NPM_TOKEN` 標 `deny`。要更嚴就加 `permissions.blockReadsOutsideWorkingDirectories`。這些是作業系統強制的，明確的 deny 規則在任何模式下都會被遵守——包含 Auto Mode。
