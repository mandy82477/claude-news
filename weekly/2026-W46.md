# CLAUDE NEWS 週報 · 2026-W46

## 一、頭條敘事：Claude Code 預設模型換成 Fable 5.2，價格降兩成，自己管對話歷史的 API 程式要改 4 處

11-09 Anthropic 發布 Claude Fable 5.2 與 Mythos 5.2；Claude Code 從 2.1.321 起把 Fable 5.2 設為預設模型（[官方公告](https://www.anthropic.com/claude-fable-and-mythos-5-2)）。Fable 是 Anthropic 開放給一般大眾的最高階模型系列，Mythos 是同代、對資安用途另有管控的版本。5.2 的牌價是每百萬 token 輸入 8 美元、輸出 40 美元，比 5.1 的 10／50 美元便宜兩成，context 仍是 1M。WebDev 排行榜上它也直接登頂（見本期數字）。

用 Claude Code、claude.ai 或 Agent SDK 的人，對話歷史由官方工具代管，不用改任何東西。要注意的是自己組 `messages` 陣列直接打 API 的程式。[官方遷移指南](https://platform.claude.com/docs/en/models/fable-5-2/migration-guide)列了 4 項破壞性變更：
- 中途改過 system prompt、工具清單或舊訊息，再把 thinking block（模型的思考片段）送回去，會直接回 400，重送同一請求也不會好；
- 5.1 讀不了 5.2 的 thinking block；
- 舊的 `computer_20251124` 工具在 Bedrock 以外都回 400；
- advisor 工具（beta）只接受 5.2 等級的模型當 advisor。

另有一項影響帳單的行為變化：effort（思考深度，共五檔）開到最高兩檔 `xhigh`、`max` 時，5.2 會自己開子 agent 審查自己的工作，官方提醒子 agent 可能佔 session 成本的一大塊。

要不要做什麼：自己組對話歷史的 API 程式，切到 `claude-fable-5-2` 前照指南跑一次 prefix check 測試；Claude Code 使用者不用動，但習慣開 `max` 的人，這週留意用量有沒有變快。

## 二、技術討論與深挖

### 本週官方出了什麼

- **Fable 5.2 與 Mythos 5.2**（11-09）：見頭條。
- **2.1.323：「Yes, and don't ask again」不再把密鑰寫進設定檔**（11-12）：權限提示選「之後不再問」時，看起來含密鑰、或會存進被 git 追蹤的 `.claude/settings.local.json` 的允許規則，改成只在本次 session 有效、不寫檔，`settings.local.json` 也改成全域忽略；同版加了預設關閉的實驗功能 Code Mode，讓 Claude 寫 JavaScript 來呼叫自己的工具（[v2.1.323](https://github.com/anthropics/claude-code/releases/tag/v2.1.323)）。npm 穩定版仍停在 2.1.311，沒有這項修補。
- **2.1.325：修補 zstd 壓縮回應的解碼安全問題**（11-14，[v2.1.325](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)）。照常升級即可。

這週最值得試的一項：已經在用 Claude Code 的人升到 2.1.323 以上，讓「之後不再問」不再把密鑰寫進設定檔。

升版：2.1.321 起預設模型換成 Fable 5.2。想留在 5.1 的人在 `/model` 指定 `claude-fable-5-1`。

### 討論綜述

- **「之後不再問」外洩的規模出來了**：資安業者 Apiiro 掃到 GitHub 公開倉庫裡有 1,122 個 `.claude/settings.local.json` 含真實密鑰，成因都是按了「Yes, and don't ask again」後把整個專案 commit 上去（[Reddit 討論](https://www.reddit.com/r/ClaudeCode/comments/1xw6ls3/yes_and_dont_ask_again_can_commit_your_api_key/)）。2.1.323 只防新的，已經推上去的不會消失。**直接做**：到自己的 repo 查有沒有 commit 過 `settings.local.json`，有的話換掉裡面的金鑰，並把它加進 `.gitignore`。
- **Cowork 雲端沙盒的網域設定不照你選的走**：有人回報 Cowork 雲端沙盒（Claude 在雲端替你執行任務的隔離環境）對外連線的允許清單會自動縮到約 5 個網域，即使帳號設定選了「All domains」，累積 35 則留言（[#93525](https://github.com/anthropics/claude-code/issues/93525)，11-14 快照）。**值得繼續看**：工作流要連自訂網域的人，先實測一次再把任務丟上雲端。
- **11-13 一天兩起錯誤升高**：官方狀態頁記錄 claude.ai、API 與 Claude Code 錯誤升高，其中一起已於 15:38 UTC 解決；Hacker News 上「Claude Code 掛了」的討論串同日出現（[官方狀態頁](https://status.claude.com/incidents/34wq7gxnxvvm)）。同週另一則老 issue「模型的工具呼叫無法解析」持續累積到 116 個讚，官方仍未附修復時程（[#63875](https://github.com/anthropics/claude-code/issues/63875)，11-13 快照）。**值得繼續看**：跑長任務的人留意中途被打斷時，重開 session 通常可繼續。

#### 社群｜2.1.323 悄悄拿掉 subagentStatusLine，同時跑多個子 agent 的人看不見各自燒了多少

**這週社群在吵什麼？**

有人發現升級後，自己用慣的設定默默失效了。Claude Code 11-12 發布的 2.1.323 移除了 `subagentStatusLine`。subagent（子 agent）是主 agent 派出去分頭做事的小幫手，這個設定讓使用者自己寫一段指令，決定每個小幫手在畫面上那一行顯示什麼。有人把這件事[開成 issue](https://github.com/anthropics/claude-code/issues/109446)，Hacker News 26 分（11-13 快照），issue 累積 32 個反應、8 則留言（11-15 快照）。

**少了這一行，到底少了什麼？**

據 issue 作者描述，這一行原本能同時看到每個小幫手的 context 用量（已讀進多少內容）、花費、用哪個模型與思考深度、跑了多久。移除後，預設畫面只剩名稱和正在執行的動作。同時開好幾個背景小幫手的人，等於看不出誰在燒錢、誰快撐爆。而且升級後設定檔不報錯也沒警告，只是指令不再執行。

**官方怎麼回應？**

一位 Anthropic 的貢獻者在 issue 裡承認處理不當，說移除原因是外掛附帶設定檔的做法不合理，本來打算改由 mod（能改 Claude Code 介面的擴充）接手，卻沒留緩衝期；他說下一版會先加寬限期。11-15 查 2.1.325 的更新說明，還沒有恢復這項設定。

**社群自己怎麼防？**

同一週冒出一批看守類小工具：[Reinwatch](https://github.com/sofumel/reinwatch) 號稱能擋住失控的子 agent；[Bright Lines](https://github.com/LeriderTechnologies/bright-lines) 是遇到不確定就拒絕放行的 hook（在特定時刻自動跑你指定指令的設定）；[Aq](https://github.com/nodo-labs-uk/attention-queue) 把多個 session 裡「在等你回應」的排成佇列，HN 19 分（11-12 快照）。

**值不值得跟？**

直接做：設定檔有 `subagentStatusLine` 的人，先別升到 2.1.323 以後，issue 作者實測 2.1.322 仍正常；已經升了的，等下一版並確認更新說明真的提到恢復。沒用過這個設定的人不受影響。
