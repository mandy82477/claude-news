# 設計者派工模板（Opus，一位，只派一次；第二輪用續用）

貼 `../dispatch-prefix.md` 共用前綴，接本段，再逐字貼 dispatch-prefix 的「設計者交件契約」。

```
## 本次任務：第 {N} 波設計者——`wiki/{slug}.md`

工作目錄 {REPO}；scratchpad {SCRATCH}。**行號一律以檔案原始行號為準**（含 frontmatter）。

**先讀（依序）**：`docs/page-audits/{slug}-{date}.md`（健檢卡；預測對照節可能稍後才 append，不必等）、`wave{N}-cold-reader-{date}.md`、`{slug}-{date}-verified.md`（主編查證；行號口徑見該檔）、上一波定稿 `{prev}-proposal.md`＋`-draft.md`＋`-review.md`（學形狀：結論表打頭、每列「誰會遇到／你能先做什麼」、退場＋補位＋入口判準、保命條款、整頁去向小節、第二輪處置對照）；規則檔 `.claude/rules/{rules}.md`、`wiki-ingest-format.md`「時段蒸餾與封存」、`wiki-reporter-shared.md`；對象頁與 archive 頁；鄰居 {清單}（跨維護者的頁只能走 `pending_handoffs.py`）。

**主 session 已定（不可再議）**：使命句「{…}」。節點去留：{本頁／每個鄰居一行；併頁或缺一頁＝裁決點交使用者}。{已代判項目}。

**設計必須涵蓋（缺一項評審會退）：**
1. {Q1 結論層：表名、欄位、判準句＋上限＋退場＋補位＋入口＋留表優先序；自己拿現有列跑一遍，連還在跑的產品行為也跑}
2. {Q2…}
3. {Q3…}
4. {Q4…}
5. **同一事實多家去重**：{懸置 n 筆實為 m 事實，行號}——以事實為單位定家，**砍前保命條款**（被砍處不是某懸置僅存的家）。
6. **符號系統**：正文只留一套讀者語言狀態＋一行圖例；懸置 metadata 進 `%%` 或細節區。
7. **蒸餾**：{時段與條數}，每頁至多 2 時段，月份算對；archive 反向指針先修。
8. **入口**：index 首屏該加哪一列（只給文字）；鉤子句；首屏誤導路怎麼堵（跨頁走帳本）。
9. **數字自洽**：{頁內矛盾的數字}，各定一個值＋理由；證據等級混排→來源等級欄或降細節區。
10. **內部用語外洩 {n} 條**逐條處置。
11. **維護者同步**：規則檔哪條改成什麼，逐字；規則檔指向不存在的節先修。

{接：設計者交件契約逐字}

**產物**：`docs/page-audits/{slug}-{date}-proposal.md`、`-proposal-map.md`、`-draft.md`。回報：路徑、兩閘輸出（含驗紅）、裁決點（≤3；拆頁／砍整節／併頁／缺一頁必列）、最沒把握的一處。繁體中文。之後會被續用做第二輪，保留 context。
```

## 續用：第二輪（評審交件後，SendMessage 同一 agent）

```
評審交件：`docs/page-audits/{slug}-{date}-review.md`（{n} 🔴、{m} 🟡、實作單 {k} 步）。請 append `## 第二輪：評審條目→處置` 到提案末尾，上限 {45–50} 行，同步改 draft 與 map：
1. 每條一列：接受／接受但改寫（貼你的版本 ≤3 行）／反駁（一句理由＋證據行號；只准用在評審事實有誤處）。
2. 評審指名你必須親改的：{條目}。
3. 主 session 更正代判：{…}。
4. {其他必補：整頁去向小節、退場入口判準、日期口徑}。
5. 最後一句：裁決點是否仍 ≤3、除既有裁決外有無新增。
未回覆的裁決以保守預設寫去向表，另留「若裁 X」替代去向。
```

評審與設計者互相改版時，主 session 每次都要明說「哪份是現行檔」（實作者曾因此拿到舊版）。
