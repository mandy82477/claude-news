# 健檢卡派工模板（Opus，一位，與冷讀者同時派）

貼 `../dispatch-prefix.md` 共用前綴後接本段。`{}` 內由主 session 填。

```
## 本次任務：第 {N} 波健檢卡——`wiki/{slug}.md`（{廣度層／入邊／行數}）

工作目錄 {REPO}；scratchpad {SCRATCH}。樣板：上一波健檢卡 `docs/page-audits/{prev}-{date}.md`（含預測對照節）。**行號一律以檔案原始行號（含 frontmatter）為準**，不用 `wiki_graph` 口徑。

**角色：健檢卡 agent，只診斷。** {層級：樞紐＝完整六問／中層＝Q1、Q2、Q4、Q5／葉子＝機械掃描＋節點三問一句}。維護者 {記者}，規則檔 `.claude/rules/{rules}.md`。

節次：使命句候選（≤2，附理由；不能太硬）／考題集（a/b、讀者起點、預測跳數＝開頁數、卡點行號）／首屏路由（射程＝index 上指向本頁與所有鄰居的每一列，逐列問那條路送到的頁答不答得了本頁考題、多久沒更新）／數字自洽掃描（scratchpad .py）／結論句反向掃描／懸置 metadata 裸露筆數／符號系統計數與圖例／證據等級混排／節名帶日期是否對得上內容／逐節診斷（服務哪幾題、雷達或百科、留／改／併／砍／下沉／拆）／鄰居分工含**節點三問**與「節點去留」欄（鄰居由 `wiki_graph.py explain`＋`similar` 機械產生；至少含 {鄰居清單}；人物頁供料零停滯久者要認真答存在必要）／表格生命週期（已知：{census 摘要}；無機制成長表＝爆版點，每張給覆寫式或累積式＋判準句）／維護者同步（規則檔哪些條會被牽動，只列不改）／拆頁三題判（候選：{子故事}）／需官方查證表（你沒 web 工具，不猜官方現況）／設計起點（Q2 及格與否＋一句給設計者）。**已知逾期懸置 {n} 筆**——列行號與主題，並以事實為單位去重。

**考題集種子（驗證、補充、標 a/b、加讀者起點、預測跳數與卡點）：**
- Q1（a/b）{…}
- Q2 {…}
- Q3 {…}
- Q4 {…}
使用者線索：{reader-notes 行號／Query 史}。上一波冷讀者若已跑過相關題：{結果一句}。

**產物**：`docs/page-audits/{slug}-{date}.md`，上限 180 行。回報：路徑、Q2 及格與否、使命句候選、節點去留欄摘要（本頁與每個鄰居一行）、需官方查證表原文、最沒把握的預測。繁體中文。之後會被續用做預測對照，保留 context。
```

## 續用：預測對照（冷讀者交件＋主編查證後，SendMessage 同一 agent）

```
請 append `## 預測對照（冷讀者實測後）` 到健檢卡末尾（編號接續），上限 40 行。冷讀者 `docs/page-audits/wave{N}-cold-reader-{date}.md`（現在允許讀）；主編查證 `{slug}-{date}-verified.md`。

實測摘要：{每題 ✅⚠️❌＋跳數＋一句卡點；入口；不一致；洩漏條數；撐不起的句子}。
主編查證要點：{三到五句}。

做：(1) 每題預測 vs 實測（跳數＝開頁數）判對上／部分／沒對上＋一句原因；(2) 冷讀者抓到你沒預測的，逐條判盲區還是六問本來不抓；(3) 查證結果回填第 {逐節診斷／查證表} 節處置（哪幾列由待查證改結案或事實更正）；(4) 可信度一句＋下波要加什麼問。
```
