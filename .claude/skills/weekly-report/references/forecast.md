`.claude/skills/weekly-report/SKILL.md` 步驟 4 第 (3)(4) 段的規則單一來源。括號內的「反例」是界標，全文敘述見沿革檔 `docs/rules-changelog/weekly-report.md`。

## (3) 下週看什麼

**本節目的（2026-08-30 使用者裁定，權威）：提醒讀者下週有哪些消息值得關注。**

回收段服務於這個目的——它是**篩選器**（告訴讀者哪些舊線死了可以放下、哪些活線已併入清單），不是帳本本身；因此**新開表在上、回收表在下**。判準凍結與逐條結算照舊一字不放鬆：沒有它，「值得關注」就變成每週憑感覺重選一次。

> **規格只寫格式不寫目的，接手的人只會把它當成一張要瘦身的表。**（教訓見沿革檔 2026-08-30 B）

本段含兩張表，必須用下列固定小標與**固定欄名**寫，`scripts/build_web.py` 依欄名分辨兩者（欄名改動會讓該表整張不進 JSON、在網站上消失）；小標字串另被 `scripts/check_weekly_ledger.py` 三處引用，改名要同步（皆見 `.claude/skills/weekly-report/references/contracts.md`）。

```markdown
### 下週值得關注：新開 N 條

（表前導言 1 句：上期幾條結案、幾條續盯，交代為什麼新開額度是 N。）

| 類型 | 預告 | 判準 |
|------|------|------|

### 上週的線怎麼了（Wnn）

（表前導言 1 句＝盤點摘要：幾條活著帶進下週、幾條死了可以放下、幾筆判錯。）

| 上週預告 | 判準 | 本週結果 |
|---|---|---|
| … | 逐字沿用立案當期原文，不得改寫 | ✅／❌／⏰ 結案，或 ⏳／🟡 + 「→ 續盯至 Wnn」 |
```

### 回收段＝篩選器的書寫紀律

1. **位置在新開表之後**——讀者先拿到要盯的清單，再看舊線的下場
2. **表前一行盤點摘要**：幾條活著帶進下週（及去向）、幾條死了可以放下、幾筆判錯。
   判錯筆數**必須出現在摘要裡**——讀者需要知道「不用再盯」這個判斷會錯、錯了會被公開更正
3. **結果欄第一句回答「還要不要盯」**：死線寫「不用再盯」＋一句為什麼；活線寫去向
   （「→ 續盯至 Wnn」，或「已轉入 [[頁]] 長期追蹤，本刊不再逐週報告」＋一句該頁現在說什麼）。
   程序性交代（依哪一條分支判定、寫回哪個 wiki 頁）退到句尾括號，且**用讀者語言**寫（「官方原文與庫內三處不一致，已更正」），不得寫成「判準第三支」「逐字凍結」（見 `.claude/skills/weekly-report/references/deepdive.md`「讀者版禁用內部詞」）
4. **零命中結案的列 ≤ 30 字**：「零命中、無後續、結案」本身就是完整資訊。（反例：W35 五列各寫 60–100 字重述判準）
5. **判準欄一個字都不動**——它是給 `check_weekly_ledger.py` 的契約，不是給讀者的內容。
   本節改的只有結果欄文體與摘要行，凍結機制零改動

> **節導言與兩張表的表前導言都不可省略。** 節導言與新開表導言（第一個 `|` 之前的所有非標題文字）由 `scripts/build_web.py` 合併抽成 `nextweek.intro`；回收表導言由 `_parse_weekly_recap_intro` 抽成 `nextweek.recapIntro`，顯示在網站回收區塊標頭下方。三者皆由 `scripts/check_weekly_ledger.py` 以 ⚠️ 提醒。

`scripts/check_weekly_ledger.py` 依上述欄名與標題比對兩期帳目，掛在 `scripts/run_tests.py` 內。

### 帳目生命週期

回收表要涵蓋的是**上一期的整本帳**——上期新立的 ＋ 上期回收表中仍未結案（⏳／🟡）的，兩者都必須逐條出現，漏一條即測試失敗。

| 結果 | 下一期 |
|---|---|
| ✅／❌ 判準被切乾淨 | 結案，不再出現 |
| ⏰ 到期日已過 | 結案；結果重要則轉入 wiki 對應頁，於結果欄註明去向 |
| ⏳ 未定／🟡 半收 | **留在帳本這一側續盯**，結果欄寫「→ 續盯至 Wnn」，**不佔新開條數額度** |
| 同一條連續兩期未定 | **強制結案**，寫「無結論」或降級為未證實——避免殭屍條目長住帳本 |
| 判準因事件性質改變而失效 | 結案並註明「判準失效（原因）」，要續追改立新條，不得沿用舊判準 |

### 判準的四條規格

**可證偽預告**：每條立判準「若 X 則 A、若 Y 則 B」。

**判準形狀**：新立判準**扣掉 `｜查證：…` 尾巴後的正文 ≤80 字**（含標點）、**單一 if/then＋null 分支（到期日型免 null 分支，見下）、讀者語言**——不寫三分支決策樹、不引用 wiki 頁路徑、不用內部詞（見 `.claude/skills/weekly-report/references/deepdive.md`「讀者版禁用內部詞」）。網站已不渲染判準欄，但 markdown 讀者仍看得到；已凍結的舊判準不回溯改（契約），靠新立案守形狀讓它自然換血。（反例：W35 單格 190 字三分支，冷讀者五格全跳過）

**正文的前瞻承諾必須入表**：頭條、綜述或數字節裡提到的「X 日到期」「下週將…」這類前瞻句，該事件**必須同時出現在新開表**（立判準），否則刪掉前瞻句；與「條數 3–6」衝突時**上限優先**——額度用完就刪正文未入表的前瞻句（或改寫成不含承諾的既成事實敘述），不得破 6 條上限。（反例：W34 +50% 促銷未入表，換軌時無人交代）

**到期日型條目附一句行動**：預告欄為到期日型者，預告文字末必須含一句讀者可執行的動作（「到期前決定要不要續約」「無需動作，到期自動轉為 X」）——與頭條行動句同一原則，答不出就寫「到期前無事可做」。其餘五類不強制。

**判準必須含 null 分支**：二分法只涵蓋「發生了 X」與「發生了 Y」，但實務上**最常見的結果是「這週什麼都沒發生」**。因此除到期日型外，每條判準都要寫明**無事發生時的處置**（順延 N 週／降級為未證實／併回既有敘事／結案），例如「若兩週內只剩體感抱怨 → 併回既有共識，不另立線」。（實據：W30 六條有三條落在此格）

**判準必須可查證**：判準的作用是讓回收變成**查證**而非**判斷**——寫成主觀敘述（「社群覺得有改善」）時，回收者既立判準又判結果，等於自己給自己打分。每條判準結尾必須附查證線索，格式固定：

```
…判準文字…｜查證：關鍵字1、關鍵字2
```

關鍵字須是**能在 `news/*.md` 直接 grep 到的字串**（產品名、issue 編號、版本號、機構名），不可是形容詞。日更 pipeline 會在**選材完成後**用這些關鍵字掃當日條目，命中則 append 至 `weekly/open-signals.jsonl` 供下期回收取用（見 `.claude/skills/news-digest/SKILL.md` Step 3e）。

續盯條目的判準**一律逐字沿用，不得補寫、不得縮寫、不得加查證線索**——`scripts/check_weekly_ledger.py` 對回收表判準逐字比對，加一個字即報「判準遭改寫」讓測試轉紅。`scan_open_forecasts.py` 對缺線索的舊條目印 ⚠️，那是**可接受的常態提醒**，不是待辦。舊判準真的驗不動（無線索、或超出形狀規範）→ 比照「連續兩期未定 → 強制結案」的處置把它結掉（不必等滿兩期），再以合規的新判準另立一條，不得原地修補。

> ⚠️ 掃描一律在選材之後執行。若讓選材階段知道週報正在賭什麼，會產生確認偏誤——選材傾向撿能證實預告的條目，命中率虛高，並連帶破壞每月聚焦校準的獨立性（校準量測的正是選材品質，兩者不得互相知情）。

**條數 3–6，寧缺勿湊**：可證偽是有成本的，湊數會混進「其實沒把握怎麼驗」的題目。每條入選前先過一關：**這個判準能用日報 grep 驗嗎？** 答不出關鍵字 → 不立此條。（實據：W30 六條僅 1 條被判準切乾淨）

第一期（無上一期可回收）時省略回收表，只寫新開表。

條目六類（**技術類——修復追蹤、趨勢確認——優先選**）：

- 到期日型
- 矛盾待解型
- 修復追蹤型（技術類，優先）
- 官宣待發型
- 傳聞驗證型
- 趨勢確認型（技術類，優先）

## (4) 檔尾數字

**格式硬性要求：每筆必須是條列、不得寫成表格，形狀見 `.claude/skills/weekly-report/references/contracts.md`；本節輸出檔的標題逐字為 `## 四、本週數字`（同表）。** 寫成表格會解析出 0 筆，**markdown 讀起來完全正常，但網站上這一節是空殼**；現由 `scripts/check_weekly_ledger.py` 的 `check_weekly_numbers()` 硬擋（< 3 筆即報錯，並辨識「是不是寫成表格了」）。

**5 個數字收尾（淡週可降至 3 個，並在該節末註明「本週管線數字較少」）**：

- 故事型（編輯挑，1–2 個能代表本週故事的數字）
- 管線型（收錄漏斗、Status 事故數、版本數、最高互動 issue 留言數、wiki 更新頁數等）
- **不重列正文數字**：正文已出現過的數字不得原樣再列；本節的價值是**正文沒講的**管線型數字＋至多一個故事型總結數字（後者若正文出現過，必須加新的對照角度才可列）。（反例：W35 五條有四條是複製貼上）
