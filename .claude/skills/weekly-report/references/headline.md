# 第 (1) 段：頭條敘事

`.claude/skills/weekly-report/SKILL.md` 步驟 4 第 (1) 段的規則單一來源。括號內的「反例／實據」是界標，全文敘述見沿革檔 `docs/rules-changelog/weekly-report.md`。

當週最大張力縫成一條因果敘事，**300–500 字，不列清單**。

## 頭條要有標題

`## 一、頭條敘事：` 冒號後接一句話，那就是本期的頭條標題，**≤60 字**，由 `check_weekly_ledger.py` 的 `HEADLINE_DECK_RE` 硬擋（W36 起；舊期凍結不回溯）。格式見 `.claude/skills/weekly-report/references/contracts.md`——`頭條敘事` 四個字不可省，`build_web.py` 以 `"頭條" in title` 認這一節。網站把冒號後那段渲染成頭條副標（`app.js` 的 `weeklyHeadlineDeck()`）。原本另立的 `> **本週一句話**：` callout 已於 2026-09-06 退場，兩者合併成這一句。

**寫這一句的判準：**

1. **句子裡每個名詞，讀者不看正文都指得出是什麼嗎？** 指不出的多半是撰稿者當下發明的抽象詞（預算、版圖、格局、天平），換成正文真的出現過的具體物（指令名、產品名、動作）。
2. **一個沒讀過本刊的人，能照這句話覆述一件具體的事嗎？** 不能就代表它是總結不是標題。
3. **唸出來像人講話嗎？** 口語動詞（讓／叫）優於書面（請／使其）；主動優於被動；具體物（電腦、程式）優於抽象名詞（執行權、邊界）。**一句只放一件事**——塞第二、第三個事實就會變成用分號和破折號串起來的公告。

（W36 三次修稿的病：太抽象、矯枉過正太生硬、定稿一動作一後果一轉折。）

> **標題不負責給行動**——那是收束段「你該做的事」的職責（見下方「頭條必附行動」）。把解法塞進標題正是第二版變生硬的主因：讀者在標題位置還沒有任何脈絡可以接住解法。

> **同日發現、同日改的可讀性缺陷不受步驟 5 凍結拘束**：凍結擋的是「因後續 ingest 回頭改事實」，不是「讀者說看不懂而改寫法」。事實一個字都沒動時，改寫標題照做；動到事實則照凍結規定不改舊檔。

## 頭條必附行動

頭條事件若對讀者有可做的事（趕在某日前調整用量、評估方案、改排程），收束段**必須**有一句「你該做的事」；確實無事可做也要明寫「目前無需動作，等 X」。安全類條目（討論綜述亦同）比照：被繞過的機制要一句「該不該關」、供應鏈攻擊要一句「該不該擋」，答不出就寫「尚無官方緩解，暫無動作可做」。（實測：W35 −17% 配額零行動建議。）

以下規則依 W30–W34 五期實測歸納，W35 起生效；帶「🔧」者由 `scripts/check_weekly_ledger.py` 對 **2026-W35 起**的期數機械檢查（舊期已凍結，不回溯）。

## 結構層：為誰寫、線怎麼選、怎麼收

1. **入口讀者裁定**——首段的敘事入口必須是排序最高讀者（Claude Code 重度使用者）**當週實際經歷或可感知的事件**；商業／生態消息可以是本週最大的線，但只能作為第二段以後的「另一側」，不得開篇。例外：當週使用者側無頭條級事件時方可從生態側開篇，並於檔尾素材說明（即檔尾 **素材涵蓋窗** 段）註明。（反例：W33／W34 連兩期從財經視角開篇）
2. **編線准入**——收束段必須逐線交代該線在因果鏈中的位置（推動什麼、或被什麼推動）；點不到名、或只能以「同一週也發生了」連接的線 → 整段移出頭條（入討論綜述或本週數字）。**線數由因果鏈決定，不由當週大事數決定**——兩條緊的線優於三條鬆的。（反例：W34 浮水印線缺席卻佔頭條一段）
3. 🔧 **頭條-深挖分工**——同題可以，但兩篇回答不同的問題：頭條回答「這件事為什麼重要、我要不要反應」，深挖回答「機制是什麼、怎麼做」。同題時頭條只寫意義層，**指令、檔名、設定名、官方文件連結與機制層數字只住深挖**，頭條收束段用一句顯式路由指過去（「……拆開來是什麼，見本期深挖」）；「你該做的事」只寫要不要動，怎麼動留給深挖與「本週要動的事」。W39 起 `check_weekly_ledger.py` 硬擋頭條與深挖共用的反引號詞（頭條標題裡的除外）與連結，共用數字提醒。不同題時，頭條懸而未答的問題若本期無解，明寫「列入下週看什麼」並確認預告表真有該列，不得偽裝成有答案。（反例：W34 頭條收尾的問題零指引）

## 連載層：跨期連續性

4. **前情錨＋增量**——延續上週的線（同一組行動者＋同一衝突），首句必須同時給：**前情錨**（≤25 字從句，含起點日期＋發生了什麼，服務冷讀者）與**本週增量**（新事實／官方動作／狀態變化，服務連續讀者）。寫不出增量的延續線降入討論綜述；三條線與上期重疊 ≥2 且均無增量 → 換題，或改寫成「張力未解，但 X 動了」的推進式敘事，不得重講。（反例：W34「浮水印的餘波」餘的是什麼波未交代）
5. **固定稱呼**——每條線指定一個 ≤10 字固定稱呼，首見處以完整敘述定義，其後**全篇（含討論綜述、深挖、下週看什麼、本週數字）逐字沿用**，不得換說法、不得用「那則」「前述」回指；補細節寫成「稱呼＋補述」。（反例：W34 同一起事件六種說法）

## 句子層

6. **收束預算**——本刊自己的推論（官方沒說、由事實推得的判斷）全篇頭條至多一句，標「（本刊推論）」，不獨佔一段。對仗判斷句（「不是 X 而是 Y」等）全文 ≤1 次且只能在末段，其餘段落陳述事實不下判斷；末段結論句**禁抽象隱喻**，寫成讀者可直接覆述的因果句。（正例：W33「規模化的三個代價同時到齊」）
7. 🔧 **跨期句式防重複**——動筆前 diff 上期頭條末段的句法骨架，同構即換收束方式（時間因果鏈、反問、或直接給結論）。機械檢查擋的是連兩期命中「把 N 條線並排」句型。（實據：W33 與 W34 收束句逐字級同構）
8. 🔧 **數字紀律**——關鍵數字第一次出現時句內附（來源，日期）；**量級數字（≥1 億（含外幣等值）的金額、或任何以「億／兆」為單位書寫者）不得歸因給「財經媒體」「多家媒體」這類無名集合**，至少指名一家並附行內連結，其餘才可概括為「另 N 家跟進」；**同段 ≥2 個同單位數量時，每個數字緊鄰處必須帶角色詞**（已實現／年化／單季／預測（年份）／估值／額度上限／一次性），同段 ≥3 個角色互異 → 拆句或移「本週數字」；同段具名機構／媒體 ≥3 家 → 概括為「N 家媒體同步」，不逐一列名。（反例：W33 首段六個金額無角色詞）
9. 🔧 **日期位置**——每段以 `MM-DD` 開頭的句子 ≤1（留給該段真正以時序為重點的那句），其餘事件先行、日期後置（句中補述或括號）；段內日期由早到晚，做不到代表混了兩條時間線 → 拆段。（反例：W33 首段日期序倒退一天）
10. 🔧 **粗體預算＋案例定性**——頭條全節粗體 ≤2 處、只標數字／專名、單處 ≤15 字，不標完整判斷句。引用具體使用者案例時**當句交代**它是個案、已知模式、還是本期確認的新機制，不留給回收表。（反例：W34「排程被切到 Fable 5」未當句定性）

## 驗收層：冷讀者三問（頭條寫完後強制執行，不進交付檔）

假裝你是第一次讀本刊、只讀了頭條敘事的人，回答固定三問，**每個答案必須是頭條正文中可逐字引用的連續文字**（附引用），不得用腦中背景知識補：

1. 這週最壞的具體情況是什麼、發生在誰身上？
2. 和上一週相比，**變的**是什麼？（答案要是變化，不是狀態）
3. 讀完之後，該對哪一件事保持懷疑？（哪個說法還沒被證實）

任一問找不到可引用的連續文字 → 回頭改頭條（**補一句，不是加一段**），不得以「這在深挖有寫」放行。三問與引用寫入完成回報，供收尾檢視。（實測：W34 三問掛兩問，各補一句即修復）

> 刻意不規定的維持不變：語氣詞彙、句長、比喻用不用。收束預算管的是**密度**不是禁令——金句是預算制，全篇留一個記憶點，它反而更值錢。
