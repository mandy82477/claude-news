# 第 (1) 段：頭條

頭條講**本站目標讀者這週最該知道的那一件事**，300–500 字，不列清單。目標讀者是誰見 `.claude/rules/collection-scope.md`。

**選題**：主編選。動筆前先重讀 `.claude/rules/collection-scope.md`「目標讀者」三句（讀者定義會改，不憑記憶），再寫三行給自己（不進週報）：這則回答的是哪一句讀者的問題（對不上任何一句就不上頭條）、影響到目標讀者裡的多數還是少數、有幾個獨立來源且同週有沒有更貼那句問題的。修復、故障與升版提醒預設放「本週官方出了什麼」與「本週要動的事」，它本身就是社群這週最熱的討論才上頭條。專文可以寫給專欄自己的讀者，頭條要對準本站目標讀者。

**標題**：`## 一、頭條敘事：` 冒號後一句話，≤60 字（格式見 `.claude/skills/weekly-report/references/contracts.md`）。一句只講一件具體的事，沒讀過本刊的人能照著覆述；用正文出現過的具體物（指令、產品、動作），不用撰稿者發明的抽象詞。寫事實或答案，不寫讀者照著做不出來的指示（「先自己比」「先觀望」這類只有動詞、沒有比什麼／等什麼的句子）。

**誰定稿**：頭條標題與每篇專文標題（`#### 專欄名｜標題`）一律由 Opus 定稿。主 session 是 Opus 就自己定；不是就派一個 `model: "opus"` 的 agent，給它頭條或專文正文與 `.claude/rules/collection-scope.md` 目標讀者三句，要它回兩三個候選並各自說明「回答哪一句讀者的問題、讀者覆述出來是什麼」，主編從中選。記者交來的專文標題照此重審，不合就改。

**正文**：
- 先講這週出了什麼新東西、或社群在談什麼，再講為什麼重要、接下來會怎樣。
- 延續上週的線，第一句交代前情（什麼時候、發生什麼）再講本週新增了什麼；沒有新增就不上頭條。
- 數字第一次出現附來源連結；本刊自己的推論標「（本刊推論）」。
- 收尾一句告訴讀者值不值得現在用或試、要不要做什麼；沒有值得試的也寫明「目前不用動，等 X」。
- 頭條與專文同題時，頭條講為什麼重要，怎麼做留給專文，用一句話指過去。
