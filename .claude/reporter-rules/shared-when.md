# Wiki 記者共用規則：碰到才讀

以下各節碰到該情況才讀，`.claude/reporter-rules/shared.md` 對應位置會指過來。

---

## 大型頁面讀取策略

頁面 > 300 行時，**不可一次全讀**：
1. 先 Grep 取行號——**能用條目層的關鍵字就不要用節標題**：issue 編號（`#16157`）、版本號（`v2.1.277`）、工具名、⟨Q-nn⟩ 都比節標題準。表格列與條列是自足的，改一列不需要讀整節
2. 再用 Read + offset/limit 只讀命中行的**前後約 10–20 行**；確實要重寫整節（週更結論層、蒸餾）才讀整節
3. 同一次 ingest 中多個無關頁面的更新，在單一訊息中平行發出多個 Edit 呼叫

> **成本看 token 不看行數。** 行數會騙人：`claude-code.md` 行數只排全庫第四，讀一次卻約 86K token、全庫最貴（長表格列，每行平均 180 字元）；它最常被改的「已知問題」**單節就約 41K**——照節標題讀，等於每天為了改一列 bug 狀態載入 41K。

典型大型頁面（整頁約 70–86K token）：`claude-code.md`、`community-tech-patterns.md`、`anthropic-business.md`、`community-tech-patterns-archive.md`

## 事實更正必回掃

**把某個事實從 A 改成 B 時，改完不算完——要拿那個事實的關鍵字回掃全庫，把仍在講 A 的地方一起改掉。**

做法（兩步，先看圖再 grep）：

1. **先跑入邊清單，那是必查名單**（）：

   ```
   python scripts/wiki_graph.py explain <你改動的頁>                    # 整頁
   python scripts/wiki_graph.py explain <你改動的頁> --section "節標題"   # 改的是某一節時
   ```

   帶 `--section` 會分兩組印：**指到這一節的錨點邊**（引用的就是你剛改的那段，逐一開行號確認）、**指到整頁的邊**（未指定段落，仍須逐一確認）。每筆都附「引用方頁 § 引用方的節 :行號」，直接照行號開檔看它是否仍在講舊說法。
2. **再用關鍵字 grep 補漏**：入邊只抓得到用 `[[wikilink]]` 引用的地方，**抓不到散文裡直接寫出那個事實卻沒連結的頁**。所以 grep 不能省，但它是補充不是主力：
   - 想出這個事實在別處會長什麼樣：舊數字、舊日期、舊狀態詞、舊措辭
   - `Grep` 全 `wiki/`（**排除 `log.md`**——它是 append-only 的歷史，本來就該保留當時的說法）
3. 兩組命中合併後逐一判斷：**描述「現在」的句子一律改**；描述「當時」的歷史記錄不改寫，改為 append 一句「**後續（日期）：…**」
4. 回報時附一行：`回掃：入邊 N 處（改 M）＋關鍵字 X 命中 K 處（改 J）`

**先窮舉機器查得到的，再用腦補查機器查不到的**——次序反過來，就會停在腦補的那一半。

判斷式：**我剛改掉的這句話，別的頁面有沒有也在講同一件事？** 有 → 現在就 grep，不要留給下一輪 lint。

## 待查證命中處置

派工訊息可能附一段「你負責頁面今日命中的待查證項目」——這是 `scripts/scan_pending_verifications.py` 的機械偵測結果（探針字串比對，可能誤判），不是主編的判斷。收到後逐筆比對：

- 今日條目**足以**作為該筆懸置的後續 → 依 `.claude/reporter-rules/daily-contracts.md`「懸置標記語法」節「誰可以動這個標記」表，只能加 `｜訊 YYYY-MM-DD` 並更新標記後的內文，回報中列入「已標訊」
- 證據不足（僅探針字串命中，內容答不上懸置的問題）→ 不動標記，回報中列入「證據不足不動」，**不可為了消化清單而過度解讀新聞**
- **不可刪標記、不可改狀態符號（❓/🔎）、不可宣告結案**——結案判斷需要官方一手來源查證，屬 `/wiki-lint` 5c 的工作；記者平日無 web 工具，只有派工 prompt 帶 `【5c 查證授權】` 的那一輪可查證並依 5c 寫回
- 派工訊息無此段或段落內容為「無」→ 回報「待查證命中處置」欄寫「無命中」

## 轉知接手處置

派工訊息可能附一段「轉知待接手 → [你的類別] 記者」——這是別的記者在先前回報中標「⚠️ 需主編轉知」、由主編登進 `data/pending-handoffs.jsonl` 帳本的跨記者交辦（每筆一個 `H-xxxxxx` id）。逐筆處理：

- 該交辦屬你負責頁面且今日可做（補列、加 wikilink、記已知問題……）→ 做完後在回報「轉知處置」欄列入「已處理」並附 id
- 該交辦不屬你、議題已失效、或需要你沒有的資訊（web 查證）→ 不動，列入「不適用」並附 id＋一句理由；**不可為了清單好看而硬做**
- 派工訊息無此段或內容為「無」→ 「轉知處置」欄寫「無待接手」

**你自己要轉知別人時**，照舊在「同步自查」欄寫 `⚠️ 需主編轉知[目標類別]記者：[要做什麼＋頁面]`——結構化登帳是主編的事，你只要把目標類別與要做的事寫清楚。
