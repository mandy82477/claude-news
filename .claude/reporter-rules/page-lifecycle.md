# Wiki 頁面生命週期規則

頁面存續期間會遇到的四件事：節名能不能改、要不要拆、舊時段怎麼蒸餾封存、長到警示閾值怎麼辦。頁面骨架與欄位格式見 `.claude/reporter-rules/page-templates.md`。

---

## 節名什麼時候不能改

**預設可以改，措辭不由規則檔指定。** 條文用「這一節在答什麼＋欄位形狀」指涉一張表，措辭放括號當「現名」——改名只動括號，不必重寫條文。

只有這三種情況凍結：

| 凍結條件 | 怎麼查 |
|---|---|
| 有 `[[頁#節]]` 錨點指入 | `build_web.py` 的 `check_wikilink_anchors()` 在驗，改名會 WARN |
| 有腳本在 grep 它 | `grep -rn "節名" scripts/ web_reader/assets/ src/tests/` |
| 已登記 `.claude/review-registry.json` 的 `anchors` | `check_rules.py` 會驗 |

**改名時**：全庫回掃引用並更新規則檔括號裡的現名；`wiki/log.md`（append-only 歷史）與 `docs/page-audits/`（考古鏈）一律不動。同一句型散在幾頁就一次全改。

## 頁面拆分原則

**一頁一故事**：頁面邊界由主題完整性決定。厚度（> 600 行）是進入評估的**鬧鐘**，不是切法；但蒸餾後仍 > 600 行且考題分得出群時，厚度可作拆子頁的**加分訊號**（使用者 2026-09-23，不必等三訊號同時亮）。拆分的判準是**這一頁回答的問題是不是已經太多**：把這頁要答的讀者問題列出來（健檢卡考題集），分得出多群、每群各有自己的答案與變動節奏，就每群拆成一個子頁；母頁留下**索引＋重要結論**（上半結論表、下半子頁路由表，一子頁一行：答什麼、最後動態），受下方「母頁契約」看守，不得只剩目錄。不按行數對半切、不按月份切、不按層切（結論／證據分家不是拆頁）。另一種拆分是 **死案歸檔**——已 resolved 且不再被任何活躍敘事引用的整段。兩者皆須經使用者確認才可執行。（使用者裁決：「要不要拆子頁要看是不是這一頁回答的問題已經太多了」「母頁也可以變索引頁跟重要結論」）

**先跑蒸餾，再談拆分**：厚頁若有 ≥3 個月前的事件流時段，先走本檔下方「時段蒸餾與封存（全站通用）」，蒸餾後多半掉到鬧鐘以下、根本進不了三題。（量測見沿革檔 2026-09-03）

### 子故事三題（每個子頁要能過；「問題太多」分出的每一群各自過一次）

1. **有自己的問題**：讀者會單獨問這個問題來（「提示注入怎麼防」會；「2026-06 發生了什麼」不會——按月切出來的是 log 不是故事）
2. **有自己的結論與時序**：能寫出自己的 delta-first callout、目前結論、事件流，不是借母頁的
3. **被獨立引用**：別的頁 wikilink 進來時指的是這一段（頁級入邊全指整頁的，照精神判：會被單獨引用嗎）

答不齊 → 那只是母故事的一章，該做的是蒸餾（熬濃），不是拆。

### 階層的語意與紀律

- **parent＝「是它的一部分」（part-of）**，不是「衍生自它」——衍生／引用仍是 wikilink（`community-large-codebase-workflow` 縫合 patterns 的主線，是引用不是子頁）。判斷式：把子頁內容搬回母頁自然嗎？自然 → part-of；不自然 → 引用
- **單一 parent（樹）、規則每層遞迴適用、無深度上限**（使用者裁決）：孫子故事要成頁一樣過三題；深度由故事結構決定
- **階層的單一來源**是子頁標頭一行 `**上層：** [[topics/xxx]]`（放在「領域」之後）；frontmatter `parent`／`children`／`page_role` 由 `scripts/gen_wiki_frontmatter.py` 生成，不手填。**不重用 `kind` 欄**（它是 entity|topic，Bases 視圖在用）
- **子頁扁平放在 entities/ 或 topics/**，slug 自由命名、不編碼階層（日後可改嫁、可升格）；**子頁領域＝母頁領域**（懸置命中靠頁面領域派記者）
- **子頁不入 index 目錄表、不在網站列表平鋪**——只從母頁下鑽（母頁詳頁列子頁卡、子頁有麵包屑；搜尋仍找得到）。index 上母頁列的摘要格由腳本投影一段 `↳ 子故事：[[a]]、[[b]]`（機器投影，家在各子頁的上層欄）——查詢入口與記者認領靠它，記者認領規則「領域＝X 的所有頁面」因此不必改字
- **archive 頁掛在它封存的頁底下**（`**上層：**`），不參與三題、不入 index

### 母頁契約：升格後母頁必須仍是故事

hierarchy 最自然的衰退是母頁退化成目錄——那正是本原則要避免的東西，所以有機械看守：

| 時點 | 母頁准動什麼 | 誰 |
|---|---|---|
| 每日 ingest | **唯讀**，除三樣：頂部 callout（覆寫）、分支目錄表、既有懸置標記加 `訊` | 記者 |
| 每週 lint | **結論層整線重寫**（照 `community-large-codebase-workflow` 契約：固定分層、行數硬上限、只寫「哪條子故事的答案變了」、不 append、引子頁 wikilink 不複製數字） | 對應類別記者，觸發邊登記在該類 `weekly.md` |

- 母頁自身「最後新聞更新」**不因子頁動**（動了會與 `check_wiki_freshness.py` 第 2 類互斥、擋 web build）；「母不落後子」改驗 **callout 日期 ≥ 子樹最新新聞**（`scripts/check_hierarchy.py`，掛 `run_tests.py`）；列表排序與訊號用子樹聚合值（frontmatter `days_since_news_subtree`）
- **路由**：母頁對應規則檔的路由表寫明每個子頁收什麼；判不出的節點寫進母頁「未歸類」節（不是預設子頁——那會變雜物間），週更時分派

### 對稱規則：併回

子頁 < 80 行且 60 天無新聞更新 → lint 提案併回直接上層（需使用者裁決）。併回**必留 redirect 殼**：原 slug 保留標頭＋一行「已併回 [[母頁]]」（`page_role=redirect`），否則週報與外部連結永久斷。

### 升格／併回 verify 流程（強制）

| 階段 | 做什麼 | 機械證據 |
|---|---|---|
| **0 前置** | 厚頁先跑蒸餾；量出蒸餾後行數；仍 > 600 才進三題 | lint 回報行數 |
| **1 盤點 dry run** | 記者對候選頁列子故事，每個附三題答案（引用方頁名＋行號） | 回報表；使用者裁決 |
| **2 手術（同一 commit）** | 建子頁（標頭：領域＝母頁、`上層`）、母頁改寫（callout／目錄／結論層）、回掃 `[[頁#段]]` 錨點連結、懸置標記 `⟨Q-nn⟩` 與細節區成對搬、轉知帳本 `page` 改派、路由規則加子頁 | `python scripts/gen_wiki_frontmatter.py`（產 index 投影）→ `python scripts/run_tests.py` 全綠（含 check_hierarchy／freshness／index_sync／pending_markers／check_tools_page）→ `python scripts/build_web.py` 錨點 WARN 不增 |
| **3 帳本同步** | `python scripts/devpractice_diff.py mark`（搬家 diff 不得被當新料）；log 記升格 | 基準線 sha |
| **4 上站** | 同一 commit push（雲端班次是 fresh clone，配套晚一個 commit 就停站一天） | gate_web_build 綠 |
| **5 冷讀者驗收** | 派冷讀者從 index 走 2 題（1 題母頁層級、1 題子故事層級），3 跳內拿到答案 | 回報 |
| **6 一週回訪** | 下次 lint：母頁 callout 是否跟上、子頁歸因是否落地、`page_role`／訊號是否合理 | check_hierarchy 綠＋lint 回報 |

判斷式：**這次升格，機器抓得到它壞掉嗎？** 答不出 → 還沒到動刀的時候。

## 時段蒸餾與封存（全站通用）

蒸餾契約**住這一檔**（頁面生命週期的家），六類記者共用；`.claude/reporter-rules/community/weekly.md`「月度蒸餾與細節封存」只留社群兩頁的特有判準並指回本節。條文複製到六份規則檔必然漂移，所以通用部分只留一份。（全站泛化的教訓見沿革檔 2026-09-04）

**對象（判準，不窮舉標題）：** 頁面中「依日期堆疊、新的加在上面」的區塊——`## 時序`、`## 歷史記錄`、`## 事件記錄`、`## 攻防紀錄`、以 `### YYYY-MM` 或 `### YYYY-MM-DD` 分組的技術彙整皆屬之。判斷式：**這個區塊的條目是按時間 prepend 的嗎？** 是 → 適用。結論層（摘要、現況、決策表、對照表、風險表）永遠不適用——它們該被覆寫，不該被封存。

**時段 ＝ 一個區塊 × 一個月份**（如 `topics/competitor-landscape` 的 `## 時序` × `2026-04`）。候選門檻：該月距今 **≥ 3 個月**（月份算術：本月序 − 該月序 ≥ 3）。

**三條例外（滿足其一即不蒸）：**
1. **有錨點邊指入**——`python scripts/wiki_graph.py explain <頁slug> --section "<段名>"` 列出的入邊非空
2. **該時段是唯一細節出處**——頂部 callout 或 `## 摘要`／`## 現況`／未結案風險表所述的事實，只在該時段條目裡寫著（同頁他處已有細節家者不算）
3. **狀態 🌊延燒／🌋重燃的討論**，其歷史時段一律不蒸（重燃需要上下文在場）

**產物兩件：**
- 主頁該時段 → **≤ 15 行時段總結**：收斂結論、仍具引用價值的專有名詞、末行固定 `原始條目見 [[<archive 頁>#YYYY-MM]]`（錨點建置會驗）。總結受 `.claude/reporter-rules/shared.md`「書寫風格」硬上限拘束
- 原文**一字不刪**照搬 append 至 archive 子頁的 `## YYYY-MM` 分組

**archive 子頁（每個母頁一個，slug ＝ `<母頁 slug>-archive`）：** 首次建立時——標頭領域＝母頁、`**上層：** [[母頁]]`、狀態 `resolved（封存頁）`、頂部一句 callout 說明「本頁為原始條目封存，重點層見主頁」；**不補 index 列**，跑 `python scripts/gen_wiki_frontmatter.py` 會投影進母頁列的「↳ 子故事：」（`scripts/check_hierarchy.py` 驗上層、領域繼承、投影、`resolved（封存頁）` 狀態）。既有 archive 頁沿用其既有分節，新時段一律開 `## YYYY-MM`。懸置標記 `⟨Q-nn⟩` 與其細節區條目**成對搬**，不可只搬一半。

**引用回掃：** grep 全庫指向被搬條目的 `[[頁#條目標題]]`，改指 archive 對應錨點（`scripts/build_web.py` 的 `check_wikilink_anchors()` 會驗）。蒸餾是搬位置＋熬濃，不是刪除，斷鏈即違規。

**節奏與角色：** 每次 `/wiki-lint`，各記者對自己負責頁面提案（回報欄 `蒸餾候選：`，格式見 `.claude/skills/wiki-lint-reporters/references/dispatch.md` 的 3h），主編彙整後**經使用者確認才執行**；**每頁至多 2 個最舊時段**（漸進，不一次大搬家）。無達標時段 → 回報「無蒸餾候選」。

**欄位：** 主頁與 archive 頁都只更新「最後更新」，**不動「最後新聞更新」**——搬位置不是新聞。

判斷式：**這個時段的條目，還有活躍敘事在指它嗎？** 沒有 → 它該進證據層，讓重點層讀得動。

## 警示觸發重構（超過閾值時嘗試修復；工作量過大則記錄 log.md 待辦）

| 警示條件 | 閾值 | 重構方向 |
|---------|------|---------|
| 頁面過長 | > 200 行 | 檢查入口層結構（callout / 概覽表 / 月份或主題分組），有入口層即通過；缺入口層才補結構，不建議拆分 |
| 事件流堆積 | 連續 8 個以上 `### YYYY-MM-DD` 無主題分組 | 合併為主題段落 |
| 缺少結構化 | 方案比較以純段落表達 | 改為 Markdown 表格 |
| 表格不可排序 | 欄位值格式不一致 | 統一日期、熱度、狀態符號格式 |
| 摘要缺失 | `## 現況`/`## 摘要` 空白 | 從頁面內容萃取補寫 |
| 指標表凍結 | 核心指標/統計表格的數據日期落後「最後新聞更新」超過 21 天 | 更新表格數據；無新數據可更新時在表格上方標註「數據截至 YYYY-MM-DD」，避免讀者誤判新鮮度 |
