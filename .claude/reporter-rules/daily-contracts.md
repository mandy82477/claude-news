# Wiki 每日派工必讀契約

以下兩份契約（呈現品質標準、懸置標記語法）是每日派工都會用到的，記者開工與 `.claude/reporter-rules/shared.md` 一起讀；頁面格式模板、決策框架、命名與分類仍在 `.claude/reporter-rules/page-templates.md`。

## Wiki 頁面呈現品質標準

### 必須修復（ingest 完成前不得跳過）

| 項目 | 判斷方式 | 修復動作 |
|------|---------|---------|
| **頂部 delta-first callout** | 狀態為 `ongoing` 或 `monitoring` 的 topics/ 頁面，標頭後必須有 `> **標籤**（YYYY-MM-DD）` callout 區塊，說明最新一筆重大事件；**今日有實質更新的任何頁（entities/ 也算），callout 括號日期必須寫成 TARGET_DATE**——讀者版日報（`daily/`）就是各頁當日 callout 的投影，日期不對這頁當天就不上站 | 新增或補寫 callout，格式見下方範例 |
| **摘要 delta-first** | `## 現況`/`## 摘要` 的第一句回答「最近發生什麼」，不是「這個頁面是什麼」 | 改寫第一句為最新事件或狀態變化 |
| **摘要可獨立閱讀** | `## 現況`/`## 摘要` 前 160 字能讓不熟悉背景的讀者理解頁面主題 | 改寫摘要段落 |
| **關鍵資訊前置** | 最重要的事實出現在頁面前 1/3 | 將核心表格或結論移至前段 |
| **熱度表格緊接摘要** | 熱度統計表格緊接在 `## 摘要`/`## 現況` 之後，不可置於末尾 | 移動表格區塊 |
| **無 LLM 專屬指令** | 正文不含「請執行」「下一步」「若日報出現…」等操作語句 | 移至對應的 `.claude/reporter-rules/<類別>/` 規則檔或刪除 |
| **無維運術語洩漏** | 正文與標頭不含 ingest / lint / 派工等內部維運字眼（如「每次 ingest 更新」「此頁為 lint 專用」「下次 ingest 應…」）——讀者只需要「每日更新」「每週策展」這類節奏描述 | 改寫為讀者語言；「更新頻率」欄位的補充說明照 `**更新頻率：** 🗓️ 週更（每週策展一次；更新日期停留數天屬正常節奏）` 格式書寫。刪不掉的維運備忘移進 `%% … %%`（見 `.claude/reporter-rules/shared.md`「維運備忘的家」）；本列由 `scripts/check_reader_language.py` 看守，禁詞清單住該腳本 |
| **實體狀態變更全檔案 cross-check** | 今日更新涉及實體狀態變更（如管制解除、模型下線、功能升版）時，該實體名稱在同一頁面（含摘要、表格、callout、歷史記錄）與被引用的其他頁面中若有殘留舊狀態敘述 | 對該實體名稱 grep 全檔案，逐一確認並統一為最新狀態，不可只改觸發本次修改的那一行 |
| **現況不被時序侵蝕** | `## 現況`/`## 摘要` 內帶日期的事件段落超過 2 段（新事件 prepend 進摘要卻不清舊段，會讓摘要變成第二份時序） | 只保留最新 2 段，其餘移入歷史記錄/時序；若該事件已在歷史記錄則直接刪除，不雙重維護 |
| **表格放結論，細節下沉（全站通用）** | 但書——上一列判定確實需要表格時：任何表格儲存格超過 **120 字元**散文（量測前先剝掉 markdown 連結 URL；純引用來源格〔標題＋URL＋日期〕豁免）——查證過程、演進脈絡、多來源歧異塞進格子會讓表格失去可掃描性並在網站爆版 | 儲存格只留結論短語＋關鍵數字＋最新日期，細節**完整下沉**到該表格正下方的細節區（錨定表內關鍵詞）——細節區條列本身受 `.claude/reporter-rules/shared.md`「書寫風格」的 200 字元上限拘束，下沉是換位置，不是換成無上限的傾倒區；下沉是搬位置不是刪除，數字與歸因一個不能少。此規則自 `.claude/reporter-rules/models/pages.md` G/H 條提升為全站通用（2026-08-27 可讀性掃描：政策/商業/功能頁多表同病）；model-comparison 的欄數上限與自查指令仍見該檔 |
| **表格只在有得比時才用（全站通用）** | 表格的條件：≥3 列共用同一組欄、讀者要跨列比較（排行、狀態、選型、對照），且欄數 ≤4（每格都是短代號者除外）。時間軸、鍵值對應、逐項說明、只有一兩列的資料，讀者不會跨列看——用條列（`**鍵**：值`）或一句話，不用表 | 改寫成條列或散文；`python scripts/table_census.py` 列出的 ≤2 列表與 2 欄長文表優先 |

**頂部 delta-first callout 格式：**
```markdown
> **標籤**（YYYY-MM-DD）
> 給讀者的今日重點：發生了什麼、這頁怎麼看、對他意味什麼。
```
**callout 是寫給讀者版日報的**：日報一字不改地抄它，讀者只看到這一段、看不到頁面其餘部分。所以它就是這一頁**今日重點的摘要**——外面發生了什麼（一次發布、一份量測、一個人說了什麼）、本頁獨有的角度或數字、對讀者意味什麼。寫完把整頁遮掉只讀這段：陌生人看得懂發生了什麼、該怎麼看嗎？看不懂就重寫。我們拆了哪頁、換了版面、未收錄理由——讀者不在乎，進 `wiki/log.md`，不進 callout。

- **外殼**：首行粗體標籤緊接全形括號、括號內緊接日期。標籤自取（最新動態／最新判讀／本週衝擊……）。`（` 後不是日期的（`❓ **待查證**（標 …`、`（快照 …）`、`（重寫 …）`）不會被當成今日重點，沒有時效的頁面自介就用這種寫法。消費端：`scripts/build_reader_digest.py`、`scripts/check_hierarchy.py`。
- **日期**：你這次 ingest 的 TARGET_DATE，不是事件日；寫到「隔日」的事，日期就是那天——日報按這個日期投影，寫早了會把後來的事洩漏進舊日報。
- **只有一則**：更新時覆寫，不疊「前次動態」；多件互不相關的事用 `> - **主題**：一句話` 條列。歷史進 `## 時序`。
- **同一事件只在它的家講一次**：事件的家是主題頁；人物頁、相關實體頁只寫一句點名事件（有主詞）＋這個人／東西的角色＋ `[[topics/事件頁]]`。
- 位置：標頭欄位之後、`---` 之前。entities/ 頁面同樣建議加，非強制。

> 產生器會對投影後讀不通的形狀印 WARN（頁內編號 `⟨G-11⟩`、「見『## 節』」、「詳見下方表」、沒有頁名的 `[[#節]]`）——那些都是「陌生人看不懂」的症狀，不是規則本身。

## 懸置標記語法

事實尚未確定時（待查證／待核實／官方未載），**必須用本節語法標記**，不可只寫一句「待查證」了事。

理由：散文裡的「待查證」沒有任何機制讀得到它。本語法讓每筆懸置**自帶偵測條件**：每日掃描拿探針比對當日日報，命中就通知對應記者。

### 標準式（散文／條列／callout／短表格儲存格）

```
❓ **待查證**（標 2026-08-07｜查 [[topics/ai-agent-safety]]、CI workflow secrets）｜**GitHub Issue 觸及 CI secrets**（2026-08-07 報導）：The Hacker News 報導…
```

四段：`狀態符號` + `**類別詞**` + `（metadata）` + `｜**題目**：內文`。前三段是機器區、第四段是人類區，以全形 `｜` 分界。**括號寫在粗體外**，讓表格處理函式不會動到 metadata。

| 欄位 | 語法 | 必填 | 語意 |
|------|------|------|------|
| 狀態符號 | `❓` / `🔎` | ✅ | `❓` 尚無人查；`🔎` 已查官方一手來源、確認未載 |
| 類別詞 | `待查證` / `查無官方` | ✅ | 與符號一一對應，不一致會被檢查擋下 |
| 標記日 | `標 YYYY-MM-DD` | ✅ | **寫下這個標記的那天，不是事件發生日**。事件日寫在題目後的散文括號裡 |
| 探針 | `查 A、B` | ✅ | 每日掃描拿來比對日報的關鍵字，頓號分隔。`[[wikilink]]` 優先 |
| 複查日 | `複 YYYY-MM-DD` | ⬜ | **省略即為標記日 + 14 天**。有寫代表有人動過手 |
| 訊號日 | `訊 YYYY-MM-DD` | ⬜ | 日報出現後續的那天。**記者唯一可新增的欄位** |

### 表格變體

儲存格加上完整標記後 **≤ 120 字元**（同 `.claude/reporter-rules/models/pages.md` G 條）就直接用標準式；超過則儲存格只留短標記，完整標記下沉到該表格正下方的「懸置細節」區：

```markdown
| … | ❓ 待查證 ⟨Q-07⟩ |

**懸置細節**
- ⟨Q-07⟩ ❓ **待查證**（標 2026-08-07｜查 [[topics/ai-agent-safety]]、CI secrets）：僅標題可用，攻擊鏈與是否已修補均未見報導
```

`⟨Q-nn⟩` 的 nn 為該頁內序號（不跨頁唯一）。儲存格短標記與細節區定義**必須一一對應**，缺任一邊都會被檢查擋下——這是防止下沉後細節區被順手刪掉的唯一機制。

### 探針怎麼寫

探針決定這筆懸置能不能被偵測到，**寫壞了等於沒標**：

- **能在 `news/*.md` grep 到的字串**：產品名、issue 編號、版本號、機構名、英文術語。不可是形容詞
- **至少 2 個**（掃描要求 ≥2 個同時命中才算，單探針偵測力不足）。唯一例外是 wikilink 探針或長度 ≥ 6 字元的字串
- **長度地板**：英數 ≥ 4 字元、中文 ≥ 3 字元
- **禁用過寬詞**：`Claude`、`Anthropic`、`AI`、`Code`、`API`、`agent`、`model`、`Opus`、`Sonnet`、`Cowork` 這類天天出現的詞，以及 `Reddit`、`GitHub`、`Hacker News`、`ClaudeCode`、`Show HN`、`dev.to`、`lobsters`、`Google News` 這類每則條目必帶的平台/來源名，會每日命中、把真訊號淹掉
- **`[[wikilink]]` 優先**：指向實體頁時探針詞自動取自該頁（改名時跟著更新），且建置會驗證目標存在。**樞紐頁（`claude-code`、`ai-agent-safety` 這類高頻詞頁）的 wikilink 不具偵測力，僅作語意連結**——展開出的別名（slug、H1 標題）本身就是通用詞，會落在上述禁用過寬詞清單，不參與比對；偵測力須靠另外 ≥2 個具體探針撐起

### 誰可以動這個標記

| 角色 | 可做 | 不可做 |
|------|------|--------|
| 記者（每日 ingest／lint 3g） | 加 `訊 YYYY-MM-DD`、更新題目後的內文 | **不可刪標記、不可改狀態符號、不可宣告結案**——記者無 web 工具，判準只有日報 |
| 主編（`/wiki-lint` 5c） | 查官方一手來源後三選一：改寫為事實並移除標記／改 `🔎 查無官方`／議題失效則移除；**查實後必須拿探針字串回掃全庫，把仍在說「待查證／推算值」的引用方一併上修**（5c 第 5 步）| — |

> 記者只掃了日報，就只能宣稱日報沒有。**不得寫「至今無後續」**——那讀起來像已經確認過，但答案可能一直躺在官方說明中心。

**機械看守**：`scripts/check_pending_markers.py` 比對全庫標記總數與 `data/pending-marker-count.json` 基線，減少即 FAIL；主編查證結案移除標記時同批 `--rebuild-count --reason`。
