# 開發實務（devpractice）記者：負責頁的維護契約

每日與每週各做什麼在 `.claude/reporter-rules/devpractice/daily.md`、`.claude/reporter-rules/devpractice/weekly.md`；本檔只寫頁面本身的契約。

## topics/coding-workflow-guide

### 程式開發實戰手冊維護

本頁回答「我現在在做這件事，該下哪個 skill、它會做什麼、有什麼坑」。整頁由你一人維護。它的領域欄仍是 🛠️ 工具/功能，負責人靠 `scripts/pending_handoffs.py` 的 `OWNER_OVERRIDES` 與功能記者規則檔的例外句指到你。

三條進料：

| 進料 | 節奏 | 觸發邊 |
|---|---|---|
| **官方對既有功能的使用指南**（省 token、session 經營、設定建議，無新指令旗標） | 每日 | 分類層把這類條目標成「開發實務」，派工包隨每日沉澱一起給你（`.claude/skills/wiki-ingest/references/classification.md`「分流鐵則：官方內容不是社群類的禁區」） |
| 候選帳本 | 每週 | `python scripts/devpractice_diff.py pending` 列出還沒處理的候選 |
| 技能清冊與社群工具策展 | 每週 | 本節下方「週更動作」——類別路由接不到，本節即其觸發邊 |

**官方使用指南的寫入紀律：** 寫進對應的流程階段節，與該節既有的「官方的…」子節並列；**必附官方原文連結與發布日期**。它是本頁唯一可以來自新聞條目的內容，放行理由是它有一手來源、會被更新、經得起查證。社群做法走週更，不因本條放行而每日寫入。

**軸線鐵則：** 以**工程流程階段**為軸（設計→實作→審查→測試→部署→事故→償還），**不得改以開發領域（嵌入式／遊戲／資料工程）分欄或分列**。官方技能本身不按領域切，照領域組織會產出大量空格；領域差異只放在「領域注意」欄，且僅在有具體依據時填寫，無依據留 `—`。

**每段是現在的答案，不是更新紀錄：** 寫入時改寫該段既有的句子或表列，不在段尾追加「某月某日新增」。段內同一件事只留最新說法，舊說法刪掉。

**週更動作：**

1. **候選落地**：`python scripts/devpractice_diff.py pending` 列出的每一筆，問「它改變了哪個流程階段的做法」。答得出 → 先開候選的原頁確認現況（issue 可能已修、說法可能已被更正，帳本那一句是撿到當天的狀態），再改那一段，事實細節以 wikilink 指回原頁；答不出、或原頁已不支持 → 不寫。全部看完才跑 `python scripts/devpractice_diff.py consume`。
2. **技能清冊**：讀 `Official Skills` 來源近 7 天條目（`src/news_aggregator/sources/official_skills_repos.py` 偵測到的清冊異動）。屬工程流程階段的新 skill 補入流程表；屬產出物格式補入格式表；屬非工程用途不進本頁。清冊有增減時，同步自查寫「⚠️ 需主編轉知功能記者：`entities/claude-skills` 生態動態」。
3. **官方涵蓋不到的地方**：已被新官方 skill 覆蓋的列移除，同步自查寫「⚠️ 需主編轉知功能記者：`official-community-gap` 矩陣」。
4. **「深入」節的技巧回訪**：比對近 7 天 patterns 樹（`community-tech-patterns` 母頁與七個子頁）新節點，判斷有無解掉、取代或補強「探索時常撞到的問題」表中某一列。有則更新該列，無則不動。
5. **缺口回訪**：段內寫著「還沒解掉」「缺什麼」的缺口，本週候選或 patterns 樹有對應證據才補，補了標來源與日期；沒有就不動，不拿通用工程常識填。
6. **本週 coding 亮點**：覆寫，至多三條，只放本週真的改了正文的地方，每條一句加指向該段的錨點。本週正文沒動就留一行 `> 本週無新亮點（YYYY-MM-DD 檢查）`。
7. 清冊查證日更新於「參考來源」。清冊性更新不動「最後新聞更新」；當日有官方使用指南寫入時才動。

`## 6. 測試與上線` 段末保留一行指向 [[topics/anthropic-agent-stack]]「你該用哪個」的出口，連頁不連錨。

**不做的事：** 不從通用工程知識補內容；不記錄各 skill 的內部實作細節；不重述事實頁已寫的版本與 issue 細節。
