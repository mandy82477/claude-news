# Wiki 頁面格式規則

建立新頁面、或需確認格式規範時讀取此檔案。頁面的生命週期（節名凍結、拆分、蒸餾封存、重構警示）見 `.claude/reporter-rules/page-lifecycle.md`。

---

## 決策框架：新建頁面類型

- **具體事物**（模型/工具/人物/產品）有足夠描述 → 當天建 entities/ 頁
- **現象/爭議/趨勢** 且 log.md 顯示昨天也出現 → 建 topics/ 頁
- **現象/爭議/趨勢** 今天首次出現 → 暫記於相關 entities/ 歷史，明天再評估
- **entities＝有專有名詞的具體事物；topics＝多方參與的現象/故事。更新頻率不是分類依據**——entities 也會每日更新

**建頁時必須確認觸發邊：** 新頁建立前先判斷它吃什麼——

| 頁面吃什麼 | 觸發邊 | 建頁時要做的事 |
|---|---|---|
| **新聞條目**（一般 entities/topics） | 類別路由即觸發：日報條目分類 → 記者更新對應頁 | 無需額外登記，動態認領條款自然覆蓋 |
| **主題延伸到 Claude/Anthropic 之外**（競品、他家實驗室、產業現象） | 類別路由**只接得到「標題／tag 有提到 Claude/Anthropic」那一半**——12 個來源全部在來源端綁定關鍵字，`filter.py` 對 Google News 再加一道標題閘 | **必須寫 `**蒐集邊界：**` 欄位**（見下方「蒐集邊界欄位」），誠實告訴讀者哪些會漏；若該主題值得補抓，另評估申請 `src/news_aggregator/sources/topic_watch.json` 的定向 query |
| **別的頁面／跨記者彙整**（衍生頁：縫合層、策展層、趨勢層） | 類別路由**接不到**——沒有新聞會路由到它 | **必須同步在對應規則檔登記明文觸發邊**（該記者 `daily.md` 的順手規則或 `weekly.md` 的週更規則），未登記不得建頁。記者無權改規則檔 → 在回報中標「⚠️ 需主編登記觸發邊：[頁名＋建議節奏]」，由主編層執行 |

> 既有衍生頁的觸發邊清冊見 `wiki/CLAUDE.md` 搜尋策略第 5 路。（教訓見沿革檔 2026-07-26）

### 蒐集邊界欄位

主題延伸到 Claude/Anthropic 之外的頁面，**標頭「領域」之後必須加一行** `**蒐集邊界：**`，用讀者語言講清楚「本頁自動蒐集涵蓋什麼、什麼會漏」。

```
**蒐集邊界：** 以 Claude 為參照系的競品動態為主，另針對競品發布與定價定向補抓（每日至多 2 則）；競品自身未與 Claude 對比的發布可能延遲或缺漏。
```

> **承諾了結構上兌現不了的覆蓋範圍，且靜默地不完整**，與「查過確認沒有」和「沒人查」長得一樣是同一種病。（教訓見沿革檔 2026-08-13）

寫法紀律：**用讀者語言**，不得出現 `filter.py`、`topic_watch.json`、query 等實作名詞（此欄位會原樣顯示在網站詳頁標頭）；有定向補抓者要寫出每日上限，讓讀者知道那是補充而非完整覆蓋；**不得寫成「涵蓋全部」**——寫得出邊界才寫，寫不出代表還沒想清楚該頁吃什麼。

## entities/ 頁面格式模板

功能類型（`類型: feature`）且熱度 ≥ 🔥🔥🔥，必須含 `## 熱度與試用價值` 及 `## 使用指南` 區塊。

```markdown
# 實體名稱

**類型：** model / feature / person / product / policy / event
**狀態：** active / beta / deprecated / acquired / resolved（格式：主值（補充說明））
**領域：** 🤖 模型 / 🛠️ 工具/功能 / 👤 人物 / 💼 商業 / 🏛️ 政策/安全 / 🌐 社群
**首次出現：** YYYY-MM-DD
**最後更新：** YYYY-MM-DD
**最後新聞更新：** YYYY-MM-DD

## 現況

## 熱度與試用價值（feature 類型且熱度 ≥ 🔥🔥🔥 必填）

| 項目 | 評分 |
|------|------|
| 社群熱度 | 🔥🔥🔥 |
| 試用價值 | ✅ / ⚡ / ⏳ / ❌ |
| 最適合 | 適用場景 |
| 不適合 | 不適用場景 |

> 詳細最新熱度見 [[feature-radar]]

## 使用指南（feature 類型且有具體用法 必填）

## 核心功能
## 相關議題
## 參考來源
## 歷史記錄
```

## topics/ 頁面格式模板

```markdown
# 議題名稱

**狀態：** ongoing / resolved / monitoring
**開始日期：** YYYY-MM-DD
**最後更新：** YYYY-MM-DD
**最後新聞更新：** YYYY-MM-DD

## 摘要
## 技術彙整        ← 技術類 topic 用此名；政策/商業類可改用自訂區塊名（見下方說明）
## 目前結論
## 相關實體
## 時序
```

**技術彙整** 區塊：每次 ingest 後累積，條列技術機制、已知限制、workaround，不重複已有條目。議題解決後移至 entities/ 作為歷史記錄。

**政策 / 商業類 topic 的區塊命名：** `技術彙整` 僅適用於技術議題。政策、政治、商業類 topic 可自訂更貼切的區塊名，例如：
- `## 根本矛盾` + `## 三個戰場`（用於多方角力的政策議題）
- `## 核心爭點`（用於單一政策爭議）
- `## 背景分析`（用於商業策略分析）

命名原則：讓讀者從標題就能理解「這個區塊在回答什麼問題」。

## Wiki 頁面呈現品質標準

### 必須修復（ingest 完成前不得跳過）

| 項目 | 判斷方式 | 修復動作 |
|------|---------|---------|
| **頂部 delta-first callout** | 狀態為 `ongoing` 或 `monitoring` 的 topics/ 頁面，標頭後必須有 `> **標籤**（YYYY-MM-DD）` callout 區塊，說明最新一筆重大事件；**今日有實質更新的任何頁（entities/ 也算），callout 括號日期必須寫成 TARGET_DATE**——讀者版日報（`daily/`）就是各頁當日 callout 的投影，日期不對這頁當天就不上站 | 新增或補寫 callout，格式見下方範例 |
| **摘要 delta-first** | `## 現況`/`## 摘要` 的第一句回答「最近發生什麼」，不是「這個頁面是什麼」 | 改寫第一句為最新事件或狀態變化 |
| **摘要可獨立閱讀** | `## 現況`/`## 摘要` 前 160 字能讓不熟悉背景的讀者理解頁面主題 | 改寫摘要段落 |
| **關鍵資訊前置** | 最重要的事實出現在頁面前 1/3 | 將核心表格或結論移至前段 |
| **熱度表格緊接摘要** | 熱度統計表格緊接在 `## 摘要`/`## 現況` 之後，不可置於末尾 | 移動表格區塊 |
| **無 LLM 專屬指令** | 正文不含「請執行」「下一步」「若日報出現…」等操作語句 | 移至對應的 `.claude/reporter-rules/<類別>/` 規則檔或刪除 |
| **無維運術語洩漏** | 正文與標頭不含 ingest / lint / 派工等內部維運字眼（如「每次 ingest 更新」「此頁為 lint 專用」「下次 ingest 應…」）——讀者只需要「每日更新」「每週策展」這類節奏描述 | 改寫為讀者語言；「更新頻率」欄位的補充說明照 `**更新頻率：** 🗓️ 週更（每週策展一次；更新日期停留數天屬正常節奏）` 格式書寫。刪不掉的維運備忘移進 `%% … %%`（見 `.claude/reporter-rules/shared.md`「維運備忘的家」）；本列由 `scripts/check_reader_language.py` 看守，禁詞清單住該腳本 |
| **實體狀態變更全檔案 cross-check** | 今日更新涉及實體狀態變更（如管制解除、模型下線、功能升版）時，該實體名稱在同一頁面（含摘要、表格、callout、歷史記錄）與被引用的其他頁面中若有殘留舊狀態敘述 | 對該實體名稱 grep 全檔案，逐一確認並統一為最新狀態，不可只改觸發本次修改的那一行 |
| **現況不被時序侵蝕** | `## 現況`/`## 摘要` 內帶日期的事件段落超過 2 段（新事件 prepend 進摘要卻不清舊段，會讓摘要變成第二份時序） | 只保留最新 2 段，其餘移入歷史記錄/時序；若該事件已在歷史記錄則直接刪除，不雙重維護 |
| **表格放結論，細節下沉（全站通用）** | 任何表格儲存格超過 **120 字元**散文（量測前先剝掉 markdown 連結 URL；純引用來源格〔標題＋URL＋日期〕豁免）——查證過程、演進脈絡、多來源歧異塞進格子會讓表格失去可掃描性並在網站爆版 | 儲存格只留結論短語＋關鍵數字＋最新日期，細節**完整下沉**到該表格正下方的細節區（錨定表內關鍵詞）——細節區條列本身受 `.claude/reporter-rules/shared.md`「書寫風格」的 200 字元上限拘束，下沉是換位置，不是換成無上限的傾倒區；下沉是搬位置不是刪除，數字與歸因一個不能少。此規則自 `.claude/reporter-rules/models/pages.md` G/H 條提升為全站通用（2026-08-27 可讀性掃描：政策/商業/功能頁多表同病）；model-comparison 的欄數上限與自查指令仍見該檔 |

**頂部 delta-first callout 格式：**
```markdown
> **標籤**（YYYY-MM-DD）
> 一到兩句說明最新重大事件，讓冷讀者不需往下看也能理解當前狀態。
```
**外殼固定、內容自由**：機器只認外殼——首行粗體標籤後**緊接**全形括號、括號內**緊接**日期（日期後可有「，補充」尾巴）；標籤依頁面重點自取（最新動態／最新判讀／本週衝擊／最新安全事件……），內容是條列或散文、幾行、要不要 wikilink，由你決定。`（` 後不是日期的（如 `❓ **待查證**（標 …`）不會被當成最新動態，那是懸置標記自己的形狀，別混用。**沒有時效的自介 callout**（「這頁在回答什麼」「本頁是什麼」）不帶日期，或把日期放在括號後段（「（重寫 2026-08-08）」「（快照 2026-09-12）」），它才不會被當成當日最新動態投影進日報；當日 delta 另開一段帶日期的 callout（如 `> **最近變動**（YYYY-MM-DD）`）。**脫離頁面也要讀得懂**：帶日期的 callout 會原文投影進讀者版日報，讀者看不到頁面其餘部分——不用頁內編號（`⟨G-11⟩`、「第三線」）、不寫「見下方表格」「見『## 攻防紀錄』」這類頁內路標（要指就用 `[[頁#節]]` 完整 wikilink），事實之後帶一句「所以什麼變了」；寫完自問：拿掉整頁只剩這段，讀者知道發生了什麼、該怎麼看嗎？消費端：`scripts/build_reader_digest.py`（讀者版日報）、`scripts/check_hierarchy.py`（母頁不落後子頁）。
**callout 寫「發生了什麼」，不寫「收錄決策」**：未收錄清單、門檻判定理由（「X 未達中門檻，未收錄」）屬編輯部日誌，寫入 `wiki/log.md` 的 ingest 紀錄，不得出現在 callout 或正文——callout 首句必須是當日新增的內容本身。多條互不相關的事件改用 `> - **主題**：一句話` 條列，不擠成單一長段。
**callout 寫本頁讀者在乎的更新重點**：外面發生了什麼（一次發布、一份量測、一篇實測、一個人說了什麼）、對他有什麼影響。我們拆了哪頁、併了哪頁、換了版面、汰了哪張表、本頁開張——讀者不在乎，不寫；讀者版日報直接抄 callout，整理紀錄會原樣上站。自檢：拿掉 wikilink 後那句還說得出 Claude／Anthropic／生態發生了什麼嗎？`scripts/check_reader_language.py` 以 callout 範圍的整理語看守（`scope: "callout"`）。
callout 放在標頭欄位（最後更新、最後新聞更新）之後，`---` 分隔線之前。entities/ 頁面同樣建議加，但非強制。
**只保留單一最新一則 callout：更新時直接覆寫舊 callout，不得保留「前次動態」等舊 callout 疊加**（callout 是全 wiki 唯一該「覆寫」而非「prepend」的地方；歷史沿革一律進 `## 時序`，不在頂部堆疊）。

## 懸置標記語法

事實尚未確定時（待查證／待核實／官方未載），**必須用本節語法標記**，不可只寫一句「待查證」了事。

理由：散文裡的「待查證」沒有任何機制讀得到它。本語法讓每筆懸置**自帶偵測條件**：每日掃描拿探針比對當日日報，命中就通知對應記者。（教訓見沿革檔 2026-08-08 A）

### 標準式（散文／條列／callout／短表格儲存格）

```
❓ **待查證**（標 2026-08-07｜查 [[topics/ai-agent-safety]]、CI workflow secrets）｜**GitHub Issue 觸及 CI secrets**（2026-08-07 報導）：The Hacker News 報導…
```

四段：`狀態符號` + `**類別詞**` + `（metadata）` + `｜**題目**：內文`。前三段是機器區、第四段是人類區，以全形 `｜` 分界。**括號寫在粗體外**，讓表格處理函式不會動到 metadata。

| 欄位 | 語法 | 必填 | 語意 |
|------|------|------|------|
| 狀態符號 | `❓` / `🔎` | ✅ | `❓` 尚無人查；`🔎` 已查官方一手來源、確認未載 |
| 類別詞 | `待查證` / `查無官方` | ✅ | 與符號一一對應，不一致會被檢查擋下 |
| 標記日 | `標 YYYY-MM-DD` | ✅ | **寫下這個標記的那天，不是事件發生日**。事件日寫在題目後的散文括號裡 |
| 探針 | `查 A、B` | ✅ | 每日掃描拿來比對日報的關鍵字，頓號分隔。`[[wikilink]]` 優先 |
| 複查日 | `複 YYYY-MM-DD` | ⬜ | **省略即為標記日 + 14 天**。有寫代表有人動過手 |
| 訊號日 | `訊 YYYY-MM-DD` | ⬜ | 日報出現後續的那天。**記者唯一可新增的欄位** |

### 表格變體

儲存格加上完整標記後 **≤ 120 字元**（同 `.claude/reporter-rules/models/pages.md` G 條）就直接用標準式；超過則儲存格只留短標記，完整標記下沉到該表格正下方的「懸置細節」區：

```markdown
| … | ❓ 待查證 ⟨Q-07⟩ |

**懸置細節**
- ⟨Q-07⟩ ❓ **待查證**（標 2026-08-07｜查 [[topics/ai-agent-safety]]、CI secrets）：僅標題可用，攻擊鏈與是否已修補均未見報導
```

`⟨Q-nn⟩` 的 nn 為該頁內序號（不跨頁唯一）。儲存格短標記與細節區定義**必須一一對應**，缺任一邊都會被檢查擋下——這是防止下沉後細節區被順手刪掉的唯一機制。

### 探針怎麼寫

探針決定這筆懸置能不能被偵測到，**寫壞了等於沒標**：

- **能在 `news/*.md` grep 到的字串**：產品名、issue 編號、版本號、機構名、英文術語。不可是形容詞
- **至少 2 個**（掃描要求 ≥2 個同時命中才算，單探針偵測力不足）。唯一例外是 wikilink 探針或長度 ≥ 6 字元的字串
- **長度地板**：英數 ≥ 4 字元、中文 ≥ 3 字元
- **禁用過寬詞**：`Claude`、`Anthropic`、`AI`、`Code`、`API`、`agent`、`model`、`Opus`、`Sonnet`、`Cowork` 這類天天出現的詞，以及 `Reddit`、`GitHub`、`Hacker News`、`ClaudeCode`、`Show HN`、`dev.to`、`lobsters`、`Google News` 這類每則條目必帶的平台/來源名，會每日命中、把真訊號淹掉
- **`[[wikilink]]` 優先**：指向實體頁時探針詞自動取自該頁（改名時跟著更新），且建置會驗證目標存在。**樞紐頁（`claude-code`、`ai-agent-safety` 這類高頻詞頁）的 wikilink 不具偵測力，僅作語意連結**——展開出的別名（slug、H1 標題）本身就是通用詞，會落在上述禁用過寬詞清單，不參與比對；偵測力須靠另外 ≥2 個具體探針撐起（教訓見沿革檔 2026-08-10）

### 誰可以動這個標記

| 角色 | 可做 | 不可做 |
|------|------|--------|
| 記者（每日 ingest／lint 3g） | 加 `訊 YYYY-MM-DD`、更新題目後的內文 | **不可刪標記、不可改狀態符號、不可宣告結案**——記者無 web 工具，判準只有日報 |
| 主編（`/wiki-lint` 5c） | 查官方一手來源後三選一：改寫為事實並移除標記／改 `🔎 查無官方`／議題失效則移除；**查實後必須拿探針字串回掃全庫，把仍在說「待查證／推算值」的引用方一併上修**（5c 第 5 步）| — |

> 記者只掃了日報，就只能宣稱日報沒有。**不得寫「至今無後續」**——那讀起來像已經確認過，但答案可能一直躺在官方說明中心。（教訓見沿革檔 2026-08-08 B）

**機械看守**：`scripts/check_pending_markers.py` 比對全庫標記總數與 `data/pending-marker-count.json` 基線，減少即 FAIL；主編查證結案移除標記時同批 `--rebuild-count --reason`。

## 命名與分類規則

**entities 狀態**主值限定五項（格式：`主值（補充說明）`）：`active` / `beta` / `deprecated` / `acquired` / `resolved`。**topics 狀態**維持：`ongoing / monitoring / resolved`。

**領域欄位**：所有 entities/ 與 topics/ 頁面標頭必填 `**領域：**`，六選一：🤖 模型 / 🛠️ 工具/功能 / 👤 人物 / 💼 商業 / 🏛️ 政策/安全 / 🌐 社群。`wiki/index.md` 對應欄位須同步。

**新 topics slug 命名規約**（既有頁面不溯及）：社群類 `community-*`、企業類 `enterprise-*`、Anthropic 官方 `anthropic-*`、安全政策 `safety-*`。

**別名欄位（選填）**：頁面主題有常用英文名／舊名／媒體慣用別稱，且與中文頁名或 slug 字面不同者，在標頭「領域」之後加一行 `**別名：** Fable 5, Mythos-class`（逗號分隔，只列真實出現過的稱呼，不預測性堆詞）。用途：全庫 grep 與 `scripts/wiki_graph.py sections` 查詢時可命中、記者判斷條目歸屬時對照。人物頁英文名、產品頁官方英文名為典型適用；slug 已含該英文者不必重複。（立法依據見沿革檔 2026-08-28）
