# Wiki Ingest — 社群記者 Lint 指南

`/wiki-lint` 時由社群記者載入，處理三項任務：`community-tech-tools.md` 策展 + `community-tech-patterns.md` 模式淘汰審查 + `community-pattern-trends.md` 趨勢頁週更。每日 ingest 不需讀此檔。

---

## community-tech-tools 三層結構 `[加入: 2026-06-19，改版: 2026-06-19]`

**此頁已脫離每日 ingest，三層全部只在 `/wiki-lint` 維護。** 讀者動線：`痛點洞察 → 值得關注的工具 → 工具目錄`。

| 區塊 | 性質 | 門檻 |
|------|------|------|
| `## 痛點洞察` | 痛點 → 代表工具入口（分析）| 代表工具僅放 ✅ 或 HN≥50 |
| `## 值得關注的工具` | 高門檻精選索引（按類型分組）| **✅ 廣泛採用 或 HN score ≥ 50** |
| `## 工具目錄（依日期倒序）` | 採用 ⚡/✅ 的完整列表 | 採用 ⚡/✅；⏳ 不長期保留 |

## community-tech-tools 策展規則 `[加入: 2026-06-19]`

**步驟：**
1. **來源**：讀取距今 7–14 天的 `news/*.md`，這是工具的唯一原始資料來源
2. **萃取達標工具寫入 `## 工具目錄`**（門檻，滿足其一）：
   - HN score ≥ 30，或 HN 評論數 ≥ 5
   - 同一天被至少 2 個獨立來源報導
   - 已證明採用（多次出現、有實際使用回饋）
   - **排除**：無公開 repo / demo / 連結；純商業廣告；只在 Google News 無 HN/Reddit 討論
3. **欄位** `| 工具 | 類型 | 採用 | 首次出現 | 簡介 |`：有 URL → `[**Tool**](url)`，URL 從日報原文擷取；採用預設 `⚡`，score ≥ 100 或評論 ≥ 20 維持 `⚡`，廣泛採用才給 `✅`
   - 寫入前查表去重：同名 / 同 URL 已存在則更新該筆，不新增重複列
4. **汰除**：採用降為 ❌、或距今 > 30 天仍為 ⏳ 無後續者，移除該列（git history 留存）
5. **同步 `## 痛點洞察`**：新工具歸屬痛點時更新 `近期工具` 欄；`代表工具` 欄每痛點最多 3–4 個，僅放 ✅ 或 HN≥50；狀態 ≤ 14 天有新工具 → 🔥，> 14 天 → 🌙，官方發布 → ✅，最佳實踐穩定 → ⚡

## community-tech-patterns 模式淘汰審查 `[加入: 2026-06-28]`

每次 `/wiki-lint` 時對 `wiki/topics/community-tech-patterns.md` 執行以下審查（dry run 先回報，確認後執行）。

**淘汰標準（滿足其一即列出）：**

| 條件 | 說明 |
|------|------|
| **官方化** | 模式描述的 workaround 已被 Claude Code 官方功能取代（對照 `wiki/feature-radar.md` 與 `wiki/entities/claude-code.md`）|
| **60 天沉寂** | 近 60 天日報未提及此模式或相關技術，且成熟度 ≤ ⚡ |
| **否定驗證** | 日報或 `community-tech-discussions.md` 出現「此模式有問題 / 過時」的明確社群共識 |
| **版本過期** | 模式明確綁定某已 deprecated 版本號 |

**處理原則：**
- 完全被取代 → 刪除
- 部分被取代（如底層官方化、上層應用層未取代）→ 拆分，刪除已取代部分，保留未取代部分並加「官方趨勢觀察」說明
- 主題相近的多條條目 → 合併為「同目標不同做法對照」，保留各自來源連結
- 沉寂但概念仍有效 → 保留，不因沉寂單獨刪除

**Dry run 回報格式：**
```
## community-tech-patterns 淘汰審查

### 建議淘汰（共 N 條）
| 模式名稱 | 所在區塊 | 觸發標準 | 說明 |

### 建議合併（共 N 組）
| 模式組合 | 合併理由 |

### 保留（共 N 條）
[列出保留理由]

### 無法判斷（共 N 條）
[列出需人工確認的項目與不確定點]
```

**回報後等待使用者確認，再執行實際修改。**

## community-pattern-trends 趨勢頁週更 `[加入: 2026-06-29]`

每次 `/wiki-lint` 時更新 `wiki/topics/community-pattern-trends.md`（週更，非每日）。

**趨勢成立門檻（同時滿足）：**
- ≥ 3 個獨立來源（不同社群帳號、不同媒體、不同工具）
- 首次出現距今 ≥ 14 天
- 至少 1 條 A 層（量化/可重現）或 B 層（機制完整）證據

**更新步驟：**
1. 讀取近 14 天 `news/*.md`，對照 `community-tech-patterns.md` 現有模式，偵測：
   - 現有趨勢有新節點加入（補充 `#### YYYY-MM-DD` 節點）
   - 趨勢成熟度升級（升格 📈 → stable 或標記進入 plateau）
   - 新趨勢達成立門檻（新增趨勢區塊）
   - 趨勢沉寂超過 30 天且無新節點（標記為「↘ 淡出」）
2. 每條趨勢的 `**對現有設計的啟示：**` 欄位若有新節點，同步更新啟示文字
3. 更新頁面 `**最後更新：**` 日期

**不更新情況：** 若近 14 天無新模式節點、無趨勢成熟度變化，保持頁面不動（不必要地更新日期會誤導讀者）。

**格式（新節點）：**
```markdown
#### YYYY-MM-DD
[一行說明新增的模式或事件，附 pattern 名稱]（🔥/🔥🔥/🔥🔥🔥）
```

## community-tech-tools 精選層提拔規則 `[加入: 2026-06-19，改版: 2026-06-19]`

維護 `## 值得關注的工具`（高門檻精選）。

**提拔門檻（滿足其一）：** 採用為 **✅ 廣泛採用**、或 **HN score ≥ 50 / Launch HN**。（YC 批次、HN 30–49、單純 ⚡ 不足以進精選，留在工具目錄。）
**呈現：** 按類型分組（`###` 子標題），每工具一行 `| 工具 | 採用 | 亮點（一句話）|`，亮點精簡不照抄目錄簡介。
**上限：** 精選層至多 ~20 個工具；超過時淘汰最舊且採用未升級者。
**降級：** 採用降為 ❌ 或長期無後續者，移出精選層（仍保留於工具目錄）。
