# Wiki Lint — 對抗輪（月度）派工範本 `[加入: 2026-09-04]`

`/wiki-lint` 步驟 6j 由**主編**於每月首次 lint 載入（判斷方式同月度蒸餾：`wiki/log.md` 本月尚無 `Lint` 記錄）。其餘週次不讀此檔。

---

## 為什麼要有對抗輪

lint 前十步考的是「考卷內」（格式、欄位、遵守率）；2026-09-04 實測兩種**模擬視角**各挖出真問題：冷讀者抓到內部語言外洩、無行動句、證據點不開；prompt reviewer 抓到規格改了機器沒跟（六個阻擋級中五個）與一個尚未爆發的 U+0001 注入 bug——**沒有任何既有檢查會抓到它們**。對抗輪把這兩種視角變成排程，發現走既有路徑：修 → 屬新型質疑模式 → `scripts/inquiry_bank.py` 加題（經使用者確認）→ `scripts/lint_health.py misses add` 登記。

預算：每月 3 個 Opus agent（冷讀者日報、冷讀者週報＋隨機 3 頁 wiki、prompt reviewer 規則檔）。主編視當月配額可縮為 sonnet，但**冷讀者角色用 sonnet 會明顯失去挑剔度**，優先保 Opus 給冷讀者。

## 三個派工（同一訊息並行，`subagent_type: general-purpose`，只讀不寫）

### A. 冷讀者：日報呈現（最新兩期）

角色設定：重度使用 Claude Code 的工程師，每天早上 5 分鐘掃日報，**完全不知道產製流程、內部術語與規則**，只讀眼前文字。評的是呈現方式不是選題。八維度各附行號證據，每維度一行結論 ✅／⚠️／❌：
1. 5 分鐘動線（讀序、必看／跳過、區塊順序合理否）
2. 今日聚焦分得出輕重否、標籤有用否
3. 重點話題的「重點感」——每則讀得出為什麼今天它是重點嗎
4. 條目寫法——中文說明是否只是標題直譯；情緒標籤有沒有在看
5. 重複與雜訊——跨區塊重複、檔尾內容價值
6. 視覺可掃性
7. 兩期版式一致性
8. 整體：比自己刷 HN＋GitHub 省多少時間

末尾「修復優先序：只能改三件改哪三件」。

### B. 冷讀者：週報（最新一期）＋隨機 3 頁 wiki

週報角色：三週沒看的付費訂閱者，只讀 `weekly/<最新>.md`，可對照前一期只為判斷「下週看什麼」有無兌現。八維度：開頭 30 秒測試、冷讀者斷點（假設前情／未解釋術語）、用字精煉度、敘事結構、可行動性、預告兌現感、數字與證據、整體值不值。

wiki 三頁用 `python -c "import random;random.seed('YYYY-Wnn');..."` 從 `wiki/index.md` 目錄列擲骰抽，不可自由心證挑。每頁三問：前 160 字能獨立讀懂嗎、有無內部語言、3 跳內能回答該頁 callout 暗示的問題嗎。

### C. Prompt reviewer：近 30 天改過的規則檔

`git log --since=30.days --name-only -- .claude/` 取清單。每檔六項：矛盾與殘留（新舊條文打架、引用已廢除的東西）、可執行性（LLM 判得出來嗎，給可判定措辭）、機械契約完整性（對照契約表與消費端程式）、指示／輸出混染風險、規格長度與注意力、既有承諾覆蓋核對。分級 🔴阻擋／🟡應修／🟢建議，每項附**可直接貼上的修訂文字**。

## 收報後

- 🔴🟡 逐項修，修完**用原 agent（SendMessage）複審**直到「無阻擋意見」——不重派，保留上下文
- 每項發現判斷：既有檢查該抓而沒抓 → `lint_health.py misses add --why 考卷內抽樣不足|檢查失效`；沒有對應檢查 → `--why 無對應檢查`，並評估是否值得加機械檢查或題庫加題
- 對抗輪結果寫入步驟 8 的 `對抗輪（6j）` 行；本輪發現的類型分佈附一句（「規格改了機器沒跟 5／新舊打架 2／…」）
