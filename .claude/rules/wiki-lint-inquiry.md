# Wiki Lint — 歷史質疑代打指南（主編層）`[加入: 2026-09-02]`

`/wiki-lint` 步驟 7b 由**主編**載入。每日 ingest 不需讀此檔。

---

## 為什麼有這一步

`wiki/log.md` 的 Query 條目（35 筆起）記錄「使用者哪句質疑揭露了哪個缺陷」。回顧結論：**歷史上所有重大品質問題，全部來自使用者的不定期質疑，沒有一次是排程檢查抓到的**——排程檢查考「考卷內」（格式、欄位、遵守率），真問題在「考卷外」（沒發生的事、過期的宣稱、答不出來源的數字）。而使用者的質疑歸納起來反覆只有少數幾種模式（現八種），每種都可操作化。

本步驟把「使用者已經問過的問題」變成常設抽問：**問過一次的，不需要再問第二次**。判斷式：

> 這題是「已知模式的重複執行」還是「新型質疑」？前者歸題庫代打；後者仍然只有使用者問得出來——所以 `scripts/open_loops.py` 的人類質疑時效燈**不因本步驟在跑而熄滅**。

## 執行步驟（每次 `/wiki-lint`）

1. 跑 `python scripts/inquiry_bank.py draw`（預設抽 2 題，seed 綁本 ISO 週）
2. 逐題執行印出的探針步驟，**逐步做完，不可跳步**；探針裡的「擲骰」一律用 python 產生（seed 用同一個週字串），不可自由心證挑對象
3. 每題三態結果：
   - ✅ 通過——**必附證據行**（查了什麼、看到什麼），只寫「通過」視同未執行
   - ⚠️ 已修復——說明改了什麼，修復照對應規則檔執行
   - ❌ 待辦——記入 `wiki/log.md` 本次 lint 紀錄，並回報使用者
4. 結果寫入 lint 紀錄的 `質疑代打（7b）` 行

## 紀律

- **同週重跑同題**：seed 綁 ISO 週是防「重擲骰子換好答的題」，補跑時不可傳 `--seed` 換題（`--seed` 僅供測試）
- **❌ 不可為了好看降級成 ⚠️**：修不完就是待辦，誠實記錄；本步驟的價值在訊號，不在滿分（教訓見 `.claude/commands/wiki-lint.md` 收報核對「連續滿分與抓不到問題是同一枚硬幣」）
- **探針結果須含證據**：質疑代打自己也是宣稱，證據行就是它的 diff

## 題庫維護

- 題庫內容**單一來源住 `scripts/inquiry_bank.py`**（探針要跟指令住在一起），本檔只放機制與判準，不重抄題目——兩處抄寫必然漂移
- **加題條件**：`wiki/log.md` 出現新 Query、且其質疑模式不屬現有模式 → 主編提案（模式名＋操作化探針），**經使用者確認後**加入腳本並補 `src/tests/test_inquiry_bank.py` 對應斷言
- **刪題須經使用者確認**：腳本自檢會擋題數 <7
- 題庫的抽選指令與 `.claude/commands/wiki-lint.md` 7b 的指令**必須一致**（已登記 `.claude/review-registry.json` sync_pair，`scripts/check_rules.py` 會驗）

## 人類質疑時效燈（可見性，處理端不在本步驟）

`scripts/open_loops.py` 第 [6] 節：`wiki/log.md` 最新 Query 條目距今 **>21 天**即亮 ⚠——語意是「黑天鵝偵測器已離線 N 天，題庫只在代打已知模式，新型錯誤無人看守」。燈亮時本步驟照常執行，但主編應在 lint 回報末尾原樣轉述該行，讓使用者看見。
