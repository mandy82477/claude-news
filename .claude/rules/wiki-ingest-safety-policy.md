## anthropic-government-policy 更新規則 `[加入: 2026-06-18，改版: 2026-09-06]`

**觸發條件：** 日報出現 Anthropic 與美國政府（或其他國家政府）的新互動事件。

**每次 ingest 後依序：**
1. 在 `## 攻防紀錄` 表格最上方 prepend 新行（`| 日期 | 🏛️/🏢/🌐 | 動作 | 效果 |`），並在 `## 時序` prepend 新日期區塊。時序行首方括號只准放 🏛️／🏢／🌐，不得寫「新增」「更新」「跟進」「僅標題可用」這類編輯狀態詞。
2. 依判準覆寫 `## 現在有哪幾條線在動`。**判準句（三條全過才入表）：** ① 這條線有具名的政府、法院或監管主體做出可查證的動作，或該動作對 Anthropic 產品造成直接後果——分析文章、產業論戰、廠商自宣、單一匿名貼文、私人之間的訴訟（著作權、和解案）不入表；② 「會不會改到你用的 Claude」欄寫得出「會：怎麼改」或「不會」的一句理由，兩者皆答不出留在證據層；③ 「下一個時點」欄寫得出日期或明寫「無時程」，不得寫問句。同一條敘事線上的多起事件合為一列。**每列的最後動態日期寫在「線」欄的括號內；退場的 90 天與排序的新舊皆讀該日期。上限 8 列**，排序「會」在上、「不會」在下，同類依下一個時點日期近者在上、無時程者依最後動態新者在上。**退場（先看這一列標「會」還是「不會」）：** 標「會」的列——只在那個產品行為停止或被官方取消時才移出，**不適用 90 天**；標「不會」的列——依序問，第一個成立即定案：這條線已定案且不再改變讀者能不能用、怎麼用 Claude 即移除該列，結論留在 `## 時序` 該日；距最後動態逾 90 天且本輪無新事實即移除該列；其餘留表。**留表優先序：**「會改到你用的 Claude」＞「下一個時點有日期」＞其餘（依最後動態新舊）；表滿載時序位最低者移除出表，在其 `## 時序` 對應條目末加「（未列入現況表：表滿載，YYYY-MM-DD）」並在表下一句點名。**移除後表未滿載時**，從 `## 時序` 挑仍符合三條判準、最後動態最新者補位，並移除其註記。**新列進表的入口只有兩種訊號：** 政府、法院或監管機構做出新的、有具名主體的動作，或既有線首次出現對讀者可觀察的產品後果；媒體轉述、評論文章、熱度回升不構成入口。狀態四值定案／進行中／提案／觀察，**由官方一手來源、法院文件或官方公告決定**；日報的媒體轉述只能更新格內文字，不能翻狀態。
3. 上表某列標「會」時，`## 政府動作對你的產品做了什麼` 必須有對應的一項，寫出已發生的產品行為＋一行「你的選項」（列選項不下指令）；該列改標「不會」或移除時，對應項同步移除。本節只寫已發生、可觀察的產品行為。
4. `### 誰在動這幾條線` 只收在上表某一列裡實際出過牌的人（下令、提案、判決、談判、代表出席），或在 `## 攻防紀錄` 已封存的兩個時段（2026-05、2026-06）或 07-01 恢復存取這條已結案主線上出過牌的人（該款不隨線退場，但主線已結案不得新增）。上限 12 人，不寫生平。
5. 事件影響 `## 三個戰場` 任一條故事線時，只補該段的機制敘述（為什麼會這樣），不寫逐日事件——逐日的家是 `## 攻防紀錄` 與 `## 時序`。
6. 蒸餾與封存照 `.claude/rules/wiki-ingest-format.md`「時段蒸餾與封存（全站通用）」，archive 子頁為 `topics/anthropic-government-policy-archive`，`## 攻防紀錄` 與 `## 時序` 皆為對象。**蒸餾 `## 攻防紀錄` 之前先確認 archive 沒有反過來指著它的條目**（2026-09-06 修過一處）。
7. 更新「最後更新」；有新事件時一併更新「最後新聞更新」。

## ai-agent-safety 更新規則 `[改版: 2026-09-06]`

**觸發條件：**
- 新的 Claude Code 安全漏洞披露（含 CVE 或具名披露）
- 提示注入攻擊案例（遠端或本地）
- 惡意套件 / 假冒安裝包事件
- Anthropic 官方安全回應聲明

**更新動作（每日）：**
1. 事件本身 prepend 進 `## 技術彙整` 最上方（`### 事件名稱（YYYY-MM-DD 新增）`），並在 `## 時序` prepend 一行。**本頁沒有 `## 事件記錄` 這一節**，舊條文指名的是不存在的節。
2. 依判準覆寫 `## 現在會打到你的` 對應列。**判準句（三條全過才入表）：** ① 是現在還打得到讀者的攻擊面——論述、教學、產業對照、第三方廠商動態、以及「別人拿 Claude 打別人」的濫用態勢都不入表；② 「誰會遇到」欄寫得出使用條件，寫不出就寫「所有人」；③ 「你能先做什麼」寫得出一個今天做得到的動作或明寫「無繞法」。同一個讀者動作觸發的多起事件合為一列。上限 11 列，依「誰會遇到」的範圍由寬到窄，**寫「所有人」的一律在最上**，同寬依最後動態新者在上。`## 現在會打到你的` 的退場依序問，第一個成立即定案：狀態翻 ✅、或轉 ⛔ 且官方給出替代做法即移除該列；距最後動態逾 90 天且本輪無新回報即移除該列；其餘留表。表滿載時上限之後者移除出表，在其事件記錄條目末加「（未列入現況表：表滿載，YYYY-MM-DD）」並在表下一句點名；**移除後表未滿載時，從事件記錄挑仍符合三條判準、最後動態最新者補位，並移除其註記。新列進表的入口只有兩種訊號：官方或研究者公開一個新的攻擊面，或既有事件首次出現「讀者能自己做的一件事」；單純的媒體轉述、論述文章與熱度回升不構成入口。** 狀態沿用 [[entities/claude-code]] 五值 🔴／✅／⛔／❓／🔎，語意為「現在仍會發生」。**狀態由官方一手來源或訴訟文件決定；日報的媒體轉述只能更新格內文字，不能翻狀態。**
3. `## 提示注入已不是單點漏洞，是產業級攻擊面` 是覆寫式訊號表，一則訊號一列，上限 8 列，收斂點改變時整表重判、汰除最舊者；**導言、收斂點與「仍未有答案的」三處的則數必須等於表列數**，改表就要一起改這三個數字。
4. `## 拿什麼擋` 每條開頭必須指名它擋上表哪一列；上表某列移除時，指向它的那一條同步移除或改指別列。
5. 蒸餾與封存照 `.claude/rules/wiki-ingest-format.md`「時段蒸餾與封存（全站通用）」，archive 子頁為 `topics/ai-agent-safety-archive`。
6. 更新「最後更新」；有新事件時一併更新「最後新聞更新」。
